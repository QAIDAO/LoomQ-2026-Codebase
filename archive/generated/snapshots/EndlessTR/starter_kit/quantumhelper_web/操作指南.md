# QuantumHelper Web 操作指南

> 面向第一次接触这个项目的用户（新手、演示者、评审）。想了解底层实现细节请阅读同目录的 `README.md`，本文只讲「怎么用」。

---

## 1. 这是什么项目

QuantumHelper 是一个把自然语言变成「量子线路」的网页工具。你不需要会写 QASM、不需要先选算法或平台，只需要用日常语言描述你想做什么，它会帮你：

1. 理解你的意图（生成线路 / 修复代码 / 选运行环境 / 解释概念）；
2. 生成或修复一条量子线路，并**真实校验**它是否合法；
3. 逐门解释这条线路在做什么；
4. 在线路包含测量时，在本地模拟器上**真实运行**，画出测量结果分布；不含测量时也可检查和阅读线路。

底层复用提交中的确定性核心 `starter_kit/adapter.py`（解析、转译、校验、后端匹配和本地执行），网页的 `starter_kit/quantumhelper_web/web_agent.py` 负责「听懂人话 + 生成或修复候选线路 + 解释 + 管上下文」。模型产生的候选线路必须再次通过 adapter 校验，不能绕过确定性边界。

面向评审、部署和二次开发的完整工程说明见 `starter_kit/evidence/files/engineering-productization/engineering-productization.md`。

## 2. 怎么启动

要求 Python 3.10 或兼容版本，基础功能只依赖标准库。

在包含 `starter_kit/` 的仓库根目录运行：

```powershell
python starter_kit\quantumhelper_web\server.py
```

启动后浏览器打开 <http://127.0.0.1:8000/> 即可。

- 健康检查：<http://127.0.0.1:8000/api/health>
- 换端口：`python starter_kit\quantumhelper_web\server.py --port 8080`
- 局域网访问：加 `--host 0.0.0.0`（只开放确有需要的防火墙端口）

**不要**直接双击 HTML 文件打开页面——页面依赖同源 API 和 adapter，必须通过上面的服务访问。

## 3. 配置 LLM（两种方式）

「生成/修复线路」需要模型服务。概念问答、场景卡片、导入线路、本地运行等不依赖模型也能用。

### 方式 A：环境变量（比赛标准方式）

在启动服务的同一个 PowerShell 窗口里设置，再启动：

```powershell
$env:QUANTUMHELPER_ENABLE_LLM = "1"
$env:LOOMQ_LLM_BASE_URL = "https://你的 OpenAI 兼容接口地址"
$env:LOOMQ_LLM_API_KEY  = "你的密钥"
$env:LOOMQ_LLM_MODEL    = "deepseek-v4-flash"
python starter_kit\quantumhelper_web\server.py
```

正式评测由组委会注入 `LOOMQ_LLM_*`，这一层完全兼容、不被网页改动。

### 方式 B：网页运行时配置（普通用户推荐）

启动服务后，打开首页，进入「模型服务设置」页（或直接访问 <http://127.0.0.1:8000/config.html>），填写：

- Base URL（OpenAI 兼容接口根地址，如 `https://api.openai.com/v1`）
- API Key
- Model（模型名）

然后点「测试连接」确认显示 **✓ API 连接正常**，再点「保存到本次运行」。

### 优先级

```
网页运行时配置  →  LOOMQ_LLM_* 环境变量  →  未配置
```

即：网页里填了就以网页为准；网页没填才回退到环境变量；都没有则提示「模型服务尚未配置」。

### API Key 安全（重要）

- API Key **默认只保存在当前 server 进程内存**，不写入浏览器 localStorage、不写入前端 JS 文件、不写死进任何静态文件。
- 服务重启后，网页配置自动失效，回到环境变量状态。
- `GET /api/config/status` 只返回「是否已提供密钥」的布尔值，**绝不回传完整 Key**。
- 不要把你的 Key 写进 HTML/JS、提交进 Git、截图或粘贴到聊天记录。「保存到本机 .env」目前**尚未实现**，若未来加入会要求显式确认并加入 `.gitignore`。

## 4. 首页四张卡片分别能做什么

首页「不知道怎么描述？」下有四张场景卡，点击后会自动填入一段描述并进入相应流程：

| 卡片 | 现在能做什么 | 模式 |
|---|---|---|
| **01 查找** | 解释「搜索类问题」如何对应量子计算（Grover 思路：候选 → 标记目标 → 放大 → 测量），并给出一个**可运行的编码演示**。 | 解释 + 编码演示（Grover 自动生成未实现，不假装支持） |
| **02 优化** | 解释「组合优化」如何映射到量子问题，并给出一个候选编码演示（可运行）。 | 解释 + 编码演示（完整 QAOA 未实现，不硬生成假线路） |
| **03 测量** | 真正可运行示例：两比特叠加 + 测量，走完整 `生成 → 校验 → 运行 → 结果`，看为什么重复运行结果不同。 | 可运行示例 |
| **04 关联** | 真正可运行示例：H + CX 构成 Bell 态，走完整流程，看两个比特的测量结果如何关联。 | 可运行示例 |

> 卡片承诺的能力不会超出后端真实能力：查找/优化没有可靠生成器时只解释不假装；测量/关联有真实线路，可以直接运行。

## 5. 新手可以怎么用

### 从哪开始

1. 打开首页，在中间大输入框用日常语言描述目标。普通 `Enter` 换行，`Ctrl+Enter`（或 `Cmd+Enter`）发送。
2. 不知道说什么，就点输入框下方的示例 chips，或点首页下方「第一次使用」的引导入口。

### 可以直接试的输入示例

| 想做什么 | 可以这样说 |
|---|---|
| 看懂 H 门 | `H 门到底干嘛的，别给我公式` |
| 第一条新手线路 | `给我弄个新手能看懂的量子线路` |
| 最简单的纠缠 | `给我一个最简单的量子纠缠例子，不要太复杂` |
| 标准 GHZ | `生成一个 4 比特 GHZ 态，只测量前两个量子比特` |
| 修复一段代码 | `我想制备一个贝尔态，但这段代码报错了：H q[0]; CX q[0] q[1]` |
| 选运行环境 | `我需要运行一个 15 比特电路，要求零排队并且免费` |
| 多轮修改 | 先 `生成一个 3 比特 GHZ 态`，再 `改成 5 比特`，再 `H 门到底干嘛的，别给我公式` |

### 新手默认行为

- 你说「新手能看懂的线路」，它会默认给你**单比特叠加 + 测量**，并明确告诉你它默认了什么。
- 你说「最简单的纠缠例子」，它会默认**两比特 Bell 态**，并声明假设（2 个量子比特、全测量）。
- 真正缺信息时（比如「做个优化线路」但没说优化什么），它只会**问最少的一个问题**，不会一次要你填一堆量子参数。

## 6. 开发者怎么跑测试

在项目根目录运行：

```powershell
python -m pytest -q
```

测试数量以当前提交运行该命令的输出为准，避免固定数字随新增回归用例而过期。

单测分模块运行（可选）：

```powershell
python -m unittest starter_kit.test_web_agent -v            # 意图路由
python -m unittest starter_kit.test_backend_selector -v     # 后端需求/冲突
python -m unittest starter_kit.test_qasm_extract -v         # QASM 提取
python -m unittest starter_kit.test_runtime_config -v       # 运行时配置
python -m unittest starter_kit.test_quantumhelper_web -v    # 网页/Agent API 回归
```

前端语法/状态测试（需要 Node）：

```powershell
node --check starter_kit\quantumhelper_web\static\app.js
node starter_kit\quantumhelper_web\static\workspace-state.test.js
```

本地全链路自检（不打印密钥，需先配好环境变量）：

```powershell
python starter_kit\quantumhelper_web\selfcheck.py
```

## 7. 为什么有时没有结果图

量子电路不一定必须测量。只包含量子门、不包含 `measure` 的线路仍然可以合法地描述状态制备或演化，QuantumHelper 仍会展示线路图、逐门解释、校验结果、标准 OpenQASM 2.0 和所选目标的 adapter 代码。

柱状图统计的是测量写入经典位后的 `counts`。因此只有线路含有测量操作时，“本地结果预览”才会启用；没有测量时，结果区会提示“当前电路检查通过，但没有测量操作，所以不会产生可视化结果”。这不是 API 故障，也不代表电路无效。如需观察结果，可继续输入“测量全部量子比特”或明确指定要测量的量子比特。

## 8. 已知边界（会如实告知，不假装）

- **「真机 + 免费 + 零排队 + 无需账号」无解**：能力表里没有后端能同时满足这四条硬约束。系统会明确告诉你「没有完全匹配的运行环境」，再列出最接近的备选，并逐条标注每个备选**牺牲了哪个条件**（例如某真机「✗ 需要排队 / ✗ 需要账号」，某模拟器「✗ 不是真机」）。它**不会**把本地模拟器说成满足全部要求。
- **Grover / QAOA 未实现**：查找（Grover）和优化（QAOA）目前只有解释 + 编码演示，**不会假装能自动生成**这两类线路。
- **真机无法直接提交**：网页只用 `spinq` / `originq` / `braket` 三个**本地模拟器**运行，不会替你向真实量子云提交任务。推荐到真机时页面只给出保守的「如何在真机上继续」步骤，结果会明确标注为**本地模拟预览**，不是真机实验结果。
- **返回的都是真实数据**：运行结果来自 `adapter.run()` 的真实 counts；不合法的输入会被拒绝，不会返回伪造的成功数据。
- 网页最多 12 个量子比特、2000 个操作、单次 10000 shots、每 IP 每分钟 60 次请求。
