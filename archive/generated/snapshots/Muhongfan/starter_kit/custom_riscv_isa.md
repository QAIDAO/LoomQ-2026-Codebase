# 自定义量子 RISC-V 扩展指令编码规格

> Bonus 项（+8）：设计 custom opcode 编码量子操作。本规格文档描述指令编码；
> 对应的模拟器扩展实现见 `riscv_emulator_ext.py`，端到端测试见
> `tests/test_riscv_quantum_extension.py`。

## 0. 定位

这是一份**概念性指令编码规格**：描述如果这两条指令真的要落到二进制机器码
里，应该怎么编码。工具链层面（本仓库的 `riscv_emulator_ext.py`）跟
`riscv_emulator.py` 对基础指令集（`li`/`add`/`beq`/...）的处理方式完全一致
——直接解析文本助记符执行，不做真正的取指/译码。也就是说本扩展和基座
`TinyRISCVEmulator` 在"文本助记符 ↔ 概念编码"这一层的抽象程度上是一致的，
不是对基础指令认真编码、对新指令偷懒的双重标准。

## 1. Opcode 空间

RISC-V 官方 ISA 手册（Volume I, "RV32/64G Instruction Set Listings"）明确
保留了四段 7 位 opcode 给非标准/厂商自定义扩展使用，不会与任何标准指令冲突：

| 名称 | `opcode[6:0]` |
|---|---|
| custom-0 | `0001011` |
| custom-1 | `0101011` |
| custom-2 | `1011011` |
| custom-3 | `1111011` |

本扩展使用 **custom-0**（`0001011`），是四段里最常被教学/研究项目使用的一段。

## 2. 指令格式

两条指令都复用标准 R-type 字段布局：

```
 31        25 24     20 19     15 14  12 11      7 6      0
+------------+---------+---------+------+---------+--------+
|   funct7   |   rs2   |   rs1   |funct3|   rd    | opcode |
+------------+---------+---------+------+---------+--------+
```

`funct3` 区分本扩展下的两条指令；字段的具体含义按指令重新定义（下表），
不是 R-type 原本"两个源寄存器做算术、写回一个目的寄存器"的语义——这是
自定义扩展的常规做法，标准字段位置复用，字段语义按扩展自己的需要重新赋予。

### 2.1 `QGATE` — 施加单/双比特量子门

`funct3 = 000`

| 字段 | 位宽 | 含义 |
|---|---|---|
| `opcode` | `[6:0]` | `0001011`（custom-0） |
| `funct3` | `[14:12]` | `000` |
| `funct7` | `[31:25]` | 门选择：`0000000`=H，`0000001`=X，`0000010`=CX |
| `rs1` | `[19:15]` | 目标比特索引（H/X 的操作比特；CX 的目标比特） |
| `rs2` | `[24:20]` | 控制比特索引（仅 CX 有效，H/X 置 `00000`） |
| `rd` | `[11:7]` | 保留，必须为 `00000` |

汇编助记符：`qgate <gate>, <target>[, <control>]`

```
qgate h, 0        # H 作用在比特 0
qgate x, 1        # X 作用在比特 1
qgate cx, 0, 1     # CX，控制比特 0，目标比特 1
```

### 2.2 `QMEAS` — 测量一个比特，写入通用寄存器

`funct3 = 001`

| 字段 | 位宽 | 含义 |
|---|---|---|
| `opcode` | `[6:0]` | `0001011`（custom-0） |
| `funct3` | `[14:12]` | `001` |
| `rd` | `[11:7]` | 接收测量结果（0 或 1）的通用寄存器 |
| `rs1` | `[19:15]` | 被测比特索引 |
| `rs2` | `[24:20]` | 保留，必须为 `00000` |
| `funct7` | `[31:25]` | 保留，必须为 `0000000` |

汇编助记符：`qmeas <rd>, <qubit>`

```
qmeas x10, 0      # 测量比特 0，结果写入 x10
```

## 3. 语义

- 比特数上限：8（`riscv_emulator_ext.py` 用一个长度 `2^8=256` 的状态向量
  表示全部比特的联合量子态，初始为 `|00000000⟩`）。
- `QGATE h, q`：对状态向量施加标准 Hadamard 变换。
- `QGATE x, q`：对状态向量施加标准 Pauli-X（比特翻转）。
- `QGATE cx, control, target`：对状态向量施加标准受控非门。
- `QMEAS rd, q`：按 `|振幅|²` 对比特 `q` 做计算基测量——采样一个 0/1 结果，
  按投影测量公式坍缩并重新归一化状态向量，把结果写入 `rd`（`rd=x0` 时按
  RISC-V 惯例静默丢弃，不报错）。测量具有真实的量子随机性；
  `riscv_emulator_ext.py` 允许注入固定随机种子仅用于让测试可复现，语义
  本身不因为可测试性而改变。

## 4. 范围边界（明确不做的事）

- **不支持参数门**（`rz(θ)`/`ry(θ)`）：R-type 的寄存器域装不下一个连续
  值角度，真要支持要么扩展成新指令格式（比如借用 RISC-V I-type 的立即数
  字段编码离散角度索引），要么额外加一张"角度常量表"由立即数索引——两条
  路都明显增加复杂度。`H`/`X`/`CX` 三个门已经能演示"叠加 + 纠缠 + 测量 +
  经典分支根据测量结果反馈"这个完整闭环，即本 Bonus 想考察的"深度"，覆盖
  更多门不是这里的评分标准。
- **不接入 `compile_hybrid`/`adapter.py` 的评分路径**：这是独立于 L3 主线
  的加分演示，题面对这条 Bonus 的要求是"规格文档 + 模拟器扩展 + 端到端
  测试"三件套是否齐备，没有要求接入主 contract。
