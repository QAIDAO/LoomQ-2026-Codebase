# 优化审计：缺点、修复与剩余边界

## 审计方法

本轮不以“公开测试已过”作为充分条件，而是沿源程序、目标文本、目标回读、执行对象、LLM 计划、经典分支和 32 位指令逐边界做对抗性检查。“已修复”必须同时有代码路径和能在修复前失败的反例测试。

## 已发现并逐项解决

| ID | 严重度 | 原缺点 | 风险 | 修复 | 反例 / 证据 |
|---|---:|---|---|---|---|
| A1 | P0 | `run()` 生成目标 IR 后仍执行源 IR | emitter 错误不会影响 counts，运行证据与目标产物脱钩 | `verified_run()` 强制“发射 → 独立回读 → 发证 → 执行回读对象” | result meta 为 `executed_ir=independently-reparsed-target` |
| A2 | P0 | translation validation 只比较计算基分布 | 相位错误可在当前测量下隐身 | 加入全局相位不变的完整状态向量距离 | `H` 后插入 `S` 时 counts 不变，证书必须拒绝 |
| A3 | P0 | 单一初态末态检查不等于任意输入算子等价 | 某些丢门/加门对 `|0…0〉` 无影响 | 对当前“不优化 emitter”强制规范化操作轨迹逐项相等 | 插入可抵消的 `X; X` 即使末态相等也被拒绝 |
| A4 | P0 | LLM 可遗漏用户的免费/免账号/排队等条件 | 确定性 selector 会对错误计划做“正确筛选”，但答案仍违背用户 | 新增受保护约束投影，原文明确字段覆写模型遗漏/矛盾值 | 敌意计划指定付费云 QPU，用户要 15 比特免费免登录模拟器，结果仍只选合规本地后端 |
| A5 | P1 | 模型可把明确的后端选型任务错分为电路生成 | 返回完全错的任务形式 | 明确后端词汇与硬约束联合守卫 task | 敌意 `task=quantum_program` 计划被本地守卫纠正 |
| A6 | P1 | Quantum RISC-V 明确拒绝 `RY/RZ/CU1` | 题面 12 门中 3 门无法端到端编码 | 新增 `funct7=1` 参数 profile；角度以经典寄存器中的微弧度整数传入 | `QRY/QRZ/QCU1` encode/decode 往返及与核心模拟器末态对照 |
| A7 | P1 | 参数量化如无界，会用“有误差”代替正确性 | 长电路数值偏差无法评估 | 定义 1 μrad 量化契约并证明 `RY/RZ/CU1` 逐门和组合误差上界 | 跨大角度的 0.5 μrad 边界测试 + 端到端态距离测试 |
| A8 | P1 | 运行结果没有机器可读的翻译收据 | 人工复核无法确定证书对应哪个产物 | 返回源/目标/证书 SHA-256、距离、容差、轨迹与测量布尔值 | Web 显示证书摘要，raw result 包含完整收据 |
| A9 | P2 | 文档仍把 RISC-V 描述为 8 指令且参数门不支持 | 代码、规范和证据不一致 | 同步指令规范、架构、README、证据和验收矩阵 | 一键验证与文档引用同一测试入口 |
| A10 | P2 | Hybrid 二元表达式为结果多申请一个 scratch register | 经典测量位较多时会在本可编译的表达式上过早耗尽寄存器 | 将已拥有的左/右临时值原地复用为结果；一元负号也原地复用 | 20 cbit 占用 `x10..x29`、仅剩 `x30/x31` 时，多项加减和负号仍编译/执行正确 |
| A11 | P1 | L2 未知电路只在第一阶段检查 parser，语法合法但无测量/无法本地执行时不触发修复 | 向用户返回无法运行的“合法 QASM” | 把 `exact_probabilities` 执行纳入同一次有界验证/修复闭环 | 首次 QASM 有 qreg 但无测量，第二次修复后返回 50/50 可执行程序 |
| A12 | P1 | 后端 task 本地守卫曾把单独的“模拟器”词当作选型充分条件 | “生成可在模拟器运行的 Bell 电路”可被错分类 | 只在原文出现“后端/平台/推荐/选择/哪个”类选型意图且存在硬约束时纠正 task | 带“免费模拟器”的 Bell 生成仍返回经验证 QASM |
| A13 | P1 | 硬约束词法若忽略极性/上下界，可把“最多 10 比特”反向当成“至少 10”，或把“不要 AWS”当成 AWS-only | 安全守卫自身可制造违反用户意图的约束 | 对最多/至多/不超过/at-most 数值不生成 `min_qubits`；平台否定转成其他官方平台的允许集 | 最大值防反转与 `不要 AWS` 排除测试通过 |

## 仍然存在、不应被隐藏的限制

| ID | 剩余限制 | 为何没有伪装成“已解决” | 降低风险的当前措施 |
|---|---|---|---|
| R1 | 无赛程内真机 job | 真机分必须由外部账号、实际任务和平台回执证明，代码无法科学地替代 | 不申报该分；所有本地 job 明示 `loomq-local-` |
| R2 | 状态向量内存/时间指数增长 | 20 qubit 上限是可审计本地 oracle 的工程边界，不是平台能力上限 | 早失败、文档明示；后端能力数与本地模拟上限分开 |
| R3 | L1 只允许末端测量 | 中途测量需要密度矩阵/轨迹分支或 shot 级执行，已超出发布的直线 Base Profile | parser 保留测量顺序，本地执行遇到中途测量明确拒绝 |
| R4 | 非已知目标族的 L2 QASM 无完整意图 oracle | 任意自然语言与量子程序的语义等价本身是开放问题 | 已知 Bell/GHZ/均匀叠加/基态有确定性 builder 和分布 oracle；其他程序至少通过严格语法与状态执行 |
| R5 | 原文约束守卫是高精度词法规则，不是全自然语言形式化 | 反语、隐喻和未知语言可被遗漏 | 已检出约束有强安全保证；未检出部分仍由模型处理，决策轨迹不伪装全覆盖 |
| R6 | `backend_capabilities.json` 是赛题快照，不是实时云状态 | 评测要求以官方快照判定；外部队列/价格可变 | 答案明示能力表依据，不伪称为实时云监控 |
| R7 | 数值证书使用 binary64 | 它是带容差的数值检查，不是符号代数证明 | 无损的规范操作轨迹是主证据；数值状态/概率为防御性复核 |
| R8 | Quantum RISC-V 是参考 ISA/模拟器，未在真实 RISC-V+QPU 硬件实现 | 硬件时序、ABI、中断和并发等不在比赛模拟契约内 | 使用官方保留的 `custom-0`，严格拒绝保留编码，公开角度寄存器约定与误差界 |
| R9 | 形式命题未在 Coq/Lean 中机械化 | 纸笔归纳 + 执行测试不等于 proof assistant 验证 | `THEORY.md` 拆分前提/结论，反例测试与生产检查器同仓可运行 |
| R10 | 随机/变形测试仍是有限样本 | 有限测试不能证明无 bug | 固定 seed 保证复现；生产路径每次运行都会生成证书，不仅依赖测试期抽样 |
| R11 | Hybrid 的 `c[k]→x(10+k)` 映射最多容纳 22 个经典位，而复杂表达式还需要 scratch | 32 个寄存器中 `x0`、`x1..x9` 和测量映射已有固定契约 | 超过 22 cbit 立即给出明确错误；临时值原地复用降低峰值压力，耗尽时 fail-closed |

## 结论

当前软件层的 P0/P1 闭环缺口已逐项修复，剩余项都是被明确约束、可检测失败或需要外部权限/新研究的真实边界。该列表是当前发布子集和威胁模型内的完整审计，不声称穷尽任意未来需求。
