## 总体判断

架构落地得很干净：LLM 只出结构化理解、本地做确定性判定这条主线贯彻到位了，`simulate.py` 的状态向量实现、`normalize.py` 的 transpile 兜底、`render.py` 对多余 backend id 的清洗都写得比设计文档还实。**主链路（模型正常返回、目标态是内置 kind）应该能稳定拿分。**

问题集中在**异常路径**——而 12 个 case 的分差往往就出在异常路径上。下面 3 个是会直接吃分的，建议今天就修。

## P0 · 会直接吃分

### 1. 要求真机时，放宽逻辑会把答案退化成模拟器

`backends.py:33-34`：

```python
if not candidates:
    candidates = [b for b in load_backends() if b["max_qubits"] >= minimum] or load_backends()
```

放宽时**丢掉了所有软硬约束**，包括 `requires_hardware`。实测：

```
B  真机 + 100 比特(不可能满足) -> originq_local_simulator   ← 错，应答 originq_wukong
B2 真机 + 免费 + 零排队        -> originq_local_simulator   ← 错，应答某个 qpu
```

B2 不是刁钻构造：能力表里没有任何 `cost=free` 且 `queue=none` 的真机，所以只要变体里出现"我要在真机上跑，最好别排队/别花钱"，就必然踩中，答案从真机变成本地模拟器，该 case 直接判错。

**修法**：给约束分级，放宽时按优先级从低到高逐条丢弃，`requires_hardware` 永远不丢。

```python
HARD = ["requires_hardware"]            # 绝不放宽
SOFT = ["cost", "queue", "no_account", "local_only"]   # 按此顺序逐条放宽
```

### 2. `best` 实际是"最后一次"，不是"最好一次"

`l2_agent.py:161-162`：`if candidate: best = candidate` —— 每轮无条件覆盖。实测三轮 fidelity 分别是 0.983 → 0.000 → 0.000：

```
G 最终返回 -> "已通过本地模拟验证，保真度 0.000。"
```

第一轮那版 0.983 已经**超过评测线 0.97**（你的自验阈值 0.99 更严），却被后面更差的覆盖掉，本来能拿的分丢了。

顺带一个文案 bug：失败路径也走 `render_qasm(..., score)`，于是输出"**已通过**本地模拟验证，保真度 **0.000**"——自相矛盾，人工复核看到会扣印象分。

**修法**：`best` 存 `(score, text)` 元组取最大；`render.qasm` 的状态文案按是否达标分支（"已通过本地模拟验证" / "本地模拟保真度 X，未达自验阈值，已返回当前最优版本"）。

### 3. 模型/API 挂掉时返回纯文本，必 0 分

实测：

```
H API 三次全挂 -> 含 QASM? False
   输出：LoomQ Agent 暂时无法完成这次请求：RuntimeError: API down。请保留原始目标并重试。
```

而 `tests/test_l2_agent.py:92-108` 把这个行为**写成了期望值**（断言 `"暂时无法完成" in answer`），等于把 0 分固化成了正确行为。

设计文档里的 `last_resort` 没实现。只要拿到过 `target`（kind + n），本地就能直接合成 GHZ / Bell / W / uniform / basis 的电路——这依然是"消费模型的结构化输出"，不是关键词硬编码，不触碰反作弊条款。哪怕模型第一轮就崩，只要它吐出过 target，仍有机会拿分。

**修法**：`l2/synthesize.py` 加 `synthesize(target) -> qasm | None`，`agent_chat` 收尾时若 `best is None` 且有 target 就合成；单测相应改成断言"输出含可解析 QASM"。

## P1 · 会白白浪费一轮重试

### 4. 模型把围栏写进 JSON 的 `qasm` 字段就直接抛错

这是 DeepSeek 类模型极常见的行为。实测：

```
J qasm 字段 = "```qasm\nOPENQASM 2.0;..." -> QASM2ParseError: encountered '`'
```

`normalize.py` 两条路径（直接 parse / transpile）都会挂，整轮作废。**修法**：`normalize` 入口先剥一层——若含 ```` ``` ````，用现有的 `extract_qasm` 抠出程序体再解析。三行代码。

### 5. `kind=custom` 且没给 `expected_distribution` 时，语义校验完全跳过

`l2_agent.py:116-123`：`expected is None` 就直接 `return True`。实测用 `x q[0]` 冒充 GHZ、标 `kind=custom`：

```
I custom 无期望分布 -> 直接放行? True
```

私有变体大概率会出内置 kind 之外的目标态（比如"两个比特反相纠缠"、"三比特均匀叠加但第 2 位翻转"），这时模型只要偷懒标 custom，你的全部自验形同虚设。

**修法**：`custom` 且无 `expected_distribution` 时，不要放行，回一轮"请补充 expected_distribution"；仍拿不到再降级放行（并在渲染里注明"未做语义验证"，便于事后排查）。

### 6. `measure_all` 是死字段

system prompt 里声明了，没有任何代码消费。既然要模型填，就用它做一次廉价校验：`measure_all=True` 时断言 `len(circuit.measurements) == circuit.num_qubits`，能抓到"少测一位"这类高频错误。

顺带 `l2_agent.py:119` 用 `int(target_n) != circuit.num_bits` 比较——`n` 语义是**量子比特数**，这里拿经典比特数比，creg 比 qreg 短时会误判。

## P2 · 排序策略的风险（不一定是 bug，但值得决策）

### 7. 平局时选谁，和题面示例对不上

题面示例问"15 比特 + 零排队"，给出的规范答案形态是 `braket_local_simulator`。你的实现：

```
A  15q + 零排队        -> originq_local_simulator
A2 15q + 零排队 + 免费 -> originq_local_simulator
```

三个本地模拟器（spinq 24 / originq 30 / braket 25）都满足约束，`tie_break` 的 `-max_qubits` 选了 originq。题面写的是"唯一正确**答案集**"，字面上是集合，多解应该都算对——但能力表里只有 `braket_local_simulator` 的 notes 写着"**评测推荐默认模拟器**"，这像是在暗示标准答案。

建议把平局键改成"notes 标注推荐者优先"，或者干脆在无其他区分度时优先 `braket_local_simulator`。这一条影响面可能有 2–3 个 case，性价比很高。

### 8. `kind_rank` 把真机排在云服务前面

```
C 34 比特（无其他约束）-> originq_wukong   （真机，排队 hours，需账号）
```

用户没要求真机，却拿到一个要注册、排队几小时的方案，`braket_cloud`（34 比特、分钟级）反而更合理。建议 `kind_rank` 改成 `simulator 0, cloud 1, qpu 2`——未声明要真机时，排队和账号成本应该优先规避。

### 9. backend 任务零校验、一轮即返

`_handle` 里 backend 分支拿到约束就 `return True`，模型只要漏抽一个 `min_qubits`，就会用空约束选出默认值，且没有任何重试机会（实测空约束 → `originq_local_simulator`）。

低成本加固：让模型在 JSON 里额外返回一个 `backend_hint`，与本地筛选结果不一致时重试一轮并把双方结论摆给模型看。仍以本地为准，但多一次纠正抽取错误的机会。

## 写得好的地方

- `render.backend` 用正则把解释里的其它 backend id 替换成"该后端"，避免评测器命中多个 id —— 这个坑很隐蔽，处理得对，且有单测覆盖（`test_renderer_removes_extra_backend_ids_from_model_explanation`）。
- `render.qasm` 把 `OPENQASM` 替换成 `Open QASM`，防止解释文字被评测器正则误抓。实测解释里带围栏也不影响抓取。
- `normalize` 先试原样解析、失败才 transpile —— 保住了 `cu1`（不在 transpile basis 里）不被无谓分解。
- `simulate.py` 的测量映射用 `bits[measurement.bit]` 再整体 reverse，与 L1 三个后端的 counts 约定一致；`test_measurement_mapping_is_respected` 覆盖了交叉映射。
- `budget.timeout_for_call` 的 `min(45, remaining-8)` + `can_retry(20)` 组合，实测三轮不会超 110s。
