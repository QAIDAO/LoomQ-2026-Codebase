# LoomQ L2 改造设计方案

> 目标：把 L2 客观分（20 分）从"能解析就返回"提升到"语义正确 + 确定性判定 + 绝不 0 分"。
> 前置结论：客观分 ≥ 12 才计交互体验的 10 分，所以本方案先做客观分。

---

## 0. 评测口径回顾（决定了所有设计取舍）

| 事实 | 出处 | 设计含义 |
|---|---|---|
| 12 个 case，2 个私有种子，**每 case 120 秒** | `l2_policy.json` | 必须有全局 deadline，重试要算预算 |
| 意图生成 / 纠错按 **Fidelity ≥ 0.97** 判定 | 题面 §2 | 语法校验不够，必须本地模拟自验 |
| 选后端按官方能力表核对**唯一正确答案集** | 题面 §2 | 不能信 LLM 的结论，要本地确定性筛选 |
| 至少一次**有效模型调用**才有得分资格 | 题面 §2 | 主链路必须真实调 API，兜底不能绕过调用 |
| prompt 是**未公开变体**，关键词硬编码必挂 | 题面 §6 | 所有本地逻辑必须基于模型输出的结构化字段，不是基于 prompt 文本匹配 |
| `agent_chat` 抛异常 = 该 case 直接 0 分 | 评测器直接调用 | 顶层必须捕获一切异常 |
| 客观分 = 各变体通过率 × 20 | 题面 §2 | 12 个 case 每个约 1.67 分，稳定性比峰值更重要 |

---

## 1. 现状与缺口

`l2_agent.py` 现在的链路是：`system prompt → 调用 → extract_qasm → parse_qasm 成功就返回`，失败最多重试 3 次，仍失败则 `raise RuntimeError`。

| 缺口 | 后果 | 严重度 |
|---|---|---|
| 只验语法不验语义 | GHZ 少一个 `cx`、测量位映射错、多测一位 → 语法全对、fidelity 0 | 致命 |
| 后端推荐信任 LLM 结论 | `_recommended_backend_ids` 只检查"恰好出现一个 id"，模型选错照样返回 | 致命 |
| 失败后 `raise` | 该 case 从"部分分"变成"确定 0 分" | 致命 |
| 无时间预算 | `LOOMQ_LLM_TIMEOUT_SECONDS` 默认 120 = 单次调用吃满整个 case | 高 |
| 门集不兼容即失败 | 模型吐 `rx`/`u3`/`cz`/`cnot`/`id` → `parse_qasm` 抛 `Unsupported gate` → 白白浪费一轮 | 高 |
| 输出格式无约束 | 若 QASM 未包裹在 fence 中，评测器的正则会把后续解释文字吞进 QASM | 中 |

**关于输出格式这条要特别注意**：评测器（`evaluator.py:119`）的抓取正则是
`OPENQASM\s+2\.0;.*?(?=^\s*```|\Z)` —— 从 `OPENQASM 2.0;` 一直吃到**下一个 ``` 或文本结尾**。
所以硬性规则是：**QASM 必须放在 fenced code block 里，解释文字只能放在代码块之前，代码块之后不得再出现第二段 QASM。**
现在的 system prompt 说了"Put QASM in one fenced block"，但没有在代码层面强制；改造后由渲染层统一保证，不依赖模型听话。

## 2. 目标架构

把 `l2_agent.py` 从"一个函数"拆成"一条可验证的流水线"，新增 `starter_kit/l2/` 包：

```
starter_kit/
  l2_agent.py          # 只保留 agent_chat 编排 + 顶层兜底（约 120 行）
  l2/
    __init__.py
    budget.py          # 全局 deadline 与每次调用的 timeout 分配
    schema.py          # 结构化响应 schema 定义与解析
    normalize.py       # 门集归一化（qiskit transpile 到白名单基）
    simulate.py        # 零依赖 statevector 模拟（基于现有 IR）
    reference.py       # 目标态参考分布生成器（ghz/bell/w/plus/basis/uniform）
    verify.py          # Hellinger fidelity 自验
    backends.py        # 确定性后端筛选
    render.py          # 结构化结果 → 评测器友好的最终文本
```

原则：**LLM 只负责"理解"，不负责"判定"。**
模型输出理解结果（任务类型、目标态声明、约束、候选 QASM），所有对错判定由本地确定性代码完成。这既提升正确率，又天然规避反作弊条款——本地逻辑消费的是模型的结构化输出，不是 prompt 的关键词。

### 2.1 数据流

```
prompt
  └─> [单次结构化调用] ──> Response JSON
                            ├─ task: "generate" | "repair" | "backend"
                            ├─ qasm: str | null
                            ├─ target: {kind, n, measure_all, expected_distribution}
                            ├─ constraints: {min_qubits, queue, cost, requires_account,
                            │                requires_hardware, local_only}
                            └─ explanation: str
                                  │
       ┌──────────────────────────┴──────────────────────────┐
       │ task=generate/repair                                │ task=backend
       ▼                                                      ▼
  normalize(qasm)  ──失败──┐                          backends.select(constraints)
       │                    │                                 │  确定性筛选 + tie-break
  simulate(circuit)         │                                 │  保证输出恰好 1 个 id
       │                    │                                 ▼
  verify vs reference       │                          render.backend(...)
       │                    │
   fidelity ≥ 0.99 ?        │
    ├─ 是 ─> render.qasm(...)
    └─ 否 ─┴─> 带实际分布回灌重试（预算允许时）
                  └─ 预算耗尽 ─> 返回当前最优候选（绝不抛异常）
```

自验阈值取 **0.99**（评测线是 0.97），留出裕度。

### 2.2 为什么用"单次结构化调用"而不是多轮

120 秒预算下，每次调用按 20–35 秒估。单次调用同时拿到分类 + QASM + 目标声明 + 约束，可以留出 2 次重试的空间。若拆成"先分类再生成"，第一轮就烧掉三分之一预算，且分类本身没有独立价值——三类任务的处理分支可以由返回字段直接决定。

## 3. 模块设计

### 3.1 `budget.py` — 时间预算

```python
class Budget:
    def __init__(self, total: float = 110.0)   # 留 10s 给本地模拟与渲染
    def remaining(self) -> float
    def timeout_for_call(self) -> float        # min(remaining - 8, 45)
    def can_retry(self, min_seconds: float = 20.0) -> bool
```

- `agent_chat` 入口即创建 `Budget`。
- 每次调用把 `timeout` 透传给 `chat_completion`（需要给 `llm_client.chat_completion` 加一个可选 `timeout` 参数覆盖环境变量，改动 3 行）。
- `can_retry()` 为 False 时立刻走渲染兜底，不再发起调用。

### 3.2 `normalize.py` — 门集归一化

不手写重写表，直接用已有依赖 qiskit：

```python
BASIS = ["h", "x", "s", "sdg", "t", "tdg", "ry", "rz", "cx", "swap", "ccx"]

def normalize(qasm_str: str) -> tuple[str, Circuit]:
    qc = qasm2.loads(qasm_str, custom_instructions=qasm2.LEGACY_CUSTOM_INSTRUCTIONS)
    qc = transpile(qc, basis_gates=BASIS, optimization_level=0)
    return qasm2.dumps(qc), parse_qasm(qasm2.dumps(qc))
```

效果：模型吐 `rx`、`u3`、`p`、`cz`、`cnot`、`id`、`barrier` 一律自动落到白名单基，语义等价、fidelity 不变。**最终返回给评测器的是归一化后的 QASM**，保证评测器侧的 `parse_qasm` 也不会挂。
（`cu1` 在白名单里但不在 transpile 基里——若原电路含 `cu1` 且能被 transpile 消解则无妨；保守做法是先尝试原样 `parse_qasm`，成功就跳过 transpile，失败才归一化。）

### 3.3 `simulate.py` — 零依赖状态向量模拟

基于现有 `Circuit` IR，用 numpy 实现，约 80 行：

- 单比特门 `h x s sdg t tdg ry(θ) rz(θ)` → 2×2 矩阵作用
- 双比特 `cx swap cu1(θ)`、三比特 `ccx` → 按控制位掩码更新振幅
- 输出：按 `measurements` 的 qubit→bit 映射折算出的**经典比特串理想概率分布**（`{"000": 0.5, "111": 0.5}`）

不复用 spinqit/pyqpanda —— L2 评测环境只保证 `requirements.txt`，不能假设量子 SDK 可用；numpy + qiskit 已是既有依赖。

### 3.4 `reference.py` + `verify.py` — 语义自验

参考分布来源，按可信度排序：

1. **内置生成器**（首选）：`target.kind ∈ {ghz, bell, w, plus/uniform, basis, custom}` + `target.n` → 本地算出理论分布。GHZ(3) → `{000:0.5, 111:0.5}`；Bell → `{00:0.5, 11:0.5}`；W(3) → 三个单激发态各 1/3。
2. **模型声明的 `expected_distribution`**（fallback）：kind 为 `custom` 时使用。
3. 两者都拿不到 → 退化为"语法可解析 + 测量位数与 target.n 一致"的弱校验，并记录降级。

比对复用 `evaluator.py:41` 的 `calculate_hellinger_fidelity`，阈值 0.99。
失败时把**实际分布**和**期望分布**一起回灌给模型：

> 你上一版电路模拟结果是 `{001: 0.5, 110: 0.5}`，期望是 `{000: 0.5, 111: 0.5}`，测量映射可能反了。请给出修正后的完整程序。

这比现在只回灌 `ValueError: Unsupported gate` 的信息量高一个数量级。

**纠错任务的特殊处理**：目标态由 prompt 显式声明，所以 `target` 字段同样可用，验证路径完全一致；差别只在 system prompt 要求"保持用户声明的意图，不得改写目标态"。

### 3.5 `backends.py` — 确定性后端筛选

```python
def select(constraints: dict) -> str:
    cands = load_capabilities()["backends"]
    # 硬约束逐条过滤
    if constraints.get("min_qubits"):      cands = [b for b in cands if b["max_qubits"] >= n]
    if constraints.get("queue") == "none": cands = [b for b in cands if b["queue"] == "none"]
    if constraints.get("cost") == "free":  cands = [b for b in cands if b["cost"] == "free"]
    if constraints.get("requires_hardware"): cands = [b for b in cands if b["kind"] == "qpu"]
    if constraints.get("no_account"):      cands = [b for b in cands if not b["requires_account"]]
    if not cands: cands = relax(...)       # 逐条放宽最不重要的约束，绝不返回空
    return sorted(cands, key=tie_break)[0]["id"]
```

`tie_break` 排序键（约束全满足后的偏好）：
`(kind: simulator优先除非要求真机, queue: none < minutes < hours, cost: free < free_quota < paid, requires_account: False 优先, max_qubits 降序)`

**关键**：这是纯函数，可以针对 `backend_capabilities.json` 里的全部后端穷举写单测，把"唯一正确答案"钉死。这一类占 12 个 case 的约三分之一（≈6.7 分），改造后应当接近满分。

交叉校验策略：若模型自己也给出了 backend id 且与本地筛选结果不一致，**以本地为准**，但在解释文本中只输出本地结果（避免文本里出现两个 id 导致评测器歧义）。

### 3.6 `render.py` — 输出渲染

统一保证评测器可解析：

- **QASM 类**：先写一段面向零基础用户的白话解释（这也服务于"平权叙事"的人工分），再输出**唯一一个** ```` ```qasm ```` fenced block，块后不再出现任何 `OPENQASM` 字样。
- **后端类**：正文包含且仅包含一个规范 id，其余描述用后端的中文名而非 id，避免多 id 命中。
- 所有输出附一行自验状态（如"已本地模拟验证，保真度 1.000"），既是给评委看的可信度信号，也方便你自己排查。

### 3.7 `l2_agent.agent_chat` — 顶层编排

```python
def agent_chat(prompt, *, completion=chat_completion) -> str:
    budget = Budget()
    best = None
    try:
        for attempt in range(MAX_ATTEMPTS):
            resp = call_structured(messages, budget, completion)   # 至少一次真实调用
            result = handle(resp)          # 分支到 QASM 验证 或 后端筛选
            if result.ok: return render(result)
            best = better_of(best, result)
            if not budget.can_retry(): break
            messages += correction_from(result)
    except Exception as exc:
        log_debug(exc)
    return render(best) if best else render(last_resort(prompt_hint))
```

**顶层永不抛异常**。`last_resort` 只在"调用成功但内容完全不可用"时触发，且基于模型返回的 `target` 构造，不做 prompt 关键词匹配。

## 4. 实施顺序与工作量

按"改动小 × 收益确定"排序，每步独立可验收、可提交：

| # | 步骤 | 预估 | 收益 |
|---|---|---|---|
| 1 | `backends.py` 确定性筛选 + 穷举单测 | 1.5h | ≈6.7 分从"看运气"变"接近满分" |
| 2 | 顶层兜底不抛异常 + `render.py` 格式硬约束 | 0.5h | 消除确定 0 分的路径 |
| 3 | `budget.py` + `llm_client` timeout 透传 | 0.5h | 保住重试机会 |
| 4 | `normalize.py` 门集归一化 | 0.5h | 减少无效重试 |
| 5 | `simulate.py` + `reference.py` + `verify.py` 语义自验闭环 | 3h | ≈13.3 分从"语法对就行"变"语义正确" |
| 6 | 结构化响应 schema + system prompt 重写 | 1h | 支撑上述全部分支 |
| 7 | 真实 Key 端到端跑 12 个自造变体 case | 1h | 验收 |

合计约 8 小时。第 6 步实际上是第 1/5 步的前置，实现时会与之交织；顺序表按"验收点"排列。

## 5. 验收标准

**单测（mock completion，不耗 Key）**

- `backends.py`：对 `backend_capabilities.json` 中每个后端，构造一组必然唯一选中它的约束，断言返回其 id；另测约束冲突时的放宽路径与 tie-break 稳定性。
- `simulate.py`：Bell、GHZ3、W3、单比特 `ry(π/2)`、`swap` 后测量映射、`ccx` 真值表，与手算分布比对。
- `verify.py`：注入"测量位反了"的 GHZ（`{001,110}`）必须判定失败。
- `l2_agent`：模型连续返回垃圾时，`agent_chat` **不抛异常**且返回文本中含且仅含一个 fenced QASM 块；预算耗尽时不再发起第 4 次调用。
- 渲染格式：用 `evaluator.extract_qasm` 反向验证自己的输出能被正确抓取（防止解释文字被吞）。

**端到端（真实 Key）**

自造 12 个变体 case，覆盖：GHZ 3/4/5 比特、Bell、W 态、均匀叠加、大小写错误的纠错、缺 qreg 声明的纠错、目标态与代码不符的纠错、15 比特零排队选型、必须真机选型、必须免费无账号选型。
**通过线：12/12 语义验证通过，单 case 耗时 < 90 秒。**

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| `deepseek-v4-flash` 不稳定输出 JSON | schema 解析容错：先试整体 JSON，失败则正则抠 ```json 块，再失败则回退到"抓 QASM + 抓 backend id"的旧路径 |
| 私有变体出现内置生成器没覆盖的目标态 | `kind=custom` 时用模型声明的 `expected_distribution`；再不行降级弱校验并放行（弱校验通过率仍高于抛异常） |
| 评测环境无网络访问除模型服务外 | 全部本地依赖，不下载任何资源；`backend_capabilities.json` 随包读取 |
| 归一化改写导致电路与用户"声明意图"不符（纠错题） | transpile 是语义等价变换，不改变末态；但在解释文本中说明"已转换为标准门集" |
| 反作弊条款 | 本地逻辑只消费模型的结构化输出与官方能力表，不含任何对 prompt 文本的关键词分支；`last_resort` 也依赖模型返回的 target |

## 7. 与 L2 交互体验 10 分的衔接

客观分改造完成后，交互入口几乎是"免费"的：`l2/` 里已经有渲染层和自验结果，CLI 只需包一层
`python -m starter_kit.l2_cli` → 交互式输入 → 复用 `agent_chat` → 打印白话解释 + 自验保真度 + 后端建议 + 直方图（ASCII 即可）。
三个用户体验任务建议定为：①"我想要三个粒子都纠缠在一起" ②"这段代码报错了帮我修" ③"我要跑 15 比特还不想排队"，与客观三类任务同源，工作量最小。
证据包 `evidence/README.md` 中勾选"L2 交互体验"，写清启动命令与三个任务的操作路径即可。
