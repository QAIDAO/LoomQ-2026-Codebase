# Task 13F-4 — Inline Term Glossary

## 目标

在 Learn 页面增加一套轻量、可复用的量子术语解释交互：

- 新术语在正文中有清晰但不过度抢眼的视觉提示；
- 可点击术语使用类似飞书 Wiki 的 **虚线下划线**；
- 点击后在术语附近弹出一个小卡片，用 1–3 句话解释“这是什么 / 在当前例子里意味着什么”；
- 不把更多解释文字重新塞回主教学流程。

目标用户仍然是：**有编程基础、但没有量子计算背景的开发者**。

本任务只增强 Learn 的术语可读性，不改三步教学结构，不提前实现 Experiments / Explorer 的新功能。

---

## 为什么要做

当前 Learn 已经用一个 1-qubit 三步程序建立了正确的教学顺序：

> quantum circuit ≈ 一段按顺序执行的程序
> → 准备状态
> → gate 改变状态
> → measurement 读取结果

但正文仍会连续出现多个新名词。即使解释本身正确，用户扫读时不容易区分：

- 哪些只是普通说明；
- 哪些是之后还会持续出现的关键量子术语；
- 忘记一个术语时，应该去哪里快速补解释。

本任务的核心不是“增加更多教程内容”，而是给术语建立一个 **低干扰、可随时查询的阅读层**。

---

## 交互模型

参考飞书 Wiki 的术语体验，但不要复制其视觉细节。

### 默认状态

正文中的可解释术语：

- 保持 inline，不做大 chip；
- 使用细的虚线 / 点状下划线，明确暗示“可点击”；
- cursor 使用 pointer；
- 文字本身可以比正文略亮，但不要所有术语都使用高饱和强调色。

示意：

```text
一个 quantum circuit 可以先理解成一段按顺序执行的程序。
        ┄┄┄┄┄┄┄┄
```

### 点击后

在术语附近显示一个轻量 popover / glossary card：

```text
┌──────────────────────────────┐
│ 量子电路 · quantum circuit   │
│                              │
│ 一组按顺序执行的量子操作。   │
│ 在这里，你可以先把它当成     │
│ 一段会不断改变量子状态的程序。│
└──────────────────────────────┘
```

要求：

- 卡片不是 modal；
- 不遮住整个页面；
- 再次点击术语可以关闭；
- 点击卡片外部可以关闭；
- `Escape` 可以关闭；
- 同一时间最多打开一个术语卡片；
- 手机 / 触屏必须可以点击使用，不能依赖 hover；
- hover 可以有轻微视觉反馈，但不能把 hover 作为唯一打开方式。

不需要复杂动画，淡入或极轻位移动画即可，也可以完全没有动画。

## 术语视觉层级

### 1. 可查询术语：虚线下划线

所有进入 glossary 的术语统一使用这套交互提示。

### 2. 第一次真正“学到”某个概念时，可以保留轻量荧光笔效果

荧光笔只用于教学上的 **首次揭示**，不是所有术语的默认样式。

例如 Step 2：

> 这就叫 **叠加（superposition）**

这一处可以保留 / 调整为柔和的半透明背景或 marker 效果，同时该词仍然可以点击打开 glossary card。

不要：

- 给整段句子加高亮；
- 每次出现 `qubit` / `gate` 都加荧光背景；
- 使用过亮黄色导致和当前深色界面冲突。

原则：

> 虚线下划线 = 这是一个可以查询的术语；
> 轻量荧光 = 这是这一刻第一次真正需要记住的概念。

## 本次 Learn 页接入的术语

至少支持以下术语：

### quantum circuit / 量子电路

推荐解释：

> 一组按顺序执行的量子操作。对开发者来说，可以先把它理解成一段会逐步改变量子状态的程序。

### qubit / 量子比特

推荐解释：

> 量子程序操作的数据单位。它最终可以被测量成 0 或 1，但在测量前可以处于更丰富的量子状态。

不要在卡片里展开物理载体。

### quantum state / 量子状态

推荐解释：

> 程序当前的量子数据状态。它不仅包含“哪些结果可能出现”，还包含之后会影响干涉的量子信息。

避免说成普通概率数组。

### quantum gate / gate / 量子门

推荐解释：

> 改变量子状态的一次操作。可以类比为对程序状态执行一个变换；例如当前例子里的 `H`。

### measurement / 测量

推荐解释：

> 把量子状态读取成经典结果。一次测量得到一个确定的 0 / 1，多次重复运行后才形成统计分布。

### superposition / 叠加

推荐解释：

> 一个量子状态同时保留多个可能性。在当前例子里，执行 `H` 后，`|0⟩` 和 `|1⟩` 两种可能性都被保留下来。

可以补一句极短防误解：

> 它不是“结果已经随机选好了，只是我们还不知道”。

### shots

如果正文中的 `shots` 仍直接展示，建议也接入 glossary：

> 同一个量子电路重复准备、执行和测量的次数。多次 shots 用来观察结果的统计分布。

## 内容组织建议

不要把术语解释散落成多个 hard-coded click handler。

建议建立一个轻量静态 glossary 数据结构，例如：

```ts
const GLOSSARY = {
  circuit: {
    label: '量子电路',
    english: 'quantum circuit',
    description: '...',
  },
  qubit: { ... },
}
```

再封装一个可复用的 inline component，例如：

```tsx
<Term term="circuit">quantum circuit</Term>
<Term term="qubit">qubit</Term>
```

命名不要求完全一致，但应做到：

- glossary 内容集中管理；
- 术语展示组件可复用；
- 后续 Bell / Grover / Phase 可以继续增加 `entanglement` / `interference` / `phase`，而不需要重写交互。

本任务 **只实际接入 Learn 页面**，不要提前改 Bell / Grover / Phase。

---

## 可访问性

术语不能只是一个带 `onClick` 的普通 `<span>`。

应提供合理的键盘和语义支持，例如：

- 可聚焦；
- Enter / Space 可打开；
- `aria-expanded`；
- popover 与触发词有关联；
- Escape 可关闭；
- focus 状态可见。

可以用 button 语义做成视觉上像 inline text 的控件。

不要为了本任务引入完整 UI 框架或大型 popover 依赖。

1. Learn 正文中的核心量子术语有统一的虚线 / 点状下划线，可一眼辨认“可点击”；

4. 同时只打开一个卡片；
5. 点击外部 / 再次点击 / Escape 可以关闭；
6. 键盘可操作；
7. Step 2 的“叠加”首次揭示可以有轻量荧光 marker 效果，但页面不因此变花；
8. 三步教学结构完全保留；
9. 不产生后端或 LLM 请求；
10. `pnpm test` 与 `pnpm build` 通过；
11. 完成后停下，等待人工体验，不继续 Task 13G。
