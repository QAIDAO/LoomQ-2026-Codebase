# Task 13F — Web Developer Quantum Onboarding

## 目标

为 **有编程基础、但没有量子计算背景的开发者** 增加一个独立的新手引导页面，先建立最小的量子程序心智模型，再进入现有 LoomQ Quantum Explorer。

本任务只做 onboarding，不改实验内容、不改 Explorer 主工作区、不改 L2 correctness。

---

## 背景

当前 Explorer 已经可以逐步骤展示：

- 当前量子门 / 测量；
- 为什么这里需要这一步；
- 当前 QASM；
- 前后状态 / 概率变化；
- Just-in-time 概念解释。

但新用户进入前仍缺少一个全局 mental model，容易在还不知道 qubit / gate / circuit / measurement 分别是什么时，就直接进入 Bell / Grover 等电路。

`starter_kit/QUANTUM_101.md` 已经提供了适合开发者的表达方式。本任务应参考它的思路，但 **不要把整份文档搬进页面**。

核心原则：

> 不把用户训练成量子物理学生，只教够他开始读懂并运行一个量子程序。

---

## 页面边界

### 1. 新手引导必须是独立页面 / 独立 screen

不要把 onboarding 卡片塞进现有 Explorer 三栏布局，也不要和实验步骤同时出现。

当前 Web 没有路由依赖，本任务不要求为了这一个页面引入 React Router。

可以使用轻量页面状态实现两个清晰独立的 screen：

- `Learn`：新手引导；
- 当前已有的实验 / Explorer 入口。

要求：

- 两个 screen 视觉上完整分开；
- 用户可以从 Learn 明确进入现有实验入口；
- 用户进入 Explorer 后仍能通过顶部或明确入口重新打开 Learn；
- 不要求 localStorage / 首次访问识别；
- 不做复杂 onboarding stepper、弹窗 tour 或遮罩引导。

后续 Task 会单独增加 Experiments 页面，因此本任务只需为后续导航留出清楚结构，不要提前实现 13G。

## Learn 页面内容

### 页面定位

建议主标题表达：

> 先用开发者的方式理解量子程序

副文案需要明确：

- 不要求量子物理背景；
- 先把量子程序映射到熟悉的软件工程概念；
- 这些概念足够开始第一个实验。

### 必须覆盖的 5 个最小概念

文案可以根据页面设计微调，但含义必须保持简单、准确。

#### Qubit / 量子比特

开发者心智：

> 量子程序里的基本信息单位。多个 qubit 一起组成程序当前的量子状态。

不要在主文案中展开物理实现。

#### Quantum State / 量子状态

开发者心智：

> 可以先把它理解成程序运行时的数据；它记录当前所有可能结果以及这些结果之间的信息。

避免说成普通概率数组，因为后续相位也是状态的一部分。

#### Gate / 量子门

开发者心智：

> 修改量子状态的一次操作，类似对程序状态执行一个函数。

可以展示 `H`、`CX` 作为代码感示例，但此处不要教学每个门具体数学含义。

#### Circuit / 量子电路

开发者心智：

> 一组按顺序执行的量子操作，可以先把它看成一段指令列表。

强调“顺序执行”，帮助用户连接后续 Explorer 的逐步骤回放。

#### Measurement / 测量

开发者心智：

> 把量子状态读取成普通程序能够处理的 0 / 1 结果；同一程序重复运行时会形成概率分布。

不要在 onboarding 主页面展开坍缩理论。

## 技术层解释（可选展开）

页面可以提供一个轻量折叠项，例如：

> 想看更技术一点？

只允许补充非常短的开发者版说明，例如：

- n 个 qubit 的纯态可由长度 `2^n` 的复振幅状态向量表示；
- Gate 对状态向量做确定性的变换；
- Measurement 按振幅模平方对应的概率进行采样；
- 多次 shots 得到 counts / 概率直方图。

这部分必须默认收起。

不要加入：

- 薛定谔方程；
- Bloch sphere；
- Hilbert space；
- 手算矩阵；
- 量子硬件物理；
- 量子纠错。

## 页面 CTA

Learn 页面底部需要一个明确主 CTA：

> 开始一个量子实验 →

点击后进入当前已有的实验 / Explorer 起始 screen。

可以保留一个弱化的跳过入口，例如：

> 我已经了解基础概念，直接开始

不要在本任务中实现新的实验卡片内容；实验选择会在 Task 13G 单独完成。

---

## 视觉要求

继续沿用当前 LoomQ Quantum Explorer 的深色开发工具视觉语言，但 Learn 页面不要做成三栏 DevTools。

目标是：

- 独立、宽松、容易扫读；
- 5 个概念有清楚层级；
- 每个概念 1–3 句话即可；
- 有一点代码 / terminal / state 的视觉隐喻可以，但不要为了炫技增加复杂动画；
- 低高度屏幕可正常滚动，不要强制一屏塞完。

---

## 数据与架构边界

本任务全部使用前端静态内容。

禁止：

- 新增 LLM 调用；
- 修改 Teaching Explainer schema；
- 修改 `/api/debug`；
- 修改 `adapter.agent_chat()`；
- 修改 parser / verifier / repair / backend selection；
- 修改 Circuit Trace；
- 为 onboarding 新增服务端接口。

不要从 `QUANTUM_101.md` 在运行时动态读取内容；可以人工提炼成前端静态文案。

7. 不产生任何额外后端 / LLM 请求；
8. 原有 Bell / GHZ / Phase / Grover 运行路径不受影响；
9. `pnpm build` 通过；
10. 现有 Web tests 通过。
