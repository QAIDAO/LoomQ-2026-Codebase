## Learn 主线：一个 1-qubit 最小程序

Learn 页面主体改成一个清楚的三步流程。

### Step 1 · 准备状态

展示类似：

```text
qreg q[1];

|0> 100%
```

解释重点：

- 程序先准备一个 qubit；
- 可以先把 qubit 理解成量子程序正在操作的数据单位；
- 当前量子状态是确定的 `|0>`。

此处不要先展开“状态向量”“振幅”等术语。

### Step 2 · 用 Gate 改变状态

展示类似：

```text
h q[0];

执行前：|0> 100%
执行后：|0> 50% · |1> 50%
```

解释重点：

- `H` 是一个 quantum gate；
- gate 会改变当前量子状态；
- 此时程序同时保留 `|0>` 和 `|1>` 两种可能性；
- **在这里第一次引出“叠加 / superposition”这个名字。**

推荐表达：

> 刚才发生的这种“同时保留多个量子可能性”，就叫叠加。

需要加一句防误解：

> 这里先把它理解成多个量子可能性同时被保留即可；它不等同于普通程序里随机选了一个结果、只是你还不知道。

不要在 Learn 中解释叠加的矩阵或物理推导。

### Step 3 · 测量

展示类似：

```text
measure q[0] -> c[0];
```

解释重点：

- 真正读取时，一次只会得到 `0` 或 `1`；
- 同一个程序重复运行很多次，才会看到大约 50% / 50% 的统计分布；
- measurement 是把量子状态转换为普通程序可以继续处理的经典结果。

### 最后再命名整体

三步结束后再总结：

> 准备状态 → 执行 Gate → 测量读取，连起来就是一个 quantum circuit。

这时再补充：

- qubit：程序操作的数据单位；
- state：程序当前的量子状态；
- gate：改变状态的操作；
- circuit：按顺序执行的操作列表；
- measurement：读取经典结果。

这些可以作为很轻的 recap，不要重新做成五张等权大卡片。

## 纠缠不要放 Learn 主流程

本任务 **不要在 Learn 中系统解释纠缠**。

纠缠需要至少两个 qubit 和具体前后状态才容易理解，应该留到后续 Bell 实验中 Just-in-time 展示：

```text
H 后：
|00> 50%
|10> 50%

CX 后：
|00> 50%
|11> 50%
```

然后再解释为什么没有 `01 / 10`，以及为什么这不是两个独立随机变量。

因此知识分配固定为：

- Learn：qubit / state / gate / circuit / measurement + 叠加；
- Bell：纠缠；
- Grover：干涉 / 概率放大；
- Phase 实验：相位。

本任务只实现 Learn 部分，不改 Bell / Grover / Phase。
