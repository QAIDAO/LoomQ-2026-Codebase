# Task 11B：L2 QASM 校验与一次修复闭环

## 前置条件

Task 11A 已完成并通过：

- `adapter.agent_chat()` 已接入独立 L2 模块；
- 首次模型调用和结构化 JSON 解析可用；
- 合法 QASM 可提取并通过现有 Parser；
- 模型异常和凭证安全测试已覆盖。

本任务在现有骨架上增加“最多一次修复”，不重写 11A 架构。

## 目标

实现：

```text
用户目标
→ 第一次模型生成候选 QASM
→ 本地 Parser 校验
→ 失败时发起一次修复调用
→ 再次校验
→ 成功返回，或稳定停止
```

覆盖自然语言生成和错误 QASM 修复两类任务。

## 实现范围

### 1. 扩展任务类型

首次结构化响应支持：

```json
{
  "task_type": "generate_qasm | repair_qasm",
  "qasm": "OPENQASM 2.0; ...",
  "explanation": "简短说明"
}
```

要求：

- 模型判断用户是在生成还是修复；
- 修复任务必须保留用户明确声明的目标态、目标功能和测量要求；
- 不能只把代码改到语法可解析，却改变目标语义；
- 不用关键词分支直接拼接 Bell、GHZ 等固定程序。

### 2. 稳健 QASM 提取

完善 Task 11A 的提取工具：

- 支持纯 QASM；
- 支持 `qasm`、`openqasm` 或无语言标识的 fenced block；
- 忽略代码块前后的简短说明；
- 从 `OPENQASM 2.0;` 开始提取；
- 不接受多个互相冲突的 QASM 程序；
- 不用正则重新实现语法校验，最终仍调用 `parse_qasm()`。

### 3. 一次修复调用

第一次 QASM 校验失败时，最多再调用一次模型。

第二次 Prompt 应包含：

- 原始用户请求；
- 第一次候选 QASM；
- 清理后的 Parser 错误；
- 明确要求返回完整、可独立运行的 OpenQASM 2.0；
- 明确要求保持原目标态和测量语义；
- 要求结构化 JSON 或沿用 11A 已定义的修复响应协议。

Parser 错误清理要求：

- 只传递错误类型和必要位置/消息；
- 不传 Python traceback；
- 不包含本机绝对路径；
- 不包含环境变量或 API Key；
- 长错误应截断到合理长度。

### 4. 严格重试上限

- 第一次合法：总调用次数为 1；
- 第一次非法、第二次合法：总调用次数为 2；
- 两次均非法：总调用次数仍为 2，然后稳定失败；
- 不得递归、循环或自动继续第三次调用。

建议把最大修复次数写成局部明确常量，但不要暴露成无必要的环境变量。

### 5. 最终输出

成功时继续使用：

```text
简短说明

```qasm
OPENQASM 2.0;
...
```
```

最终 QASM 必须：

- 通过 `parse_qasm()`；
- 包含完整寄存器声明；
- 满足用户要求的测量；
- 可被官方 evaluator 的 QASM 提取逻辑识别。

失败时返回或抛出稳定、可理解的错误，例如“模型两次生成的 QASM 均未通过校验”。不要返回内部 traceback。

## 自动化测试

在现有 L2 测试上至少新增：

1. **一次成功不重试**：合法 QASM 总调用次数为 1；
2. **Bell 修复**：第一次响应仍有语法错误，第二次返回正确 Bell QASM，总调用次数为 2；
3. **生成后修复**：生成任务第一次缺少测量，第二次补全后通过；
4. **最多一次修复**：两次均非法，确认不会第三次调用；
5. **保持目标态**：修复后的程序仍符合用户明确声明的 Bell 或 GHZ 目标结构；
6. **错误清理**：第二次模型收到的错误文本不含绝对路径或 traceback；
7. **fenced QASM**：模型返回带说明和 fenced code 时可提取；
8. **多个程序冲突**：拒绝含多个不一致 QASM 的响应；
9. **安全性**：最终异常不包含测试 Key；
10. **L1 回归**：现有全量测试通过。

关于“保持目标态”的测试，应检查电路结构或用现有无噪声模拟器验证，不要仅检查字符串中出现 `h`、`cx`。
