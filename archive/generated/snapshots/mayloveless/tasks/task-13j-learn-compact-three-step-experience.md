# Task 13J — Learn Compact Three-Step Experience

## 目标

重构 Learn 页面下半段的新手教学，让它从“重复讲解 + 常驻源码 + 长页面”收敛成一个**紧凑的三步量子程序体验**。

本任务只处理 Learn 的三步教学区域，不改 Why Quantum、不改 Experiments、不改 Explorer。

核心原则：

> **状态变化是主角，源码是按需查看的证据。**

用户应该先看见量子程序每一步发生了什么，再在需要时查看对应源码位置。

---

## 当前问题

现在 Learn 在 Why Quantum 之后存在两层重复：

1. `跟着一个量子比特，看懂量子程序怎么运行`
2. `一个量子电路，三步看完`

二者都在讲 Prepare → H → Measure，导致信息重复。

同时：

- 完整 QASM 代码窗口一直占据较大视觉空间；
- 新手第一眼看到的是很多文本和代码，而不是状态变化；
- 量子电路的定义、三步结构、每一步解释被拆得太散；
- 页面偏长，三步之间的关系不够集中。

---

## 重构后的结构

将现有 `learn-hero` + `guided-program` 这两层重复教学，合并成**一个统一的 Quickstart / Three-Step Experience 区域**。

建议结构：

```text
┌────────────────────────────────────────────┐
│ ONE QUBIT · THREE STEPS                    │
│ 跟着一个量子比特，看懂量子程序怎么运行      │
│                                            │
│                              什么是量子电路？│
│                              按顺序执行的一组│
│                              量子操作。      │
├────────────────────────────────────────────┤
│ 01 Prepare   →   02 H   →   03 Measure     │
├──────────────────┬─────────────────────────┤
│ 当前步骤          │ 状态变化 / 可视化         │
│ 简短解释          │                         │
│ 查看源码          │                         │
└──────────────────┴─────────────────────────┘
```

不要再保留一个单独的大代码 Hero + 一个单独的长三步列表。

---

## 1. 顶部：只保留一次教学入口

保留这一层含义：

- `ONE QUBIT · THREE STEPS`
- `跟着一个量子比特，看懂量子程序怎么运行`
- 不需要量子物理背景

但不要再在这里常驻展示完整 QASM code window。

右上或右侧使用一个很轻的认知块解释：

> **什么是量子电路？**
> 可以先理解成：按顺序执行的一组量子操作。

要求：

- 只用 1–2 句；
- 不单独做成长科普 card；
- 不重复后面 recap 的完整术语定义。

---

## 2. 三步导航必须成为主要骨架

明确展示：

```text
01 Prepare → 02 H → 03 Measure
```

三步文案建议：

### 01 Prepare

标题：`准备 |0⟩`

一句话：

> 程序先准备一个确定的量子状态。

### 02 H

标题：`产生叠加`

一句话：

> H 把原本确定的 |0⟩ 变成同时保留两种可能性的状态。

这里继续保留 `叠加（Superposition）` 的教学语义，但不要重新展开成长段落。

### 03 Measure

标题：`读取结果`

一句话：

> 测量把量子状态读取成经典的 0 或 1。

用户可以点击三步切换当前步骤。

当前步骤必须清晰可见，但不要依赖大量不同颜色。

---

## 3. 当前步骤区域：文字尽量短

选中某一步后，左侧只展示：

- 当前步骤编号 / 名称；
- 1–2 句解释；
- 必要术语；
- `查看源码` 入口。

不要重新出现目前每一步的大段说明卡、嵌套 aside、重复总结。

目标：用户一眼能回答：

> **现在执行了什么？**

---

## 4. 源码改成按需展示

完整 QASM 不再常驻占位。

使用现有固定示例：

```qasm
OPENQASM 2.0;
include "qelib1.inc";
qreg q[1];
creg c[1];
h q[0];
measure q[0] -> c[0];
```

### 桌面端

在 `查看源码` hover / focus 时展示源码浮层或 popover。

### 点击行为

同时支持 click 打开 / 关闭，不能只依赖 hover。

### 移动端 / touch

必须可以通过点击查看源码。

### 当前行高亮

按当前步骤高亮对应源码：

- Prepare：重点高亮 `qreg q[1];`，可根据现有实现同时轻量关联初始化语义；
- H：高亮 `h q[0];`；
- Measure：高亮 `measure q[0] -> c[0];`。

其他行正常显示，不要隐藏。

源码的定位是：

> **告诉用户“刚才看到的状态变化，在真实程序里对应这里”。**

不是本区域主视觉。

---

## 5. 右侧：状态变化成为主视觉

右侧不再只是静态文本卡，要用简单、稳定、可理解的视觉表达每一步。

本任务只做 Learn 的基础三步，不实现 Grover Oracle / Diffusion。

### Step 01 — Prepare

清楚表达：

```text
|0⟩   100%
|1⟩     0%
```

重点：当前状态是确定的。

### Step 02 — H

清楚表达“执行前 → H → 执行后”。

可以使用：

```text
        H
|0⟩  ───→   |0⟩  50%
             |1⟩  50%
```

或者现有视觉体系下更合适的等价形式。

要求：

- 用户必须能看见 `|0⟩ 100% → |0⟩ / |1⟩ 50% / 50%` 的变化；
- 可以有一个短动画表现变化过程；
- 动画只是帮助理解，不要做游戏化效果；
- 不要自动循环得很快或产生视觉噪音；
- 尊重 `prefers-reduced-motion`，必要时退化为静态前后状态。

### Step 03 — Measure

清楚区分：

```text
一次运行
→ 0 或 1

重复很多次
→ 约 50% / 50%
```

让新手理解：一次 measurement 不是直接产生一个 50/50 图表；统计分布来自重复 shots。

---

## 6. 动画原则

本任务允许加入非常轻量的状态变化动画，但只服务理解。

要求：

- 切换步骤时可以播放一次；
- 不要持续循环；
- 不要炫技粒子、光效、游戏效果；
- 不要模拟不存在的真实量子物理运动；
- 动画表达的是**教学上的状态变化**，不是物理过程录像；
- Reduced Motion 模式下必须仍然完全可理解。

---

## 7. 删除重复内容

实现后检查 Learn：

- 不应再同时存在一个完整 code hero 和一个完整 three-step long list；
- `量子电路是什么` 只在 quickstart 顶部轻量解释一次；
- Prepare / H / Measure 的核心解释只保留一套；
- 不重复描述 `准备 → 改变 → 测量` 多次。

可以删除因此失去作用的旧 DOM / CSS。

不要为了兼容旧样式留下大量 dead CSS。

---

## 8. Recap 与后续内容

现有 `NOW NAME THE PARTS` recap 可以保留。

它的定位仍然是：

> **先看懂发生了什么，再给刚才已经理解的内容补上术语名字。**

不要把 recap 合并进三步交互，也不要提前把所有术语重新塞进每一步。

`想看更技术一点？` 默认折叠区域也可以保留。

---

## 9. 本任务不做

禁止顺手修改：

- Why Quantum / 13I 的三类应用内容；
- 首屏产品定位；
- Experiments；
- Explorer；
- Repair / Backend；
- stable prompts；
- Grover Oracle / Diffusion 可视化；
- Bell / Phase 教学；
- parser / verifier / repair；
- Teaching Explainer / Circuit Trace；
- `/api/debug`；
- LLM 调用数量或后端行为。

本任务只建立 Learn 的基础可视化教学语言。

---

## 验收重点

完成后人工检查：

1. Why Quantum 之后，是否只剩一个清晰的三步新手体验，而不是两层重复教学？
2. 第一眼是否能看见 `Prepare → H → Measure`？
3. 切换步骤时，右侧是否比文字更直观地表现状态变化？
4. H 步是否明确展示 `|0⟩ 100% → |0⟩/|1⟩ 50%/50%`？
5. Measure 是否明确区分“一次结果”和“多次 shots 的统计分布”？
6. 完整 QASM 是否默认不占主要空间，但随时可以查看？
7. 查看源码时是否准确高亮当前步骤对应的源码行？
8. Hover、keyboard focus、click、touch 是否都能访问源码？
9. 页面整体是否明显比当前 Learn 更短、更集中？
10. 是否完全没有改动其他页面和 correctness 路径？

完成后停止，让用户先体验 Learn 三步交互，不要继续实现 Grover 或 Explorer。
