# LoomQ L2 用户界面与交互设计文档

> 文档状态：产品设计稿  
> 适用范围：LoomQ L2 交互入口  
> 核心定位：面向零量子基础及传统量子工具边缘用户的、单场景 Agent 引导式量子实验环境  
> 设计依据：LoomQ 赛题手册中对自然语言生成、代码纠错、智能选后端、结果可视化、零基础交互与包容性设计的要求

---

## 1. 文档目的

本文档定义 LoomQ L2 用户界面的整体体验、视觉结构、核心功能、交互规则和主要引导路径，供产品设计、视觉设计、前端制作、内容编写和现场演示共同使用。

本文档重点回答以下问题：

1. 用户打开 LoomQ 后首先看到什么；
2. 用户如何在不理解 QASM 的情况下完成第一个量子实验；
3. Agent 如何在同一界面内持续引导用户，而不是把体验变成普通聊天；
4. 自然语言生成、代码纠错与后端选择如何围绕同一个实验自然衔接；
5. 图形化电路、QASM、验证信息和运行结果如何保持统一；
6. 如何在降低认知门槛的同时维持技术严谨性；
7. 如何让键盘用户、屏幕阅读器用户、低视力用户及不适应高动态界面的用户完整使用产品。

本文档不展开模型调用、前后端通信、量子 SDK、数据结构、依赖管理或部署流程等实现细节。

---

## 2. 产品定位

### 2.1 一句话定义

LoomQ L2 是一个以“当前实验”为持续对象、以图形化量子电路为视觉中心、以 Agent 为认知导航、以实验目标和验证证据保证技术严谨性的单场景量子实验环境。

### 2.2 它不是什么

LoomQ L2 不是：

- 将专业量子 IDE 简化配色后交给新手；
- 在代码编辑器旁增加一个普通聊天窗口；
- 由多个页面、关卡和剧情组成的科普游戏；
- 通过拟人化比喻替代正式量子概念的儿童化教程；
- 以积分、徽章、排行榜或答题正确率驱动的学习产品；
- 面向完整量子课程、复杂算法开发或高级工程优化的一站式平台。

### 2.3 它是什么

LoomQ L2 提供一个始终稳定的实验空间。用户可以从预设实验、自然语言描述、已有 QASM 或当前运行需求中的任一入口开始；进入后，实验目标、图形化电路、QASM、验证状态、后端选择与运行结果始终围绕同一个“当前实验”组织。

用户不必先学会使用工具，才有资格接触量子计算。用户先在 Agent 引导下完成一次真实、严谨、可解释的实验，再根据兴趣逐步展开代码、数学表达和工程细节。

## 3. 设计目标

### 3.1 核心体验目标

一位没有量子物理、量子编程或 QASM 背景的用户，应能在约五分钟内：

1. 理解当前实验要制备或观察什么；
2. 在引导下构建一个有效的量子电路；
3. 知道每一步操作的正式名称及其在当前实验中的作用；
4. 在模拟器中完成运行；
5. 读懂主要测量结果；
6. 理解结果能支持什么结论，以及不能支持什么结论；
7. 知道如何继续修改实验或尝试真实量子后端。

### 3.2 L2 能力目标

界面需自然覆盖以下三类能力：

- **自然语言生成电路**：从用户的目标描述中建立实验目标，并生成可验证的 OpenQASM 2.0 电路；
- **纠错与修复**：定位语法、结构和目标一致性问题，在不擅自改变用户声明目标的前提下提出修复；
- **智能选择后端**：根据当前电路和用户约束推荐执行环境，并解释推荐与排除理由。

三类能力不设计为三个互相割裂的应用模块，而是当前实验生命周期中的三个动作。

### 3.3 学习体验目标

界面应当：

- 默认使用正式术语，而不是用含混比喻取代概念；
- 通过逐步展开降低认知负担，而不是删除必要信息；
- 允许用户在“简明说明、详细说明、数学表达”之间切换；
- 明确区分理想电路、有限采样和真实硬件噪声；
- 对实验结论保持证据边界，不夸大单次结果；
- 允许用户随时跳过讲解、自己操作或重新请求引导。

### 3.4 包容性目标

任何核心操作都不得仅依赖：

- 拖拽；
- 鼠标悬停；
- 颜色；
- 动画；
- 视觉空间定位；
- 对专业缩写的已有认识。

## 4. 目标用户

### 4.1 主要用户：零量子基础的跨界探索者

可能来自艺术、设计、人文、社会科学、教育、公益、产品或普通公众领域。其特点是：

- 对量子计算可能有兴趣，但不知道能做什么；
- 不熟悉量子门、测量基、QASM 或量子云平台；
- 不希望先完成系统课程再使用工具；
- 愿意通过操作、观察和提问逐步学习；
- 需要清楚的下一步，而不是空白输入框。

### 4.2 次要用户：有一般编程经验但无量子经验的开发者

其特点是：

- 能够阅读代码和错误信息；
- 希望快速理解电路、QASM 和后端差异；
- 可能直接导入、修改或修复代码；
- 需要 Agent 解释量子语义，而不是讲解基础编程概念。

### 4.3 次要用户：具有无障碍需求的用户

包括但不限于：

- 依赖键盘导航的用户；
- 使用屏幕阅读器的用户；
- 低视力或色觉差异用户；
- 对动画、闪烁或高信息密度敏感的用户；
- 容易因不稳定布局、隐藏状态或长篇输出而失去上下文的用户。

### 4.4 高级用户

熟悉 QASM 或量子电路的用户可以直接编辑电路、代码和运行参数，但高级能力不应改变默认界面的新手优先顺序。

## 5. 核心设计原则

### 5.1 单场景，而非多页面关卡

用户从开始到运行结果都停留在同一主界面。所谓“路径”是 Agent 对同一实验对象施加的引导序列，不是频繁的页面切换。

界面可以改变高亮、提示、面板内容和当前主动作，但以下核心对象始终留在原位：

- 当前实验目标；
- 图形化量子电路；
- 对应 QASM；
- Agent 引导；
- 验证、后端和运行结果区域。

### 5.2 当前实验是唯一中心

界面中的所有信息必须明确属于当前实验。

用户不应需要在“聊天记录中的目标”“编辑器中的代码”“另一个页面的运行任务”和“弹窗中的结果”之间自行拼接上下文。

### 5.3 目标—电路—证据三元组

统一体验的核心不是单独的电路图，而是以下三个持续对象：

1. **目标**：用户希望制备、观察、测量或运行什么；
2. **电路**：实现目标的图形表示和 QASM 表示；
3. **证据**：语法检查、目标验证、后端适配与运行结果。

Agent 的主要任务是帮助用户在三者之间建立关系：

- 目标要求什么；
- 当前电路如何实现目标；
- 当前证据是否支持“实验成功”；
- 证据能支持多强的结论。

### 5.4 正式术语优先，逐步形式化

界面使用“量子比特”“Bell 态”“H 门”“CX 门”“Z 基测量”等正式术语。

通俗性通过以下方式实现：

- 首次出现时提供一句操作性定义；
- 将解释限制在当前步骤；
- 把公式和扩展内容放在可展开层；
- 提供术语表和上下文提示；
- 用清晰例子辅助理解。

不使用“量子共享秘密”“量子一起行动”“量子知道另一边发生什么”等替代性拟人化表达。

### 5.5 引导不等于强制

用户始终可以：

- 按推荐步骤继续；
- 查看原因；
- 跳过当前讲解；
- 直接自己操作；
- 切换到自由实验；
- 恢复 Agent 引导；
- 撤销最近操作；
- 重置为当前路径的初始实验。

### 5.6 游戏性来自探索循环

产品保留以下具有游戏感的交互：

- 先预测再运行；
- 改变一个变量再比较；
- 逐步看到电路形成；
- 获得即时、可解释的验证反馈；
- 从模拟器继续到真实量子机；
- 从结果反向提出新问题。

不使用积分、排行榜、连续签到、强制测验或“答错失败”。

## 6. 整体信息架构

产品由一个主界面构成。主界面从上到下包含六个固定区域：

1. 全局顶栏；
2. 路径与入口标签区；
3. 当前实验目标区；
4. Agent 引导区；
5. 电路与 QASM 工作区；
6. 验证、后端与结果区。

建议的桌面端结构如下：

```text
┌────────────────────────────────────────────────────────────────────┐
│ LoomQ                    当前实验名称              帮助  显示设置 │
├────────────────────────────────────────────────────────────────────┤
│ [Bell 态] [GHZ 态] [导入并检查] [自由描述] [选择后端]            │
├────────────────────────────────────────────────────────────────────┤
│ 当前实验目标：制备 |Φ+⟩，随后在 Z 基测量两个量子比特             │
│ [编辑目标] [查看数学定义]                                         │
├────────────────────────────────────────────────────────────────────┤
│ Agent：当前说明、下一步建议、可选追问                              │
│ [添加 H 门] [为什么？] [我自己操作]                               │
├───────────────────────────────────────┬────────────────────────────┤
│                                       │                            │
│           图形化量子电路               │     OpenQASM / 诊断        │
│           始终为视觉中心               │     与电路同步             │
│                                       │                            │
├───────────────────────────────────────┴────────────────────────────┤
│ [验证] [后端] [结果] [解释]                                       │
│ 当前证据、推荐后端、计数分布、结论边界                            │
└────────────────────────────────────────────────────────────────────┘
```

用户在不同路径中看到的是同一结构。变化发生在：

- 当前标签；
- 实验目标；
- Agent 当前话语；
- 电路状态；
- 下方面板当前选项；
- 主按钮和可执行动作。

## 7. 预期视觉外观

### 7.1 总体气质

界面应呈现“开放的科学实验环境”，而不是“黑客终端”“商业数据仪表盘”或“儿童科普游戏”。

关键词：

- 清晰；
- 克制；
- 精确；
- 安静；
- 可操作；
- 有探索感；
- 不制造技术威压。

### 7.2 色彩

建议使用浅色背景作为默认模式：

- 主背景：温和的纸白或浅灰；
- 主文字：接近黑色的深灰；
- 主强调色：冷蓝、蓝紫或青蓝，用于当前步骤和选中对象；
- 成功、警告、错误状态可使用常见状态色，但必须同时配合文字和图标；
- 电路中的不同门可以有轻度色彩区分，但门名、边框形状和文字标签必须足以独立识别。

同时提供深色模式，但深色模式不是主要视觉叙事的一部分。

### 7.3 字体与排版

- 一般界面使用清晰的无衬线字体；
- QASM 使用等宽字体；
- 数学表达使用易读的数学排版；
- 正文默认字号不小于常见网页正文标准；
- 行距宽松，段落不宜过长；
- Agent 的关键结论、限制条件和下一步分开呈现；
- 不在同一屏幕堆叠大段聊天气泡。

### 7.4 图形语言

- 电路线路保持水平、稳定和高对比；
- 门使用简洁几何形状；
- 当前门、当前代码行和当前讲解之间通过统一高亮关联；
- 图标只作为文字的辅助，不单独承担意义；
- 动画只用于说明状态变化，不作为主要信息载体；
- 禁止快速闪烁、无意义粒子效果和持续背景动画。

### 7.5 空间层级

视觉中心始终是图形化电路。

Agent 引导区应明显但不过度占据空间。它更像实验台上方的“当前指导卡”，而不是右侧长期滚动的聊天软件。

QASM 是重要的同步视图，但默认权重低于电路。对于第一次使用者，QASM 侧栏可以较窄；用户主动编辑后，可扩大侧栏。

验证与结果区位于电路下方，形成自然的“操作在上、证据在下”关系。

## 8. 全局顶栏

### 8.1 内容

顶栏包含：

- LoomQ 标识；
- 当前实验名称；
- 当前状态摘要；
- 帮助入口；
- 显示与无障碍设置；
- 新建或重置实验入口。

示例：

```text
LoomQ    Bell 态：Z 基测量相关性    已通过验证    帮助  显示设置
```

### 8.2 状态摘要

状态摘要使用文字，不只使用图标：

- 尚未建立实验；
- 正在构建；
- 有待修复；
- 已通过验证；
- 可运行；
- 正在运行；
- 等待真实后端；
- 已完成；
- 运行失败。

### 8.3 显示设置

显示设置至少包括：

- 浅色 / 深色；
- 默认字号调整；
- 减少动态效果；
- 简明 / 详细 / 数学说明偏好；
- 电路文本描述开关；
- 高对比模式。

---

## 9. 路径与入口标签区

### 9.1 作用

标签不是页面导航，而是“如何开始或重新组织当前实验”的入口。

任何标签被选择后，主界面结构不变。系统只更新：

- 当前实验目标；
- 初始电路或导入内容；
- Agent 的第一条引导；
- 推荐的下一步；
- 结果区的初始状态。

### 9.2 默认标签

建议首版提供：

- **制备 Bell 态**
- **制备 3 比特 GHZ 态**
- **导入并检查 QASM**
- **用自然语言描述**
- **为当前电路选择后端**
- **自由实验**

### 9.3 标签外观

- 使用文字标签或小型卡片，不使用大型首页卡片墙；
- 当前标签有明确边框、底色和“当前路径”文字；
- 标签支持键盘方向键切换；
- 标签名称使用正式目标，不使用故事化名称；
- 每个标签可附一行短说明，但不应占据主界面大量空间。

示例：

```text
[制备 Bell 态]
从 |00⟩ 出发，构造 |Φ+⟩ 并观察 Z 基测量分布
```

### 9.4 路径阶段

进入预设路径后，可在标签区下方显示轻量阶段提示：

```text
目标  →  构建  →  验证  →  执行  →  解释  →  探索
```

它只显示当前位置和整体方向，不形成“关卡得分”。

用户可以点击已完成阶段回看，也可以选择“跳过引导，直接操作”。

## 10. 当前实验目标区

### 10.1 作用

实验目标是所有生成、修复、验证和后端选择的语义依据。它必须始终可见，不能只存在于聊天历史中。

### 10.2 展示内容

目标区默认显示：

- 实验动作；
- 目标态或目标现象；
- 测量方式；
- 必要约束；
- 当前目标来源。

Bell 示例：

> **当前实验目标**  
> 从初始态 \(|00\rangle\) 出发，制备 Bell 态  
> \[
> |\Phi^+\rangle=\frac{|00\rangle+|11\rangle}{\sqrt 2}
> \]
> 随后在 Z 基测量两个量子比特。

自然语言生成示例：

> **当前实验目标**  
> 制备 3 比特 GHZ 态，并将三个量子比特全部测量。  
> 来源：用户自然语言描述。

### 10.3 目标编辑

用户点击“编辑目标”后，可直接修改：

- 量子比特数量；
- 目标态或预期分布；
- 是否测量；
- 测量对象；
- 运行偏好。

修改目标后，系统不应立刻无提示覆盖当前电路。Agent 先说明：

> 目标已从 2 比特 Bell 态改为 3 比特 GHZ 态。当前电路不再完整满足新目标。是否在现有电路基础上扩展？

操作：

- 在现有电路上修改；
- 生成新的电路；
- 仅更新目标，稍后手动修改；
- 取消。

### 10.4 目标不明确时

导入 QASM 时，如果用户未声明目标，目标区显示：

> 当前只知道“代码需要可执行”，尚未声明预期量子态或测量结果。

Agent 可以询问：

- 只修复语法和结构；
- 同时检查是否实现 Bell 态；
- 自己描述预期目标。

系统不得在目标未知时擅自假定电路意图。

## 11. Agent 引导区

### 11.1 角色

Agent 是认知导航，不是普通聊天机器人。它负责：

- 说明当前状态；
- 推荐一个明确的下一步；
- 回答与当前实验有关的问题；
- 在用户需要时展开专业解释；
- 将用户的自然语言意图转化为目标和电路；
- 解释错误与修复；
- 解释后端推荐；
- 解释运行结果和结论边界。

### 11.2 固定结构

Agent 每次响应尽量包含三个层次：

1. **当前结论或说明**
2. **推荐的下一步**
3. **可选追问或替代动作**

示例：

> 对 \(q_0\) 应用 H 门后，联合状态将从 \(|00\rangle\) 变为  
> \[
> \frac{|00\rangle+|10\rangle}{\sqrt 2}.
> \]
> 下一步需要用 \(q_0\) 控制 \(q_1\) 执行 CX 门，才能得到目标 Bell 态。
>
> **推荐下一步：** 添加 CX 门。

动作标签：

```text
[添加 CX 门] [解释 CX 的作用] [查看状态推导] [我自己操作]
```

### 11.3 输出长度

Agent 默认只展示与当前步骤直接相关的内容。

较长内容折叠为：

- 查看详细说明；
- 查看数学推导；
- 查看术语定义；
- 查看当前结论的限制。

### 11.4 讲解模式

用户可以在任意时刻选择：

- **简明**：正式术语 + 当前步骤的一句话解释；
- **详细**：增加状态变化、设计理由和常见误解；
- **数学**：增加态矢表达和必要推导。

三种模式改变信息层级，不改变结论。

### 11.5 自由对话

“自由提问”入口始终存在，但默认不展开完整聊天历史。

用户可以询问：

- 为什么需要这一步？
- 删除这个门会怎样？
- 当前结果是否证明了纠缠？
- 模拟器和真机结果为什么不同？
- QASM 中这一行对应电路的哪里？
- 还有哪些后端可用？

自由问答后，Agent 必须能够回到当前路径，并再次提供“继续实验”的主动作。

### 11.6 主动干预规则

Agent 只在以下情况下主动出现新提示：

- 当前操作使电路无效；
- 用户目标与电路明显不一致；
- 用户准备运行但缺少测量；
- 用户选择的后端不满足明确约束；
- 运行失败；
- 用户长时间停留且尚未选择下一步；
- 用户主动请求帮助。

Agent 不应在每次鼠标移动、每次选择门或每次代码输入时输出长篇解释。

## 12. 图形化量子电路区

### 12.1 视觉地位

图形化电路是主界面的视觉中心，也是所有路径共享的主要操作对象。

### 12.2 基本内容

电路区显示：

- 量子比特线路；
- 经典比特或测量结果线路；
- 量子门；
- 控制关系；
- 测量操作；
- 操作顺序；
- 当前选中对象；
- 当前验证状态。

### 12.3 门的呈现

门保留标准缩写：

- H
- X
- S
- T
- RY
- RZ
- CX
- SWAP
- CCX

首次选中或聚焦时显示：

```text
H
Hadamard 门
当前作用：使 q0 从 |0⟩ 变为等幅叠加态
```

不把 H 门重命名为“制造随机”“制造混合”或其他可能混淆量子态与经典概率的说法。

### 12.4 操作方式

所有操作至少支持两种方式：

#### 指针操作

- 从门栏选择量子门；
- 点击线路位置添加；
- 拖动调整位置；
- 选择后删除或修改参数；
- 点击控制门后选择控制与目标量子比特。

#### 非拖拽操作

- 键盘聚焦线路和时间位置；
- 通过“添加操作”菜单选择门；
- 使用表单指定作用对象和参数；
- 使用上下左右键移动选中门；
- 使用删除键或明确按钮移除门。

### 12.5 选择与联动

选中某个门时：

- 电路中的门高亮；
- QASM 中对应代码行高亮；
- Agent 显示该门在当前实验中的作用；
- 验证区显示该门是否引发错误或目标偏离；
- 屏幕阅读器读出门名、位置、作用对象和参数。

### 12.6 电路变化

Agent 或用户执行操作时，电路更新应清楚但克制：

- 新门淡入或轮廓强调；
- 被删除的门短暂标示后消失；
- 修改前后可通过“查看差异”对比；
- 减少动态效果开启后，全部改为无动画即时更新。

### 12.7 空状态

尚未建立电路时，中央不显示复杂工具栏，而显示：

> 当前实验还没有电路。  
> 选择上方预设目标，或直接描述你想完成的实验。

主动作：

```text
[制备 Bell 态] [用自然语言描述] [导入 QASM]
```

## 13. QASM 与诊断侧栏

### 13.1 定位

QASM 是当前电路的正式文本表示，不是隐藏的“高级功能”，但默认视觉权重低于图形电路。

侧栏标题：

> OpenQASM 2.0

副标题：

> 与当前图形电路同步

### 13.2 默认状态

第一次进入预设路径时，侧栏可以显示代码但不自动获得输入焦点。Agent 每完成一步，新增代码行短暂高亮。

用户可以选择：

- 仅查看；
- 直接编辑；
- 展开至更大宽度；
- 隐藏侧栏；
- 查看代码与电路的对应关系。

### 13.3 同步关系

- 点击电路门，高亮对应代码；
- 点击代码行，高亮对应电路操作；
- 图形化编辑成功后更新代码；
- 代码有效时更新图形电路；
- 代码暂时无效时，保留最后一个有效电路，不让中央画布突然消失。

无效代码状态下，侧栏顶部显示：

> 当前文本无法完整解析。中央仍显示最近一次有效电路。

### 13.4 诊断信息

错误信息必须包含：

- 错误位置；
- 错误类型；
- 对当前实验的影响；
- 建议修复；
- 修复是否改变用户目标。

示例：

> **第 5 行：门名无效**  
> OpenQASM 2.0 的标准门名区分大小写，`CX` 应写作 `cx`。  
> 此修改只修复语法，不改变 Bell 态制备目标。

操作：

```text
[应用修复] [查看差异] [自行修改]
```

### 13.5 修复差异

“查看差异”使用并排或行级对比：

```diff
- CX q[0] q[1]
+ cx q[0], q[1];
```

差异视图同时提供文字说明，不只使用红绿颜色。

## 14. 验证、后端与结果区

下方区域使用固定标签：

- **验证**
- **后端**
- **结果**
- **解释**

标签切换不改变整个页面，只改变下方面板内容。

### 14.1 验证标签

验证分为三个层次：

#### 语法验证

回答：

- QASM 是否可解析；
- 指令、分号、参数和寄存器声明是否有效。

#### 结构验证

回答：

- 量子比特索引是否越界；
- 门参数是否完整；
- 测量与经典寄存器是否匹配；
- 当前门集合是否符合支持范围。

#### 目标验证

回答：

- 当前电路是否实现了用户声明的目标；
- 是否存在语法正确但语义偏离的情况；
- 当前验证使用了什么条件；
- 验证结论的适用范围。

状态示例：

```text
语法       通过
结构       通过
目标一致性 通过

当前电路可用于制备目标 Bell 态，并在 Z 基测量两个量子比特。
```

或：

```text
语法       通过
结构       通过
目标一致性 未通过

原因：当前电路缺少 q0 → q1 的 CX 门，因此不会得到目标 |Φ+⟩。
```

### 14.2 后端标签

后端区围绕当前实验显示：

- 当前电路摘要；
- 用户运行约束；
- 推荐后端；
- 推荐理由；
- 不推荐或被排除的后端及原因；
- 模拟器 / 真机标识；
- 规范后端标识；
- 用户覆盖选择。

约束选项使用清晰标签：

```text
运行类型： [本地模拟器] [真实量子芯片] [均可]
等待偏好： [零排队] [可接受等待]
成本偏好： [免费优先] [不限]
其他：     [优先兼容当前电路] [优先真实噪声数据]
```

推荐卡示例：

> **推荐：AWS Braket LocalSimulator**  
> 规范标识：`braket_local_simulator`
>
> 当前电路使用 15 个量子比特，用户要求零排队。该后端为本地模拟器，可立即运行，并满足当前规模要求。
>
> **未选择真实量子后端的原因：** 真机通常无法保证零排队。

操作：

```text
[使用推荐后端运行] [比较其他后端] [修改约束]
```

### 14.3 结果标签

运行结果首先展示普通用户最需要的三件事：

1. 在哪里运行；
2. 主要测量结果是什么；
3. 是否与目标预期一致。

Bell 示例：

> **运行完成**  
> 后端：本地模拟器  
> 重复次数：1024  
> 主要结果：`00` 与 `11` 占绝大多数，与当前目标的理想 Z 基分布一致。

然后显示柱状图：

```text
00   50.4%   ████████████████████
11   49.6%   ███████████████████▋
01    0.0%
10    0.0%
```

每个图表同时提供：

- 百分比；
- 原始计数；
- 可访问数据表；
- 结果排序方式；
- 位序说明；
- 理想结果对比。

### 14.4 理想结果与实际结果

默认并列显示：

```text
结果    理想概率    本次采样
00      50.0%       50.4%
11      50.0%       49.6%
```

真机结果还需显示：

- 与理想结果的偏差；
- 可能的硬件噪声影响；
- 不把偏差自动归结为用户操作错误；
- 模拟器与真机不可直接等同。

### 14.5 解释标签

解释分为三层：

#### 一句话结论

> 本次 Z 基测量分布与目标 Bell 态的理想分布一致。

#### 证据链

> H 门和 CX 门构造了目标电路。  
> 运行结果主要集中在 `00` 和 `11`。  
> 这一分布符合 \(|\Phi^+\rangle\) 在 Z 基下的理想测量预测。

#### 结论边界

> 单一 Z 基的计数分布与目标态一致，但仅凭这一组测量不能独立完成对纠缠的完整实验认证。若要进一步检验，需要增加其他测量设置。

该边界说明应当清晰可见，而不是藏在免责声明中。

## 15. 主要引导路径

### 15.1 路径 A：制备 Bell 态并观察 Z 基测量结果

这是默认黄金路径，应支持零基础用户在约五分钟内完成。

### 阶段 1：建立目标

用户选择标签“制备 Bell 态”。

目标区显示：

> 从 \(|00\rangle\) 出发，制备  
> \[
> |\Phi^+\rangle=\frac{|00\rangle+|11\rangle}{\sqrt 2}
> \]
> 并在 Z 基测量两个量子比特。

Agent：

> 当前实验将使用两个量子比特。我们会先对 \(q_0\) 应用 H 门，再以 \(q_0\) 为控制比特、\(q_1\) 为目标比特应用 CX 门，最后测量两个量子比特。

动作：

```text
[开始构建] [先解释目标态] [直接生成完整电路]
```

### 阶段 2：添加 H 门

用户选择“开始构建”。

Agent：

> 初始状态是 \(|00\rangle\)。先对 \(q_0\) 应用 H 门，使第一个量子比特进入等幅叠加。联合状态将变为  
> \[
> \frac{|00\rangle+|10\rangle}{\sqrt 2}.
> \]

动作：

```text
[添加 H 门] [查看 H 门定义] [我自己添加]
```

添加后：

- 电路出现 H 门；
- QASM 新增对应代码行；
- H 门与代码行同时高亮；
- 阶段提示从“目标”移动至“构建”。

### 阶段 3：添加 CX 门

Agent：

> 现在以 \(q_0\) 为控制比特、\(q_1\) 为目标比特应用 CX 门。该操作将当前状态转化为目标 Bell 态 \(|\Phi^+\rangle\)。

动作：

```text
[添加 CX 门] [查看状态变化] [改变控制与目标试试看]
```

用户若选择反向控制，系统允许操作，但验证区提示：

> 当前电路与预设目标不一致。你可以继续观察这个变体，或恢复推荐电路。

### 阶段 4：添加测量

Agent：

> 为了得到计数分布，需要在 Z 基测量两个量子比特。

动作：

```text
[测量全部量子比特] [只测量 q0] [先不测量]
```

若用户只测量一个量子比特，系统不判定“错误”，而是说明：

> 这仍然是有效实验，但无法直接观察两个测量结果之间的联合分布。

### 阶段 5：预测

在运行前，Agent 提供可跳过的预测：

> 理想情况下，哪类结果会出现？

```text
[00 与 11] [01 与 10] [四种结果近似相等] [直接运行]
```

回答不计分，不显示“错误”。预测与实际不同时显示：

> 本次结果与预测不同。下面从电路状态变化解释原因。

### 阶段 6：验证

系统显示三层验证结果。

Agent：

> 当前电路已通过语法、结构和目标一致性检查，可以运行。

动作：

```text
[在本地模拟器运行] [先查看 QASM] [修改电路]
```

### 阶段 7：运行与结果

结果区显示计数分布、理想对比和结论边界。

Agent：

> 结果主要集中在 `00` 和 `11`，与目标 Bell 态在 Z 基下的理想分布一致。有限重复次数可能使两者不会恰好各占 50%。

### 阶段 8：继续探索

提供有限、相关的下一步：

```text
[删除 CX 门并比较]
[增加第三个量子比特]
[改变测量设置]
[尝试真实量子后端]
[自由修改]
```

### 15.2 路径 B：从自然语言生成电路

### 入口

用户选择“用自然语言描述”。

输入区示例：

> 描述你希望制备、测量或观察的量子实验。  
> 例如：“生成一个 3 比特 GHZ 态，并测量全部量子比特。”

### 明确目标

对于信息充分的请求，Agent 直接生成结构化目标：

> 我将目标理解为：从 \(|000\rangle\) 出发，制备  
> \[
> (|000\rangle+|111\rangle)/\sqrt 2
> \]
> 并在 Z 基测量三个量子比特。

操作：

```text
[确认并生成电路] [修改目标] [查看计划]
```

对于含混请求，Agent 只询问影响电路的必要问题。例如：

> 你希望测量全部三个量子比特，还是只制备状态而不测量？

不询问与当前任务无关的偏好。

### 生成后

生成完成后：

- 目标区更新；
- 电路区显示完整电路；
- QASM 侧栏同步；
- 验证自动运行；
- Agent 解释整体结构；
- 用户可选择逐步回看每个操作。

Agent 不只返回代码。默认顺序是：

1. 目标确认；
2. 电路可视化；
3. 验证结果；
4. QASM；
5. 运行建议。

### 生成失败或验证不通过

Agent 应明确：

> 已生成候选电路，但目标验证未通过，因此尚未将它标记为可运行方案。

提供：

```text
[自动重试] [查看问题] [保留并手动修改]
```

### 15.3 路径 C：导入并修复已有 QASM

### 入口

用户选择“导入并检查 QASM”。

侧栏扩大，提供：

- 粘贴代码；
- 导入文本；
- 使用示例错误代码。

目标区要求用户选择：

```text
[只检查是否可执行]
[检查是否实现 Bell 态]
[检查是否实现 GHZ 态]
[自己描述目标]
```

### 初次解析

如果代码部分可解析：

- 中央显示可恢复的电路部分；
- 无法解析的位置显示占位标记；
- 保留最后有效状态；
- 诊断按严重程度排序。

如果完全无法解析，中央显示文本描述：

> 当前代码尚不能形成有效电路。修复寄存器声明后可继续显示。

### 错误说明

每个错误以独立卡片呈现：

```text
错误 1 / 2
第 4 行：使用了未声明的量子寄存器 q

影响：
当前代码无法运行，也无法建立图形电路。

建议：
在门操作前声明量子寄存器。
```

操作：

```text
[应用此修复] [应用全部安全修复] [查看修改差异]
```

### 保持用户目标

Agent 必须区分：

- 不改变意图的语法修复；
- 可能改变电路语义的结构修复；
- 为实现声明目标而提出的语义修复。

示例：

> 将 `CX` 改为 `cx` 只修复语法。  
> 添加缺失的 CX 门会改变电路，但这是实现用户声明 Bell 态目标所必需的。应用前需要用户确认。

### 修复完成

系统重新运行三层验证，显示：

> 代码已可解析，结构有效，并通过 Bell 态目标验证。

主动作：

```text
[运行修复后的电路] [比较修复前后] [继续编辑]
```

### 15.4 路径 D：为当前电路选择后端

### 入口方式

后端选择可以通过两种方式进入：

- 点击上方“为当前电路选择后端”标签；
- 在验证通过后点击“运行”。

两种方式均打开下方同一个“后端”面板，不切换页面。

### 读取当前实验

系统先展示：

```text
当前电路
量子比特：15
主要门：H、CX、RZ
测量：全部量子比特
目标：立即获得结果
```

### 获取约束

Agent 只询问尚未明确的关键约束：

- 是否必须是真实量子芯片；
- 是否接受排队；
- 是否要求免费；
- 是否需要当前环境立即可运行。

也允许用户选择：

> 我不确定，请根据当前实验推荐。

### 推荐结果

推荐必须包含：

- 规范后端标识；
- 是否模拟器；
- 是否满足规模；
- 是否满足排队与成本偏好；
- 为什么未选择其他候选；
- 结果应如何解释。

用户可：

```text
[采用推荐] [查看全部候选] [修改约束] [手动选择]
```

### 用户覆盖推荐

如果用户坚持选择不满足约束的后端，界面不阻止，但明确提示：

> 该选择与“零排队”约束冲突。继续后可能进入等待队列。

操作：

```text
[仍然继续] [返回推荐后端]
```

### 15.5 路径 E：自由实验

### 入口

用户选择“自由实验”。

界面仍保持同一结构，但 Agent 降低主动程度：

> 你可以直接添加量子门、编辑 QASM 或描述下一步。验证会持续显示当前电路状态。

### 用户自由度

允许：

- 从空白电路开始；
- 修改量子比特数量；
- 添加或删除白名单门；
- 编辑参数；
- 增加测量；
- 直接运行；
- 随时声明或修改实验目标；
- 请求 Agent 解释当前电路；
- 请求 Agent 从当前电路继续生成。

### 恢复引导

始终显示：

```text
[请根据当前电路建议下一步]
[为当前电路建立实验目标]
[回到 Bell 态引导]
```

## 16. 结果可视化规范

### 16.1 信息顺序

结果必须按照以下顺序呈现：

1. 运行是否完成；
2. 后端类型；
3. 主要测量结果；
4. 与目标预期是否一致；
5. 图表与详细数据；
6. 解释；
7. 结论边界；
8. 下一步。

### 16.2 图表要求

柱状图应：

- 默认按概率或位串排序；
- 同时显示位串、百分比和计数；
- 提供数据表；
- 不仅依赖颜色；
- 明确经典位串顺序；
- 支持放大；
- 屏幕阅读器可逐项读取。

### 16.3 模拟器结果

必须说明：

- 这是模拟执行；
- 当前分布来自有限 shots；
- 与理想概率的微小偏差可能来自采样波动；
- 不将模拟器结果描述为真实硬件实验。

### 16.4 真机结果

必须说明：

- 这是实际量子硬件返回；
- 噪声可能引入非理想结果；
- 与理想分布偏离不等于程序一定错误；
- 可比较模拟器与真机结果；
- 后端、任务标识和时间信息可在技术详情中查看。

### 16.5 空结果与异常结果

若没有测量：

> 当前电路没有测量操作，因此不会产生 counts 分布。可以添加测量后再次运行。

若结果字段不完整：

> 后端返回了结果，但部分信息无法按统一格式显示。原始结果仍可查看。

若运行失败：

- 说明失败发生在验证、提交、排队或执行哪个阶段；
- 保留当前电路和目标；
- 提供明确恢复动作；
- 不把用户送回首页。

## 17. 技术严谨性与内容规范

### 17.1 术语规范

优先使用：

- 量子比特；
- 量子态；
- 叠加态；
- Bell 态；
- GHZ 态；
- H 门；
- CX 门；
- 控制比特；
- 目标比特；
- Z 基测量；
- 理想分布；
- 采样分布；
- 模拟器；
- 真实量子后端。

避免使用：

- 两个量子一起行动；
- 量子互相知道；
- 量子共享秘密；
- 测量“偷看”量子；
- H 门制造普通随机；
- 纠缠意味着信息瞬间传递；
- 一次 `00/11` 分布就“证明纠缠”。

### 17.2 解释层级

每个概念可以分三层：

#### 操作层

> 对 \(q_0\) 应用 H 门。

#### 当前语境层

> 该操作把 \(|0\rangle\) 转化为等幅叠加态。

#### 数学层

> \[
> H|0\rangle=(|0\rangle+|1\rangle)/\sqrt 2.
> \]

用户可逐层展开。

### 17.3 证据边界

Agent 在解释结果时必须区分：

- 电路设计目标；
- 理想理论预测；
- 模拟采样结果；
- 真机观测结果；
- 当前结果能否唯一支持某个物理结论。

### 17.4 不确定性表达

当系统不能确定用户意图或结果原因时，使用：

- 当前信息不足以判断；
- 这是一种可能解释；
- 需要增加以下验证；
- 可以先检查语法，再检查目标语义；
- 该偏差可能来自采样或硬件噪声，不能仅凭当前结果区分。

不得用肯定语气填补缺失信息。

## 18. 无障碍与包容性设计

### 18.1 键盘操作

所有核心功能必须可通过键盘完成：

- 切换路径标签；
- 编辑目标；
- 聚焦电路线路；
- 添加、移动、修改和删除门；
- 切换 QASM；
- 应用修复；
- 选择后端约束；
- 运行；
- 阅读结果；
- 展开 Agent 说明。

焦点顺序应与视觉顺序一致。

### 18.2 屏幕阅读器

每个电路应有完整文本描述，例如：

> 电路包含两个量子比特。  
> 第一步：对 q0 应用 H 门。  
> 第二步：以 q0 为控制比特、q1 为目标比特应用 CX 门。  
> 第三步：测量 q0 到 c0，测量 q1 到 c1。

电路变化后，使用简短状态通知：

> 已在 q0 的第一步添加 H 门。

错误、运行状态和结果更新需可被主动读出，但不得频繁打断用户输入。

### 18.3 非颜色编码

成功、警告、错误、当前选中状态均需同时使用：

- 图标；
- 文字；
- 边框或形状；
- 必要时的颜色。

### 18.4 动态效果

提供“减少动态效果”。

开启后：

- 禁止门飞入、背景粒子或大幅位移；
- 只保留即时状态变化；
- 运行进度使用数字和文本；
- 不使用闪烁。

### 18.5 认知可访问性

- 页面结构始终稳定；
- 每个阶段只有一个明确主动作；
- 次要动作折叠或降权；
- Agent 不连续输出多段长文本；
- 用户可以暂停引导；
- 用户可以回看已完成步骤；
- 错误不会清空现有工作；
- 所有自动修改都可预览和撤销。

### 18.6 语言与身份包容性

- 不假定用户具有理工背景；
- 不使用“这个很简单”“显然”“基础常识”等评价；
- 不因用户选择“我不知道”降低体验；
- 不把技术能力和用户价值绑定；
- 错误反馈描述系统状态，不评价用户。

推荐：

> 当前代码缺少寄存器声明，因此无法解析。

避免：

> 你忘记了最基本的寄存器声明。

## 19. 关键组件规范

### 19.1 主动作按钮

每个阶段只突出一个主动作，例如：

- 添加 H 门；

### 19.2 行动标签

- 包含一个推荐动作；
- 包含一个解释入口；
- 必要时包含“自己操作”；

### 19.3 状态徽标

统一状态词：

- 待验证；
- 已通过；
- 有警告；
- 有错误；
- 正在运行；
- 等待中；
- 已完成；

- 点击“详情”；

### 19.5 撤销与历史

## 20. 页面状态

### 20.1 初始状态

- 无当前电路；
- 路径标签可见；
- Agent 给出三个明确入口；
- QASM 和结果区处于空状态；
- 不显示大量门工具和参数。

### 20.2 正在生成

- 保留用户目标；
- 显示“正在建立候选电路”；
- 用户可取消；
- 不显示虚假的完成进度；
- 生成后必须进入验证状态，不直接宣称成功。

### 20.3 有效但尚未验证

- 电路和 QASM 可编辑；
- 运行按钮降权；
- 主动作是“验证电路”。

### 20.4 验证失败

- 目标和最后有效电路保留；
- 错误定位明确；
- 可逐项修复；
- 可继续自由编辑；
- 不弹出阻断全屏对话框。

### 20.5 可运行

- 显示验证通过；
- 主动作是运行；
- 用户可在运行前修改后端和 shots；
- 任何修改后重新显示验证状态。

### 20.6 正在运行

本地模拟器：

> 正在执行 1024 次测量采样。

真实后端：

> 任务已提交至真实量子后端。当前状态：等待执行。

用户可以继续阅读电路和讲解，但避免在任务进行中无提示修改与该任务关联的记录。

### 20.7 运行完成

- 自动打开结果标签；
- 电路仍然可见；
- Agent 给出一句结论；
- 提供比较、修改和再次运行入口。

### 20.8 Agent 不可用

- 当前电路、QASM、验证和运行能力不消失；
- 显示“Agent 暂时不可用”；
- 提供预设路径中的固定步骤提示；
- 用户可继续手动操作；
- 不清空对话和实验状态。

### 20.9 后端不可用

- 说明具体后端不可用；
- 保留选择约束；
- 推荐可用替代项；
- 区分“暂时不可用”和“不满足当前电路”。

## 25. 设计验收标准

### 25.1 整体体验

- 用户进入后不面对空白聊天框或复杂仪表盘；
- 用户始终知道当前实验目标；
- 电路、QASM、验证与结果指向同一实验；
- 切换路径不会改变整体布局；
- 用户可以随时偏离引导并恢复；
- 不需要先理解 QASM 才能完成实验。

### 25.2 严谨性

- 正式术语首次出现时有清晰定义；
- 不使用误导性的拟人化比喻；
- 不把有限采样等同于精确理论概率；
- 不把模拟器结果描述为真机结果；
- 不把单一 Z 基分布描述为完整纠缠认证；
- Agent 明确区分确定结论、推断和未知信息。

### 25.3 三项 L2 任务

- 自然语言生成后自动进入可视化和验证；
- 修复建议区分语法修复与语义修改；
- 后端推荐基于当前电路和用户约束；
- 推荐结果包含规范标识和理由；
- 三项能力均可在同一页面自然调用。

### 25.4 无障碍

- 仅用键盘可完成三项现场任务；
- 屏幕阅读器可获得完整电路描述；
- 图表有数据表替代；
- 状态不依赖颜色；
- 动画可关闭；
- 自动修改可预览、撤销；
- 焦点不会因 Agent 更新或结果出现而无故跳转。

### 25.5 五分钟黄金路径

首次用户应能在约五分钟内：

- 选择 Bell 态；
- 建立目标；
- 构建或确认电路；
- 验证；
- 运行；
- 读取结果；
- 获得严格但可理解的解释。

## 26. 核心体验总结

LoomQ L2 的界面不应把零基础用户带入一个缩水版专业工作台，也不应通过故事包装掩盖技术内容。它应当提供一个稳定、可探索、可验证的实验空间。

用户在同一场景中经历：

```text
选择或描述目标
        ↓
建立图形电路与 QASM
        ↓
检查语法、结构和目标一致性
        ↓
根据约束选择后端
        ↓
运行并可视化结果
        ↓
理解证据与结论边界
        ↓
修改实验并继续探索
```

Agent 不替代实验对象，也不垄断界面。它负责在恰当的时刻指出：

- 我们要实现什么；
- 当前电路发生了什么；
- 为什么需要下一步；
- 哪里出现了问题；
- 哪个后端满足约束；
- 结果说明了什么；
- 下一次值得改变什么。

最终体验应当让用户产生的不是“我绕过了量子知识也成功点了运行”，而是：

> 我在没有前置背景的情况下完成了一次量子实验，并且知道目标、电路、执行环境和结果之间如何相互关联。
