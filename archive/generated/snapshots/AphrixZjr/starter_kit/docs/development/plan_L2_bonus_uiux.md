# LoomQ L2 + Bonus 新手引导与视觉叙事开发计划

## 1. 目标与交付边界

本计划依据 [`l2_UI_UX_design_spec.md`](l2_UI_UX_design_spec.md) 落地 L2 单场景交互入口，并争取题面“卓越的新手引导与视觉叙事”Bonus 的 4 分主观分。首版服务于零量子基础用户，目标是在约五分钟内完成一次 Bell 态实验，并理解“目标—电路—证据”之间的关系。

Bonus 的四项交付物与评分证据一一对应：

| Bonus 证据项 | 产品交付 | 可验收证据 |
|---|---|---|
| 零基础首次运行指南 | Bell 态八阶段黄金路径 | 首次进入至运行完成的连续录屏、步骤截图、可复现说明 |
| 量子概念解释 | 操作层、语境层、数学层三级解释 | H、CX、Bell 态、测量和结论边界的界面截图与文案清单 |
| 结果可视化 | 本地模拟 counts 柱状图、理想/实际对比、数据表；预留真机结果视图 | 本地模拟结果截图、键盘与无障碍测试记录；真机视图使用固定 fixture 验证 |
| 错误恢复或无障碍引导 | QASM 诊断/差异/撤销，以及完整键盘路径 | 错误恢复录屏、无障碍检查报告、键盘任务记录 |

本计划不改写 L2 客观分的 `agent_chat(prompt: str) -> str` 契约，不把 UI 状态塞入该黑盒接口，也不改变 L1/L3/量子 RISC-V Bonus 的评分路径。现有 `loomq_l2.py`、L1 parser/IR、后端能力表和执行适配器作为领域能力复用；Web 层通过独立的应用服务将其组织为会话化实验体验。

评测环境不保证真实量子后端、网络或凭证，因此本地模拟器是唯一阻断性运行路径和默认视觉叙事。界面保留真实后端的选择说明、排队状态与结果视图数据契约，但首版只要求使用脱敏固定 fixture 验证其渲染和降级行为；不要求成功提交真机任务，不把真机截图、任务 ID 或现场连通性列为完成条件。

首版不建设复杂项目管理、多页面云控制台或高级电路优化器；不以动画、拟人化表达替代正式量子概念。

## 2. 成功指标与发布门槛

### 核心体验指标

- Bell 黄金路径由固定端到端脚本从首次进入运行到结果解释；全程不注入隐藏状态、不调用调试接口，交互动作不超过 20 次，脚本墙钟时间不超过 60 秒。
- 黄金路径的 8 个阶段均有确定性断言：目标、H、CX、测量、预测、三层验证、运行结果和继续探索依次可见，且每阶段恰有一个视觉主动作。
- 结果页必须同时出现实验目标、H/CX 的作用、本地模拟器标识、主要 `00/11` 分布以及“单一 Z 基测量不能独立认证纠缠”的结论边界；使用文案快照和 DOM 查询固定。
- Bell 实验、QASM 修复、后端选择三个端到端脚本均在同一路由和同一 `ExperimentSession` 内完成；不得通过页面重载恢复状态。
- 偏离引导、Agent 不可用和后端不可用分别有故障注入用例；断言目标、电路和 QASM 不丢失，且至少保留一个可执行恢复动作。

### 工程与无障碍门槛

- 从干净环境用 README 中一条命令启动，不依赖真实凭证完成本地黄金路径。
- 桌面端首屏无横向滚动；核心布局稳定，生成、验证和运行不会引起焦点跳转。
- 仅用键盘可完成三项现场任务；焦点可见且顺序与视觉顺序一致。
- 电路具有等价文本描述；图表具有数据表；状态不只依赖颜色；减少动态效果设置有效。
- 自动生成、修复、目标修改和图形编辑均可预览或撤销。
- 自动化测试、端到端任务脚本、无障碍扫描、视觉回归和证据完整性检查全部通过后才进入发布候选。

## 3. 实现架构

### 前端边界

新增独立 `web/` 应用，采用成熟的可访问组件和图表基础设施；具体框架在执行块 0 通过仓库兼容性评审锁定。前端按领域拆分，而不是按页面拆分：

```text
ExperimentShell
├─ GlobalHeader + PathTabs
├─ ExperimentGoal
├─ GuideCard
├─ CircuitWorkspace
│  ├─ CircuitCanvas
│  └─ QasmDiagnostics
└─ EvidenceWorkspace
   ├─ ValidationPanel
   ├─ BackendPanel
   ├─ ResultsPanel
   └─ ExplanationPanel
```

全局状态只围绕一个 `ExperimentSession`：

```text
session_id
goal + goal_revision
circuit_ir + qasm + circuit_revision
guide_path + guide_stage + guide_mode
validation + backend_constraints + backend_selection
run_snapshot + result
undo_history + accessibility_preferences
```

所有异步响应携带 `session_id` 和对应 revision；旧响应不得覆盖用户的新编辑。运行任务保存不可变快照，用户后续修改不篡改历史结果。

### 后端应用服务

为 Web 提供窄接口：

- `POST /experiments`：建立预设、自然语言、导入 QASM 或自由实验；
- `PATCH /experiments/{id}/goal`：更新结构化目标；
- `PATCH /experiments/{id}/circuit`：提交图形操作或 QASM，并返回同步 IR；
- `POST /experiments/{id}/validate`：返回语法、结构、目标三层验证；
- `POST /experiments/{id}/guide`：按当前快照返回说明、主动作和可选动作；
- `POST /experiments/{id}/backend-recommendations`：基于电路与约束返回排序和排除理由；
- `POST /experiments/{id}/runs` 与 `GET /runs/{id}`：提交和查询运行；
- `POST /experiments/{id}/repairs`：生成修复建议和可审阅 diff，不直接覆盖用户代码。

接口返回结构化数据，前端不解析自由文本来决定权限、状态或下一动作。Agent 负责目标理解和解释，parser、验证器、能力表与运行适配器负责确定性事实。模型输出在进入实验状态前必须经过现有本地验证。

### 状态机与叙事线

页面主状态统一为：

```text
initial → generating → draft → validating
        → invalid → repairing → draft
        → runnable → running → completed
```

Agent 不使用无限聊天流作为主叙事，而使用固定“指导卡”：当前发生了什么、为什么、一个主动作、2—4 个次动作。视觉叙事由同一对象的连续变化构成：目标明确 → 门逐步出现 → QASM 同步 → 三层验证点亮 → 结果成为证据 → 提出下一次可比较的变体。

## 4. 执行规则

每个执行块遵循“实现 → 定向测试 → 脚本化验收 → 完整回归 → 证据归档 → 阶段提交”。未满足完成检查不得进入下一块。每次提交只包含当前执行块，避免混入 L1、L3 或量子 RISC-V Bonus 修改。视觉走查可以发现问题，但不作为发布门槛的唯一依据。

每个新增交互都必须同时定义：正常状态、空状态、加载状态、失败状态、键盘行为、读屏名称、撤销/恢复行为和埋点事件。视觉稿不能替代可运行验收；录屏不能替代自动化测试。

## 5. 分阶段执行计划

### 执行块 0：锁定技术方案、用户旅程和基线

1. 盘点 Python 领域能力，确认 parser/IR、验证、后端能力表、模拟执行和 `agent_chat` 的复用边界。
2. 建立 ADR，锁定 Web 技术栈、Python 服务框架、状态管理、图表与数学排版方案，以及本地一键启动命令。
3. 将设计文档转为可追踪需求矩阵：章节、组件、状态、验收用例和 Bonus 证据路径逐项对应。
4. 制作桌面主界面的低保真可点击原型，覆盖初始、可运行、验证失败和运行完成四种状态。
5. 为四种状态建立界面启发式检查表：唯一主动作、目标持续可见、无空白聊天入口、术语首次定义、证据边界可见；每项必须映射到组件断言或视觉快照。
6. 建立 Web 单元、组件、端到端、视觉回归和无障碍测试骨架；测试不得依赖网络或真实凭证。

完成检查：技术方案能在干净环境启动；黄金路径没有页面跳转；需求矩阵覆盖 Bonus 四项且每项都有证据计划。

阶段提交：`Plan the L2 guided experiment experience`

### 执行块 1：建立单场景骨架与统一实验状态

1. 实现全局顶栏、路径标签、实验目标、指导卡、电路/QASM 工作区和证据工作区的稳定布局。
2. 实现 `ExperimentSession`、revision 防竞态、关键节点历史与撤销栈。
3. 实现初始、生成中、草稿、验证失败、可运行、运行中、完成、Agent 不可用和后端不可用状态。
4. 首次进入只突出“从 Bell 态开始”，将自然语言与导入 QASM 作为次入口；高级门库和原始数据默认折叠。
5. 建立响应式策略：首版以桌面演示为主；窄屏保持语义顺序，不隐藏核心动作。

测试：状态机转换、旧 revision 丢弃、刷新恢复、撤销/重做、错误不清空实验、布局快照和全键盘焦点顺序。

完成检查：用户始终能看见当前目标、当前阶段和唯一主动作；切换路径只更新实验内容，不替换整体布局。

阶段提交：`Build the single-scene L2 workspace`

### 执行块 2：实现 Bell 态五分钟黄金路径

1. 按设计文档实现建立目标、添加 H、添加 CX、添加测量、预测、验证、运行、继续探索八阶段。
2. 每步只突出一个主动作，并提供解释、自己操作、跳过/回看；预测不计分、不显示答错。
3. H/CX/测量加入时同步更新电路、QASM、文本电路描述和阶段状态；统一高亮当前门、代码行与讲解。
4. 允许反向 CX 或只测一个量子比特等有效偏离，以“与预设目标不一致”或“证据不足”说明，不判定用户失败。
5. 完成后使用事实性总结，并提供删除 CX、扩展 GHZ、改变测量等有限分支；“了解真实后端”作为降权的可选入口，不进入黄金路径。

测试：八阶段端到端、每步跳过与恢复、自主编辑后恢复、偏离目标、Agent 不可用的固定提示降级；记录动作数、路由变化、请求数和墙钟时间预算。

完成检查：黑盒浏览器脚本仅通过可见控件在本地模拟器完成闭环；最终 DOM 同时包含 H、CX、测量分布和结论边界的规定内容，且全部断言通过。

阶段提交：`Guide the first Bell state experiment`

### 执行块 3：实现电路、QASM 与三级解释联动

1. 建立稳定的图形电路渲染：水平线路、明确门名、控制/目标形状、测量映射和位序说明。
2. 支持指针与非拖拽两种编辑方式；键盘用户可选择线路和时间位置、添加、移动、修改或删除门。
3. 以单一 IR 双向同步图形电路和 QASM；解析失败时保留最后有效图形，并标记不可恢复位置。
4. 实现操作层、当前语境层、数学层三级解释，默认简明，可逐层展开；首次出现提供正式术语定义。
5. 建立内容校对清单，禁止拟人化误导、把 H 等同普通随机、把单一 Z 基结果称为纠缠证明。

测试：图形/QASM 往返、选择联动、位序、参数编辑、无效 QASM 的最后有效状态、读屏文本快照和术语文案快照。

完成检查：同一门在图形、代码和讲解中可明确对应；不看图也能通过文本描述理解完整电路。

阶段提交：`Synchronize circuit code and explanations`

### 执行块 4：接入自然语言生成、QASM 修复与后端推荐

1. 自然语言路径先确认结构化目标，再生成候选电路，随后自动验证；生成失败不得直接标记为可运行。
2. QASM 导入路径区分“只检查可执行”与 Bell/GHZ/自定义目标；诊断按严重程度给出位置、影响和建议。
3. 修复分为不改变意图的语法修复、可能改变语义的结构修复和为实现目标的语义修复；后两者必须确认。
4. 所有修复提供逐项/全部安全修复、diff 预览、应用后重验和撤销。
5. 后端推荐读取电路规模与用户约束，展示规范 ID、模拟器/真机、规模、排队、成本、推荐和排除理由；默认推荐必须包含当前环境可立即运行的本地模拟器。真实后端只作为可选候选，缺少网络或凭证时明确标记不可用，不阻断流程。
6. Agent 调用超时或失败时，保留手动电路、QASM、验证和本地运行能力。

测试：GHZ 自然语言示例、含混目标追问、无效模型候选、本地 oracle 拒绝、语法/语义修复确认、后端约束冲突、服务失败降级。

完成检查：三项 L2 能力自然服务于同一个实验对象；模型自由文本不能绕过确定性验证或直接修改状态。

阶段提交：`Connect L2 generation repair and backend guidance`

### 执行块 5：完成结果可视化与科学证据叙事

1. 按“运行状态 → 后端 → 主要结果 → 与目标对比 → 图表/数据 → 解释 → 结论边界 → 下一步”呈现。
2. counts 柱状图同时展示位串、计数和百分比；标明经典位顺序，提供排序、放大和等价数据表。
3. 显示理想概率与有限 shots 的实际采样对比；明确采样波动，不用单次柱高制造确定性叙事。
4. 模拟器和真机预留文字、图标和结构差异，不只靠颜色；真机视图可显示噪声说明、后端 ID、任务 ID 和时间，但使用脱敏 fixture 完成开发验收。
5. 没有测量、结果字段不完整、提交/排队/执行失败分别给出阶段化恢复动作，并保留实验。
6. 结果完成后焦点不自动跳走，以礼貌 live region 通知；用户主动进入结果时再阅读摘要。

测试：本地模拟的确定性与采样结果、位序、空结果、异常结果、数据表一致性、读屏播报和视觉回归；使用固定 fixture 检查模拟/真机视图区分及真机不可用降级，不发起真实远程任务。

完成检查：结果视图按规定顺序包含运行状态、目标一致性、图表、数据表、解释、结论边界和下一步；图表与数据表的位串、计数和百分比逐项一致。

阶段提交：`Tell the experiment story through evidence`

### 执行块 6：无障碍、错误恢复与视觉精修

1. 完成语义区域、标题层级、可见焦点、跳转链接、ARIA 名称、live region 和对话框焦点管理。
2. 为电路编辑、路径标签、QASM 修复、后端选择、运行和结果提供完整键盘操作；发布快捷键帮助。
3. 状态同时使用图标、文字和边框；检查浅色、深色、高对比和常见色觉差异。
4. 实现“减少动态效果”，取消门飞入、背景粒子、闪烁和大位移；默认动画只解释状态变化。
5. 统一纸白/浅灰背景、冷色主强调、稳定电路线条和宽松排版；电路始终为视觉中心，指导卡不演变成长聊天栏。
6. 对自动修改、运行失败、Agent 失败和后端失败做恢复演练，确保目标、电路和上下文不丢失。

测试：自动化无障碍扫描、200% 缩放截图差异、仅键盘三任务脚本、无障碍树快照、live region 文本断言、减少动态效果、对比度和故障注入。屏幕阅读器录制可作为补充证据，但不作为无法自动复现的阻断条件。

完成检查：设计文档 25.4 的全部无障碍条件通过；错误恢复不依赖刷新或重新开始。

阶段提交：`Make L2 accessible and recoverable`

### 执行块 7：客观验收、性能与发布证据

1. 在全新浏览器上下文分别运行 Bell、QASM 修复和后端选择三项黑盒任务；保存动作轨迹、截图、控制台日志、请求摘要、耗时和断言结果。
2. 将黄金路径预算固定为不超过 20 次交互、无路由切换、无页面重载、无控制台错误、无未处理请求失败；CI 墙钟预算为 60 秒，不把自动化执行时间冒充真实用户完成时间。
3. 对科学内容运行静态规则和快照检查：正式术语齐全，本地模拟结果不表述为真机结果，采样不等同理论概率，单一 Z 基结果不表述为纠缠证明。
4. 优先修复任务阻断、科学表述错误、焦点陷阱、数据位序和状态丢失；每项缺陷先增加可复现测试。
5. 检查首屏、图表和数学排版性能；对 Agent、验证和运行采用取消、超时、重试和明确状态，不伪造进度。
6. 在断网、无云凭证的干净 Docker/本机环境执行一键启动、完整回归和三项演示；任何真机能力缺失不得使这些验收失败。
7. 归档四组 Bonus 证据，更新 `evidence/README.md` 的准确路径；视频只作补充，关键截图、说明、命令和测试摘要进入最终 commit。
8. 完成内容审校、敏感信息检查、生成物/缓存检查和最终 diff 审查。

发布验收命令至少包括：

```text
python -m unittest discover -s tests -v
python -m py_compile competition/*.py starter_kit/prepare_submission.py
<web package manager> test
<web package manager> test:e2e
<web package manager> test:a11y
python starter_kit/prepare_submission.py --team-id <GITHUB_USERNAME>
```

完成检查：Bonus 四项各有可复现材料；三项黑盒任务、性能预算、科学内容规则和证据完整性检查全部通过；所有声明均与实际功能和证据一致。

阶段提交：`Finalize L2 guidance and visual storytelling evidence`

## 6. 关键风险与控制措施

| 风险 | 控制措施 |
|---|---|
| UI 依赖模型文本驱动状态，导致不稳定 | 状态机和动作使用结构化协议；本地验证器为事实源 |
| 图形与 QASM 漂移 | 单一 IR、revision、往返测试，解析失败保留最后有效状态 |
| Agent 长文本挤压实验对象 | 固定指导卡、长度预算、三级渐进展开、历史折叠 |
| 动画很“炫”但削弱理解或无障碍 | 动画只表达状态变化，支持减少动态效果，证据始终有文本/数据替代 |
| 错误恢复擅自改变用户意图 | 修复分类、语义修改确认、diff 和撤销 |
| 演示依赖云服务 | Bell 本地模拟闭环为发布门槛；Agent/后端均有降级状态 |
| 真机不可接入或结果被夸大 | 本地模拟器作为唯一阻断性主流程；真机仅用 fixture 验证预留视图，明确分层并展示噪声与证据边界 |
| 主观 Bonus 只有文档没有产品证据 | 四项证据在开发过程中持续归档，最终用可运行流程、截图和测试交叉证明 |

## 7. 最终定义（Definition of Done）

只有同时满足以下条件，L2 + Bonus 才算完成：

- 单场景产品实现并可一键启动，而非仅有设计稿或 README；
- Bell、自然语言生成、QASM 修复、后端推荐和结果解释围绕同一 `ExperimentSession` 闭环；
- Bell 黑盒脚本在规定动作、路由、错误和时间预算内完成本地实验，结果页明确呈现目标、电路作用、测量结果和证据边界；
- 键盘、屏幕阅读器、非颜色编码、减少动态效果和自动修改撤销均经过验证；
- Agent/后端故障不会清空实验，也不会阻止核心手动路径；
- Bonus 四项证据已填写到 `starter_kit/evidence/README.md`，路径有效并进入最终 commit；
- 全量测试、干净环境复现、敏感信息检查和提交预检全部通过。
