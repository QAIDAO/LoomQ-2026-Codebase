# LoomQ L3 Hybrid-QASM 编译分阶段开发执行计划

## 执行规则

所有工作按下面的执行块顺序推进。每个执行块都必须遵循同一闭环：

1. 完成该块列出的代码或配置修改。
2. 按“新增测试条件”补齐测试。
3. 运行该块要求的定向测试。
4. 运行规定范围的回归测试。
5. 对照“完成检查”确认目标与边界。
6. 仅在全部检查通过后创建阶段性 Git 提交。

不得把未通过测试的工作带入下一执行块；不得在同一提交中混入 L2、Bonus、UI、真机或无关文档修改。L3 的唯一交付接口是：

```python
compile_hybrid(hybrid_qasm_str: str) -> tuple[list, str]
```

L3 输出仍是量子操作列表与文本汇编。官方 `riscv_emulator.py` 是经典部分的兼容性基准，不在 L3 中修改，不生成机器码，也不建设完整 RISC-V 工具链。Bonus 的机器码闭环另见 [`plan_bonus_quantum_riscv.md`](plan_bonus_quantum_riscv.md)。

## 执行块 1：冻结题面文法、接口与内部模型

### 执行步骤

1. 从 `problem_statement.md`、`adapter.py`、`evaluator.py` 和 `riscv_emulator.py` 固化 L3 契约测试，保持函数名、参数和二元返回值不变。
2. 定义 Hybrid-QASM 顶层模型：
   - OpenQASM 头、量子寄存器与经典寄存器；
   - 按输入顺序保存的量子门和测量操作；
   - 一个 `classical` 块；
   - `classical` 块前后仍可出现量子语句，但经典块只控制经典赋值，不改变量子操作提取顺序。
3. 定义经典 AST：
   - 整数字面量；
   - `r1..r9`；
   - 测量位 `c[k]`；
   - `+`、`-` 算术表达式；
   - `==`、`!=` 条件；
   - 顺序赋值；
   - 带必选 `else` 的嵌套 `if/else`。
4. 固定寄存器映射：`r1..r9` 对应 `x1..x9`，`c[k]` 对应 `x10+k`；校验映射不得超过 `x31`。
5. 明确值语义：经典计算采用官方文本模拟器当前表现的 Python 整数语义，不在 L3 擅自加入 RV32 溢出、截断或机器码立即数限制。
6. 为所有 AST 节点保存源码位置或相关 token，使语法错误能指出语句和位置。

### 新增测试条件

- 公共样例可构造完整顶层模型；
- `r1`、`r9`、`c[0]` 和可映射的最大测量位边界；
- 空经典块、多个经典块、缺失 `else`、越界寄存器和越界测量位；
- 量子语句位于经典块之前、之后及两侧时仍保持原顺序；
- 返回类型注解和实际返回值满足固定接口。

### 回归测试

- 运行新增的 L3 契约和模型测试。
- 运行 `python -m unittest discover -s tests -v`。
- 不改动或替换官方模拟器，不运行 Bonus 机器码测试。

### 完成检查

- 目标检查：题面所有合法构造均有唯一内部表示，公共接口边界已由测试固定。
- 边界检查：没有接受题面外的循环、函数、自定义变量、乘除法、逻辑运算或完整 OpenQASM/RISC-V 语法。
- 兼容检查：寄存器映射与官方注入方式完全一致。

### 阶段性 Git 提交

`Define L3 Hybrid-QASM contracts and AST`

## 执行块 2：实现 Hybrid-QASM 词法与语法解析

### 执行步骤

1. 实现确定性的 tokenizer，识别标识符、整数、下标、分隔符、花括号以及 `+ - == != =`；正确跳过空白和 `//` 行注释。
2. 用递归下降或等价的显式解析器解析 `classical` 块，禁止 `eval()`、正则替换后执行源码或按关键字硬编码样例。
3. 明确表达式优先级：一元负号高于 `+/-`，算术表达式高于 `==/!=`；`+/-` 左结合，括号仅在题面允许的条件和表达式位置生效。
4. 区分赋值左值与表达式操作数：赋值左值只允许 `r1..r9`，条件可读取寄存器、测量位和整数字面量。
5. 解析嵌套块并保持语句顺序；每个 `if` 将 `else` 绑定到最近尚未配对的 `if`。
6. 将顶层量子部分交给已有、经过验证的 L1 QASM 解析能力，或复用其词法规则；不得维护一套语义不同的 12 门解析器。
7. 对未知 token、未闭合括号/花括号、非法左值、缺失分号和题面外语法给出确定性错误。

### 新增测试条件

- 整数字面量、负数、`r1..r9`、`c[k]` 的合法解析；
- 连续 `+/-`、同一寄存器读写和顺序赋值；
- `==`、`!=` 与常量/寄存器/测量位的不同组合；
- 一层、左右两侧和多层嵌套 `if/else`；
- 注释、空行、紧凑格式和跨行格式；
- 缺分号、缺花括号、孤立 `else`、非法 `r0/r10`、向 `c[k]` 赋值及未知运算符。

### 回归测试

- 对每一种 AST 节点运行解析黄金测试和非法输入测试。
- 对 L1 的 12 门、测量、注释和参数表达式解析运行既有回归。
- 运行完整 `unittest` 套件。

### 完成检查

- 目标检查：任意符合题面迷你文法的输入均由真正的 parser 转为 AST。
- 隐藏集检查：解析过程不依赖公共样例中的变量名、常量、缩进或分支形状。
- 边界检查：不实现循环、函数调用、内存、任意变量名或题面外 C 语法。

`Implement the L3 Hybrid-QASM parser`

## 执行块 3：提取并验证量子操作序列

### 执行步骤

1. 从已解析的顶层程序按源码顺序提取纯量子门和测量指令，排除声明、头部与 `classical` 块。
2. 固定列表元素的规范字符串格式，使同一输入得到字节级稳定输出；格式需能表达门名、参数、量子位及测量映射。
3. 对 12 个逻辑门、参数个数、量子位个数、寄存器范围和测量目标执行与 L1 一致的校验。
4. 保留输入量子部分的逻辑门语义，不因经典 lowering 重排、删除或插入量子门。
5. 编写独立规范化器用于测试：分别解析原输入量子部分和返回列表，再比较结构化操作，不用被测提取函数生成期望值。

### 新增测试条件

- 12 个逻辑门逐一提取；
- 参数门的正数、负数和组合角度；
- 多量子寄存器、逐位测量和整寄存器测量；
- 量子语句横跨经典块时顺序不变；
- 声明和经典语句不会泄漏到量子操作列表；
- 非法门、错误元数和越界下标在编译前失败。

### 回归测试

- 运行 L1 量子 IR 测试与 L3 量子提取测试。
- 对公开电路以及固定种子的随机量子片段执行独立规范化比较。
- 运行完整 `unittest` 套件。

### 完成检查

- 目标检查：返回列表与原输入量子部分逐项语义等价且顺序一致。
- 独立性检查：测试期望值不调用被测提取路径。
- 边界检查：本块不执行量子电路，不调用本地或远端后端。

## 执行块 4：将经典 AST lower 为官方汇编子集

### 执行步骤

1. 建立经典 emitter，只允许输出 `li`、`add`、`sub`、`addi`、`beq`、`bne` 和 `j`。
2. Lower 赋值表达式：
   - 常量赋值使用 `li`；
   - 寄存器加减使用 `add/sub`；
   - 寄存器与常量组合优先使用 `addi`；
   - 两个常量在编译期折叠；
   - `常量 - 寄存器` 可先把常量写入目标寄存器，再用 `sub`，并正确处理目标与源重叠。
3. 不假定存在未占用的永久临时寄存器。条件中的寄存器—寄存器比较直接分支；零常量使用 `x0`；非零常量比较若必须临时改写操作数，则在每条跳转路径进入分支体之前恢复原值。实现前用数据流测试证明不会破坏 `r1..r9` 或后续要读取的 `c[k]`。
4. 为每个 `if/else` 分配确定且全局唯一的标签，生成“条件分支 → else → 跳过 then/else 的汇合标签”结构；递归生成嵌套分支。
5. 根据 `==`/`!=` 选择 `beq`/`bne`，对编译期常量条件直接选择对应分支，但仍保持语义而非依赖公共样例。
6. 保证所有标签已定义、不会与用户 token 冲突，输出末尾换行且连续编译结果稳定。
7. 在 emitter 边界断言 mnemonic 白名单，禁止把 `mv`、`nop`、`jal`、`lui` 或其他伪指令带入 L3 输出。

### 新增测试条件

- 所有赋值形态：常量、寄存器、常量折叠、加法、减法、目标与源重叠；
- `==`/`!=` 的寄存器—寄存器、寄存器—常量、测量位—常量及常量—常量；
- then/else 均含多条顺序赋值；
- 深层嵌套和相邻多个分支的标签唯一性；
- 分支后继续读取条件操作数，验证临时改写已恢复；
- 汇编仅含官方七条指令与合法标签。

### 回归测试

- 将每个黄金 AST 的汇编交给原样未改的 `TinyRISCVEmulator` 加载和执行。
- 对每个测量输入至少比较 `x1..x9`，并确认输入测量寄存器未被意外污染。
- 运行完整 `unittest` 套件和 `python evaluator.py --level l3`。

### 完成检查

- 目标检查：全部经典语法均能 lower 为官方模拟器接受的指令子集。
- 模拟器检查：测试导入的是仓库官方 `riscv_emulator.py`，不是 Bonus 扩展模拟器。
- 边界检查：没有机器码、完整 RV32I、QEMU、汇编链接器或模拟器修改。

### 阶段性 Git 提交

`Lower L3 classical control to Tiny RISC-V assembly`

## 执行块 5：接通 `compile_hybrid` 并建立参考解释器

### 执行步骤

1. 在 `adapter.py` 接通实现，严格返回 `(list, str)`；合法输入不得返回空汇编占位或注释占位。
2. 编译流程固定为：输入校验 → 顶层/经典解析 → 量子操作提取 → 经典 lowering → 输出后置校验。
3. 实现仅供测试使用的独立经典 AST 参考解释器：
   - 直接按语句顺序求值；
   - 用递归语义执行嵌套分支；
   - 不生成、解析或执行汇编；
   - 不复用 emitter 的分支判断代码。
4. 参考解释器接受测量位字典，输出 `r1..r9` 的完整终态；未赋值寄存器视为零。
5. 对错误输入保证原子失败，不返回部分量子列表或部分汇编。

### 新增测试条件

- 固定接口公共样例在测量值 0/1 下得到 `r1=3/7`；
- 返回对象类型、稳定性、非空汇编和操作列表结构；
- 多次赋值与嵌套控制流的参考解释器结果；
- 未赋值寄存器、零值寄存器和负值；
- 解析或 lowering 失败时不产生部分结果。

### 回归测试

- 运行 `python evaluator.py --level l3`。
- 运行 L3 全部定向测试、完整 `unittest` 和 CI 等价 `py_compile`。
- 确认 L1 evaluator 与既有 L1 回归未受影响。

### 完成检查

- 目标检查：公共接口输出可被官方模拟器直接消费，且公开分支用例通过。
- 独立性检查：参考解释器与编译器不存在共同的 lowering 实现。
- 契约检查：不改变 `transpile()`、`run()`、`agent_chat()` 或 L1 runner。

## 执行块 6：建立官方评分同构的随机语义测试

### 执行步骤

1. 实现带显式 seed 的文法生成器，按深度和规模上限生成合法 Hybrid-QASM，而不是拼接少量固定模板。
2. 生成维度至少覆盖：
   - 0 到上限深度的嵌套分支；
   - `==` 与 `!=`；
   - 正、负、零及边界常量；
   - `r1..r9` 的读写组合；
   - 不同 `c[k]` 和测量位数；
   - 分支前后顺序赋值；
   - 12 门及不同量子/测量布局。
3. 对每个生成用例穷举全部 `2^m` 个测量值组合，其中 `m` 是实际被程序读取的测量位数；设置规模上限避免组合爆炸，但不得抽样替代穷举。
4. 每个组合分别：
   - 用独立参考解释器计算完整 `r1..r9` 终态；
   - 新建原版 `TinyRISCVEmulator`，加载编译汇编后向 `x10+k` 注入测量值；
   - 执行并逐项比较 `x1..x9`，把模拟器结果缺失的零寄存器归一为零；
   - 检查测量输入寄存器未遭非语义性破坏。
5. 独立比较量子操作序列与输入量子部分；经典正确性和量子正确性分别报告。
6. 失败信息保存 seed、完整输入、测量向量、预期/实际寄存器和汇编，确保单 case 可重放。
7. 增加固定回归种子集，并在常规 CI 使用有界规模；发布前运行更大的本地种子集。

### 新增测试条件

- 生成器本身的文法合法性、seed 可复现性和覆盖计数；
- 最小、最大深度以及左右不对称分支；
- 所有测量组合确实各执行一次，无遗漏或重复；
- 随机失败输出可由记录的 seed 单独重放；
- 量子列表错误和经典终态错误能被独立定位。

### 回归测试

- 常规门禁：固定种子集的全部用例、全部测量组合通过。
- 发布前门禁：扩大 seed 数和分支深度后全部通过，并记录命令与摘要，不提交生成报告。
- 运行公开 L3 evaluator、完整 `unittest`、L1 回归和 Docker 内等价 L3 测试。

### 完成检查

- 目标检查：测试形态与官方“随机文法生成 + 测量组合穷举 + 参考解释器比对”一致。
- 确定性检查：同一 seed、输入和环境得到相同汇编及结果。
- 反硬编码检查：改变常量、寄存器、测量位和分支形状不会走专用模板。

## 最终审计整改：共享控制流

- `classical_width <= 21` 时保留 `x31` 作为编译器 scratch。赋值和条件在运行时从当前 `x1..x9` 与 `x10..x30` 求值，每个 `if/else` 生成独立的 else/join 标签，join 后的 continuation 只编译一次。
- `classical_width == 22` 时在入口按原始 `c[21]/x31` 的 0/非 0 值分成两条特化路径，将该测量位分别作为常量 0/1 编译。两条路径内部仍使用共享 CFG 和同一全局标签计数，结束前恢复 `x31`；因此只产生固定两倍代码，不复制 continuation。
- `classical_width > 22` 无法映射到固定的 `x10..x31` 测量寄存器区间，在经典语句解析和汇编生成前硬拒绝；即使程序只显式读取低位，也不把超宽声明静默当作 width 22。
- 规模门禁覆盖宽度 22 下的 12/20 个顺序 `if`、深度 4 的嵌套 CFG，以及包含 `c[21]` 的 5 位和 8 位活跃测量穷举；先断言汇编行数/字节数，再由原版 `TinyRISCVEmulator` 完成 load/execute，并以 `max_steps` 约束最大执行步数。
- 语义门禁继续逐项比较 `x1..x9`，覆盖顺序赋值、任意线性条件、负常量和嵌套分支，同时断言测量寄存器保持不变。

## Git 提交通用门禁

- 暂存区只包含当前执行块的改动；
- 相关定向测试和规定回归全部通过；
