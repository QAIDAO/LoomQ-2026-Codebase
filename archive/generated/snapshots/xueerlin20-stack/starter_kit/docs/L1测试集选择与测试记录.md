# L1 测试集选择与测试记录

> 覆盖平台：SpinQ、OriginQ、Amazon Braket  
> 公开测试：13 个电路，共 39 个平台用例  
> 通过标准：Hellinger Fidelity 不低于 0.97

本文说明 L1 测试集为什么这样选择，以及 `test4` 如何帮助我们发现并修正测量位序问题。文中的结果来自项目公开自测，不等同于组委会正式评分。

## 一、测试目标

L1 把 OpenQASM 2.0 电路转换为三个平台可以执行的格式，并统一整理运行结果。测试主要检查：

1. 寄存器、量子门、参数和测量关系是否解析正确；
2. 12 类支持门是否都能完成跨平台转换；
3. 三个平台生成的程序是否可以正常执行；
4. 测量结果是否统一为 `c[n-1]...c[0]`；
5. 转换前后的电路是否保持相同的运行含义。

## 二、测试集选择思路

Bell 和 GHZ 电路适合检查基础纠缠，但它们主要产生 `00/11` 或 `000/111`。这些字符串反转后不变，即使位序处理错误，测试也可能通过。

因此，测试集不能只使用对称电路。我们同时选择了以下几类用例：

| 选择方向 | 检查内容 |
|---|---|
| 基础电路 | 快速确认解析、基础门和测量流程可以运行 |
| 非对称分布 | 让 `01` 和 `10` 等结果概率不同，直接暴露位序错误 |
| 交叉测量 | 检查 `q[i]` 是否写入指定的 `c[j]`，而不是默认写入同一下标 |
| 多比特电路 | 检查结果长度、前导零和较大下标 |
| 稀疏分布 | 用少量非零结果检查每个逻辑位的位置 |
| 完整门集 | 确认全部支持门组合出现时没有产生新的转换问题 |

## 三、各测试用例的选择理由

当前测试集包含 5 个基础或算法电路，以及 8 个补充电路。

| 用例 | 比特数 | 主要内容 | 选择理由 |
|---|---:|---|---|
| `bell.qasm` | 2 | `h`、`cx` | 使用最小纠缠电路确认基础转换和测量流程 |
| `ghz3.qasm` | 3 | `h`、`cx` 链 | 检查三比特纠缠和连续受控门 |
| `ghz5.qasm` | 5 | `h`、`cx` 链 | 检查五比特结果宽度和更长的受控门链 |
| `QFT4.qasm` | 4 | `x`、`h`、`cu1`、`swap` | 检查参数门、受控相位门和末端交换的组合转换 |
| `grover3.qasm` | 3 | `h`、`x`、`ccx` | 检查 Toffoli 门、多轮门组合和集中于目标态的分布 |
| `test1` | 2 | `ry`、`cx`、`swap` | 使用非对称分布检查交换门和位序 |
| `test2` | 2 | 旋转门与相位门组合 | 让四种结果概率不同，检查参数和组合转换 |
| `test3` | 2 | `sdg`、`tdg`、`cx` | 检查逆相位门在不同平台上的等价转换 |
| `test4` | 2 | `ry`、`cx`、交叉测量 | 专门检查量子位到经典位的映射，是位序问题的核心诊断用例 |
| `test5` | 5 | `x`、确定结果 | 检查五位结果、前导零和确定态输出 |
| `test6` | 5 | `ry`、`x`、`ccx`、`cx` | 使用五比特稀疏分布检查 Toffoli 门和逻辑位位置 |
| `test7` | 5 | `ry`、`x`、`swap`、`cx` | 使用非对称稀疏分布检查交换后的位序 |
| `test8` | 5 | 全部 12 类支持门 | 作为完整门集的综合回归测试 |

这组测试采用“简单用例定位问题、复杂用例检查回归”的方式。基础电路失败时容易定位；复杂电路通过后，可以确认多个转换规则一起使用时仍保持一致。

## 四、test4 发现的测量位序问题

### 4.1 为什么选择 test4

`test4` 不使用常见的一一对应测量，而是交换两个经典位的写入位置：

```qasm
OPENQASM 2.0;
include "qelib1.inc";
qreg q[2];
creg c[2];
ry(pi/3) q[0];
ry(pi/5) q[1];
cx q[0],q[1];
measure q[0] -> c[1];
measure q[1] -> c[0];
```

它的理论分布为：

| 结果 | 理论概率 |
|---|---:|
| `00` | 0.6783813729 |
| `01` | 0.0716186271 |
| `10` | 0.0238728757 |
| `11` | 0.2261271243 |

其中 `01` 与 `10` 的概率明显不同。如果程序把两个经典位的位置处理反了，这两个概率会交换，Fidelity 会立即下降。相比 Bell 和 GHZ，`test4` 对位序错误更敏感。

### 4.2 测试暴露了什么

早期测试中，`test4` 在 OriginQ 通过，但在 SpinQ 和 Braket 上低于 0.97。与此同时，Bell 和 GHZ 仍然通过。

这个现象说明量子门本身大概率没有问题，错误更可能出现在平台结果转换为统一 `counts` 的阶段。OriginQ 的返回结果更接近经典位含义，而 SpinQ 和 Braket 的原始结果需要根据量子位和测量顺序重新映射。

### 4.3 问题原因

早期实现对 SpinQ 和 Braket 的结果字符串执行整体反转：

```python
key[::-1]
```

这种方法只适用于量子位和经典位按固定顺序一一对应的情况。`test4` 使用的是交叉测量：

```text
q[0] -> c[1]
q[1] -> c[0]
```

交叉测量是一种位置映射，不等同于所有情况下都进行字符串反转。只处理字符串方向，会忽略每条 `measure` 指令指定的真实目标位置。

### 4.4 调整方法与结果

结果归一化改为以下流程：

1. 解析所有 `measure q[i] -> c[j]`；
2. 确定 SDK 结果中的每一位属于哪个 `q[i]`；
3. 按测量关系把结果写入对应的 `c[j]`；
4. 最后统一按 `c[n-1]...c[0]` 生成结果字符串；
5. 如果多个原始结果映射到同一经典结果，则合并计数。

调整后，`test4` 在三个平台均达到通过标准：

| 平台 | Fidelity |
|---|---:|
| SpinQ | 0.999826 |
| OriginQ | 0.993127 |
| Braket | 0.990397 |

`test4` 说明，对称电路适合确认基础功能，但不能单独证明位序正确。测试集中必须保留交叉测量和非对称概率分布。

## 五、其他测试的补充作用

除 `test4` 外，其他复杂用例用于确认调整没有破坏已有功能：

- `test3` 和 `test8` 检查 `sdg`、`tdg` 在 OriginIR 中的等价表达；
- `QFT4.qasm` 检查 `cu1` 的平台门名和参数格式；
- `grover3.qasm` 检查测试电路与理论期望是否对应；
- `test5` 至 `test8` 检查五比特宽度、前导零、稀疏分布和完整门集。

这些用例主要承担回归检查。位序问题的直接定位仍以 `test4` 为主。

## 六、测试结果

公开测试包含 13 个电路，每个电路在 SpinQ、OriginQ 和 Braket 上各运行一次，共 39 个用例。当前 39 个用例全部达到 0.97 阈值。

```text
通过：39
失败：0
总计：39
```

真机结果单独保存在 `starter_kit/evidence/files/`，不与公开模拟器结果混合统计。

## 七、复现方式

在项目根目录和 Python 3.10 环境中运行：

```powershell
python starter_kit\evaluator.py --level l1 --target spinq,originq,braket
```

如需保存 JSON 报告：

```powershell
python starter_kit\evaluator.py --level l1 --target spinq,originq,braket --json-out starter_kit\report.json
```

## 八、结论

测试集同时覆盖基础电路、非对称分布、交叉测量、多比特宽度、稀疏分布和完整门集。它不仅检查程序能否运行，也检查不同平台是否保持相同的测量含义。

其中，`test4` 是最关键的位序测试。它证明了简单字符串反转不能处理任意测量映射，也推动结果整理方式从“调整字符串方向”改为“按真实测量关系写入经典位”。
