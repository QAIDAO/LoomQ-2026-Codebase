# 量子计算基础与 LoomQ 分层说明

## 这份文档写给谁

这份文档面向第一次接触量子计算的读者。阅读时不需要物理、数学或编程基础，文中出现的新名词都会用日常语言解释。

本文先介绍理解项目所需的量子计算常识，再说明 LoomQ 的 L1、L2、L3 分别解决什么问题。

## 从普通比特到量子比特

普通计算机中的一个比特只能是 `0` 或 `1`，可以把它想象成一个关闭或打开的开关。

量子比特可以先理解为一个**自带概率的比特**，也可以想象成一枚正在旋转的硬币。硬币停止并被看清之前，我们会同时考虑正面和反面两种可能；量子比特在测量前也保留着得到 `0` 和 `1` 的可能性。经过特定操作后，它在测量时可能有约一半机会得到 `0`，另一半机会得到 `1`。

“旋转的硬币”只是帮助入门的比喻。普通硬币在每个时刻仍有确定的朝向，量子比特却不能简单理解为一个答案早已确定、只是我们还不知道的普通比特。不同可能性之间还会互相加强或抵消，这正是量子计算能够利用的特点。LoomQ 不要求使用者计算这些变化，只需要按规则描述电路。

## 量子门是什么

普通程序使用加法、比较和赋值来改变数据；量子程序使用**量子门**来改变量子比特的状态。

几个常见例子：

- `X` 门：可以近似理解为把 `0` 与 `1` 互换；
- `H` 门：可以把初始为 `0` 的量子比特变成测量结果接近一半为 `0`、一半为 `1` 的状态；
- `CX` 门：连接两个量子比特，让第二个量子比特的变化受到第一个量子比特影响。

量子门按一定顺序排列，就组成了**量子电路**。它类似普通程序中的一串指令，只是操作对象换成了量子比特。

## 单量子比特与多量子比特

### 单量子比特

单量子比特电路只操作一个量子比特。它适合演示 `X`、`H` 和旋转门等基础操作，也容易观察测量概率如何变化。

一个量子比特测量后只有两种结果：

```text
0 或 1
```

单个量子比特可以形成叠加，但不能独自形成纠缠，因为纠缠描述的是两个或更多量子比特之间的关系。

### 多量子比特

多个量子比特放在同一电路中，可以分别操作，也可以通过 `CX` 等门建立联系。`n` 个量子比特测量后共有 `2^n` 种可能的比特串。例如：

```text
2 个量子比特：00、01、10、11
3 个量子比特：000 到 111，共 8 种
5 个量子比特：00000 到 11111，共 32 种
```

这不表示一次测量能同时读出全部结果。每次运行只得到其中一个比特串，需要重复运行才能统计各种结果出现的比例。

多量子比特也不一定处于纠缠状态。只有当这些量子比特形成不能完全分开描述的整体关系时，才称为纠缠。

## 叠加、纠缠与测量

### 叠加

量子比特在测量前可以同时保留多种结果的可能性，这种状态称为叠加。叠加并不意味着一次测量能同时读出全部答案；每次测量仍然只得到一个确定的 `0` 或 `1`。

### 纠缠

多个量子比特可以形成很强的整体关联。通俗地说，它们看起来像拥有“心灵感应”：即使相隔很远，分别测量时仍会表现出共同的结果规律。

例如，一个理想的两比特 Bell 态通常只测到 `00` 或 `11`。单独看任意一个量子比特，结果都是随机的；把两个结果放在一起看，它们却总是相同。两个量子比特因此需要作为一个整体理解。

“心灵感应”同样只是比喻。纠缠并不表示我们可以随意改变一个量子比特，再让远处的另一个按要求改变，也不能用它传递超过光速的信息。它强调的是测量结果之间存在很强的共同规律，而不是远距离遥控。

三比特及更多比特的 GHZ 态也是类似的整体关联。理想的三比特 GHZ 电路主要得到 `000` 和 `111`；推广到 `n` 个量子比特时，主要得到全 `0` 和全 `1` 两种结果。

### 怎样理解“纠缠度最高”

对两个量子比特来说，理想 Bell 态可以称为最大纠缠态。对三个及更多量子比特来说，“纠缠度最高”没有唯一答案，因为不同纠缠状态强调的关系不同，判断方法也不止一种。

在入门实验中，如果希望让 `n` 个量子比特形成清楚、容易观察的整体关联，通常可以选择 `n` 比特 GHZ 态。但这不表示 GHZ 态在所有判断方法下都是唯一的“最高纠缠态”。

向 LoomQ 描述需求时，下面的说法比“生成纠缠度最高的 `n` 量子比特”更明确：

```text
生成一个 n 比特 GHZ 态，并测量全部量子比特。
```

### 测量

测量负责把量子状态转换成普通数据。下面的 QASM 指令表示测量 `q[0]`，并把结果保存到经典位 `c[0]`：

```qasm
measure q[0] -> c[0];
```

测量结果只能是 `0` 或 `1`。测量通常也会改变量子状态，因此不能把一次测量简单看成“查看一下但不影响原值”。

## 为什么要重复运行

因为量子测量带有概率，只运行一次通常无法看出电路的整体行为。实际测试会把同一电路重复运行很多次，每次运行称为一次 `shot`。

例如运行 1000 次 Bell 电路后，可能得到：

```text
00: 492
11: 508
```

这种“结果及其出现次数”的统计称为 `counts`。理想模拟器的结果通常接近理论概率；真实量子设备受到噪声影响，可能还会出现少量其他结果。

项目中的保真度可以简单理解为：**实际结果与期望结果有多接近**。数值越接近 1，说明两者越一致。

## 模拟器、真机与后端

- **模拟器**使用普通计算机模拟量子电路，适合开发、调试和检查逻辑；
- **量子真机**在真实量子芯片上运行，会受到设备噪声、连接方式和排队时间影响；
- **后端**是程序实际提交到的运行目标，可以是一种模拟器，也可以是一台量子真机。

不同厂商的平台支持的量子门、程序格式和结果格式并不完全相同。因此，同一份电路不能总是不加处理地直接发送到所有平台。

## QASM 是什么

QASM 是一种用文字记录量子电路的方式，可以把它看成一份按顺序执行的操作清单。对于熟悉编程的读者，它也类似程序的源代码。

下面是一份两比特 Bell 电路：

```qasm
OPENQASM 2.0;
include "qelib1.inc";
qreg q[2];
creg c[2];
h q[0];
cx q[0], q[1];
measure q -> c;
```

其中：

- `qreg q[2]` 创建两个量子比特；
- `creg c[2]` 创建两个保存测量结果的经典比特；
- `h` 和 `cx` 建立 Bell 态；
- `measure` 把量子结果写入经典比特。

LoomQ 以 OpenQASM 2.0 为主要输入格式，再根据不同任务进行转换、生成或扩展。

## LoomQ 要解决的整体问题

编写一个量子电路只是第一步。真正使用它时，还会遇到三个问题：

1. 同一份电路怎样在不同量子平台运行？
2. 不熟悉 QASM 的人怎样用自然语言完成任务？
3. 量子测量结果怎样交给普通程序继续判断和计算？

LoomQ 使用 L1、L2、L3 分别解决这三个问题：

| 层级 | 主要输入 | 主要输出 | 解决的问题 |
|---|---|---|---|
| L1 | OpenQASM 2.0 电路 | 平台代码与统一运行结果 | 跨平台转换与执行 |
| L2 | 用户的自然语言 | QASM、修复结果或后端建议 | 降低使用门槛 |
| L3 | Hybrid-QASM | 量子操作列表与普通处理器指令 | 连接量子计算和经典控制 |

三个层级关注点不同，不是简单地把同一功能重复三遍。它们共同覆盖了从“描述需求”到“生成电路”“跨平台运行”再到“处理测量结果”的主要流程。

## L1：跨平台转换与运行

### L1 做什么

L1 接收 OpenQASM 2.0 电路，把它转换成 SpinQ、Amazon Braket 和 OriginQ 可以执行的格式，并把不同平台返回的结果整理成统一结构。

```text
OpenQASM 2.0
      ↓
解析电路
      ↓
生成目标平台代码
      ↓
模拟器或真机运行
      ↓
统一 counts 结果
```

### 为什么需要 L1

三个平台对量子门名称、程序格式、测量顺序和结果排列的处理存在差异。特别是 `q[i]` 测量到哪个 `c[j]`，不能只靠简单反转字符串处理。

L1 会记录真实的测量对应关系，再按比赛规定的经典位顺序整理结果。因此，普通测量、逐位测量和交叉测量都能得到一致的输出。

### L1 的作用

L1 相当于不同量子平台之间的“翻译员”。使用者只需提供一份标准电路，不必为三个平台分别编写代码，也可以用同一种格式比较不同平台的运行结果。

## L2：自然语言量子助手

### L2 做什么

L2 允许用户直接描述需求，例如：

```text
生成一个三比特 GHZ 态并测量全部量子比特。
```

当前支持三类任务：

- 根据自然语言生成 QASM；
- 修复存在问题的 QASM；
- 根据比特数、费用和排队要求推荐后端。

### L2 如何工作

L2 中的语言模型负责理解用户表达，普通 Python 程序负责执行明确规则和检查结果：

```text
用户需求
    ↓
模型理解任务并整理成固定格式的任务清单
    ↓
对应的处理器完成生成、修复或推荐
    ↓
L1 的代码检查工具或平台资料表进行检查
    ↓
返回稳定、易读的结果
```

模型擅长理解不同说法，但生成内容不一定始终正确。因此，L2 不会直接采用模型输出，而是用已有程序检查 QASM，并根据官方提供的平台资料计算后端建议。

### L2 的作用

L2 把面向代码的量子工具变成面向人的入口。初学者不需要记住全部 QASM 语法，也可以描述实验目标；有经验的使用者则可以让系统检查和修复代码。

## L3：量子与经典混合编译

### 为什么量子程序还需要普通计算

量子计算机不会完全替代普通计算机。量子门负责改变量子状态，测量得到普通的 `0` 或 `1` 后，仍需要经典程序进行判断、加减运算和结果保存。

这类配合可用于：

- 根据测量结果选择处理分支；
- 检查和修正量子设备运行中的错误；
- 根据上一次结果反复调整量子电路中的数值；
- 量子通信中的测量信息处理；
- 量子采样结果的整理。

### L3 做什么

L3 接收 Hybrid-QASM。它是在普通 QASM 中加入经典控制内容的格式，既能写量子操作，也能在 `classical { ... }` 中写普通的判断和计算：

```qasm
measure q[0] -> c[0];
classical {
  if (c[0] == 1) {
    r1 = 100;
  } else {
    r1 = 10;
  }
  r1 = r1 + 5;
}
```

编译器会生成两部分结果：

1. 保持原顺序的量子门与测量列表；
2. 可以在官方模拟器运行的 RISC-V 汇编。

RISC-V 汇编是一种接近处理器实际操作的文字指令。在本项目中，只需要用到写入数字、加减、比较和跳转等少量基础指令，不需要了解真实处理器的复杂结构。

处理器使用“寄存器”临时保存数据，可以把寄存器理解成一组有编号的小储物格。测量位按下面的规则放入这些储物格，再交给经典程序：

```text
c[0] -> x10
c[1] -> x11
c[2] -> x12
```

经典程序读取这些测量值，执行赋值、加减和 `if/else`，再把结果写入 `x1..x9`。

### L3 的作用

L3 相当于量子设备与普通处理器之间的连接层。它保证量子操作不会丢失，也保证经典程序读到正确的测量位，并能用官方模拟器检查最终计算结果。

## 三个层级怎样配合

一个自然语言实验可以经历下面的流程：

```text
用户描述实验
    ↓
L2 理解需求并生成、修复 QASM
    ↓
L1 检查并转换电路
    ↓
SpinQ、Braket 或 OriginQ 运行
    ↓
L1 整理统一的测量结果
```

如果输入本身包含经典控制，则由 L3 处理：

```text
Hybrid-QASM
    ↓
L3 分离量子操作与经典控制
    ↓                    ↓
量子操作列表       普通处理器指令
量子平台执行       经典模拟器执行
```

L2 与 L1 可以形成自然语言到量子平台的完整使用流程；L3 则补充了量子程序与普通控制程序共同工作的能力。

## 阅读后可以记住什么

1. 量子比特可以先理解为“自带概率的比特”，测量后得到确定的 `0` 或 `1`；
2. `n` 个量子比特有 `2^n` 种可能结果，但每次运行只能测到其中一种；
3. 纠缠表示多个量子比特具有很强的共同规律，不表示可以远距离随意控制或传递信息；
4. 量子门按顺序组成量子电路，重复运行后用 `counts` 统计每种结果出现了多少次；
5. QASM 是描述量子电路的文本语言，后端是实际运行电路的模拟器或真机；
6. L1 解决不同量子平台之间的转换、执行和结果统一；
7. L2 用自然语言帮助用户生成、修复电路并选择后端；
8. L3 把量子操作与经典控制分开编译，让测量结果能够进入普通程序继续计算。
