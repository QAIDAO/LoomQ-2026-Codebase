# L3 实现说明

## 我们要解决什么

L3 的目标，是把一份 Hybrid-QASM 程序拆成两个可以分别执行的部分：

1. **量子操作序列**：保留量子门和测量指令；
2. **RISC-V 汇编文本**：实现 `classical { ... }` 中的赋值、计算和条件判断。

例如下面的程序先测量量子比特，再根据测量结果修改 `r1`：

```qasm
measure q[0] -> c[0];
classical {
  if (c[0] == 1) {
    r1 = 100;
  } else {
    r1 = 10;
  }
  r1 = r1 + 5;
}
cx q[0], q[1];
```

编译后，量子部分仍按原顺序包含 `measure` 和 `cx`，经典部分则变成官方模拟器可以运行的 RISC-V 指令。

## 为什么需要量子与经典混合编译

量子计算机并不是完全替代普通计算机，而是由两者配合完成任务。

- **量子门**作用在量子比特上，负责叠加、纠缠和量子态变化；
- **测量**把量子状态转换成普通的 `0` 或 `1`；
- **经典指令**负责确定的加减运算、条件判断和结果保存。

量子设备擅长处理某些特殊计算，但不适合完成所有控制工作。例如，程序测量出一个比特后，需要普通处理器判断它是 `0` 还是 `1`，再决定如何保存结果或执行下一步。因此，一份完整程序中常常同时存在量子操作和经典控制。

```text
量子门运行
    ↓
测量得到 0 或 1
    ↓
经典程序读取测量值
    ↓
进行判断、计算并保存结果
```

混合编译的作用不是把两类指令强行变成同一种格式，而是正确读懂同一份程序，再把不同工作交给合适的设备：量子操作交给量子平台，经典控制交给普通处理器。编译时还必须保留两部分之间的测量位对应关系，否则经典程序可能读取错误的比特。

## 混合程序用在哪里

量子与经典配合常见于以下场景：

1. **根据测量结果继续处理**：量子电路产生测量值，经典程序根据 `0` 或 `1` 选择不同分支。
2. **量子纠错**：系统测量用于检查错误的辅助比特，再由经典程序判断发生了哪类错误以及应采取什么操作。
3. **参数反复调整**：量子电路给出一次结果，经典程序据此调整参数，然后再次运行量子电路。这类方法常用于求解优化问题和研究分子性质。
4. **量子通信**：例如量子隐形传态中，发送方的测量结果需要通过普通信息传给接收方，接收方再根据这些比特选择对应操作。
5. **结果整理**：量子设备负责采样，经典程序负责统计、筛选和组合结果，形成最终可读的数据。

本项目的 L3 聚焦其中最基础的一步：从同一份 Hybrid-QASM 中提取量子操作，并把依赖测量值的经典计算编译成 RISC-V。它不负责完整的设备调度，但为量子设备与经典控制器正确交换数据提供了清晰、可验证的输出。

## 本项目中的数据如何传递

量子部分的 `measure q[k] -> c[n]` 会把测量结果记录到经典位 `c[n]`。评测时，系统再把这些值依次放入 RISC-V 寄存器：

```text
c[0] -> x10
c[1] -> x11
c[2] -> x12
...
```

生成的汇编读取这些寄存器，执行 `if/else` 和加减运算，最后把结果写入 `x1..x9`。这样，量子测量结果就能成为普通程序的输入，也能由官方模拟器检查最终计算是否正确。

## 整体流程

```text
Hybrid-QASM 输入
      |
      +-- 找出 classical 块
      |
      +-- 量子部分：去掉声明，保留量子门和测量，再交给 L1 解析器检查
      |
      +-- 经典部分：识别文字和符号，理解赋值与 if/else，生成 RISC-V
      |
      +-- 返回（量子操作列表，RISC-V 汇编文本）
```

公开入口是：

```python
compile_hybrid(hybrid_qasm_str)
```

它返回一个二元组：

```python
(quantum_operations, riscv_assembly)
```

## 各文件负责什么

| 文件 | 作用 |
|---|---|
| `L3/compiler.py` | 串联整个编译流程，并整理最终返回值 |
| `L3/quantum.py` | 找出经典块，提取量子操作，并调用 L1 解析器检查量子语法 |
| `L3/lexer.py` | 把经典代码中的寄存器、数字、运算符和括号逐个识别出来 |
| `L3/parser.py` | 判断这些内容组成的是赋值、计算还是 `if/else` |
| `L3/nodes.py` | 用统一的数据结构保存已经理解的经典语句 |
| `L3/riscv_compiler.py` | 把经典语句转换为 RISC-V 指令 |
| `L3/errors.py` | 提供统一、清楚的错误类型 |
| `L3/tests/test_compiler.py` | 检查语法、寄存器映射、分支和最终运行结果 |

这种拆分方式与 L1、L2 一致：入口只负责调度，每个文件只处理一类问题。出现错误时，可以快速判断问题在量子提取、经典语句理解，还是汇编生成阶段。

## 量子部分如何处理

`quantum.py` 会先忽略注释中的 `classical`，再定位真正的 `classical { ... }`。提取经典块后，它会：

1. 检查 `OPENQASM 2.0;` 和 `creg c[N];`；
2. 跳过 `OPENQASM`、`include`、`qreg` 和 `creg` 等声明；
3. 保留所有量子门与 `measure`；
4. 保持经典块前后量子操作的原始顺序；
5. 使用现有 L1 解析器再次验证量子部分。

复用 L1 解析器可以让 L1 和 L3 对寄存器、量子门及下标范围采用相同规则，避免维护两套不同的 QASM 检查逻辑。

## 经典部分如何处理

经典块支持比赛规定的内容：

- `r1` 到 `r9`；
- `c[0]` 到已声明的经典位上限；
- 整数和负整数；
- `+`、`-`、`==`、`!=`；
- 普通赋值和自引用赋值，例如 `r1 = r1 + 5;`；
- 多条语句依次执行；
- `if/else`；
- 多层 `if/else`。

程序不会按关键词猜测答案。它先逐个识别字符，再按括号和语句关系理解代码，因此寄存器、常量、条件和嵌套层数变化后仍能使用同一套规则编译。

## 寄存器如何对应

| Hybrid-QASM | RISC-V |
|---|---|
| `r1` 到 `r9` | `x1` 到 `x9` |
| `c[0]` | `x10` |
| `c[1]` | `x11` |
| `c[k]` | `x10+k` |

测量结果由评测系统写入 `x10`、`x11` 等寄存器。编译器只读取这些输入，不会把临时结果写回其中。

复杂表达式需要暂存中间结果时，编译器从高编号寄存器开始选择空闲位置，例如 `x31`、`x30`。它会避开 `r1..r9` 对应的输出寄存器，也会避开保存测量结果的寄存器。

## RISC-V 如何生成

生成结果只使用官方模拟器支持的七类指令：

```text
li  add  sub  addi  beq  bne  j
```

常见转换方式如下：

| 经典语句 | 生成方式 |
|---|---|
| `r1 = 10;` | 用 `li` 写入常量 |
| `r2 = r1;` | 用 `addi` 完成寄存器复制 |
| `r3 = r1 + r2;` | 使用 `add` |
| `r3 = r1 - r2;` | 使用 `sub` |
| `if (a == b)` | 使用 `bne` 跳到 `else` |
| `if (a != b)` | 使用 `beq` 跳到 `else` |

每个条件都会生成自己的一组标签，例如 `L3_else_1` 和 `L3_end_1`。编号持续增加，所以连续条件和多层条件不会跳到错误位置。

## 错误检查

编译器会明确拒绝以下输入：

- 使用 `r10` 等范围外的输出寄存器；
- 使用超过 `creg c[N]` 范围的 `c[k]`；
- `if` 缺少必须的 `else`；
- 出现文法不支持的字符或运算；
- 括号、花括号或分号不完整；
- 量子部分不符合 L1 的 OpenQASM 规则；
- `classical` 块缺失、重复或边界不完整。

错误信息会尽量带上行号和位置，方便直接定位原始 Hybrid-QASM。

## 测试范围

当前测试覆盖：

- 量子门和测量顺序；
- 注释与紧凑格式；
- `r1..r9` 的完整映射；
- 多个测量位及其输入保持；
- 常量、复制、加法、减法和自引用；
- 负整数与括号表达式；
- `==`、`!=`、连续条件和多层条件；
- 标签是否唯一；
- 非法寄存器、越界测量位和缺少 `else`；
- 生成的指令是否都属于官方支持范围；
- 汇编在官方 `riscv_emulator.py` 中运行后的寄存器终值。

在仓库根目录可以运行：

```powershell
python -B -m unittest discover -s starter_kit\L3\tests -v
python -B starter_kit\evaluator.py --level l3
```

当前 L3 单元测试共 14 项，公开 evaluator 的分支语义测试也已通过。

## 当前范围

当前实现严格面向比赛文法，不额外支持循环、乘除法、小数、函数或 `r10` 以上的输出寄存器。由于测量位从 `x10` 开始、可用寄存器到 `x31`，经典寄存器最多支持 22 位。

限制输入范围可以让生成结果保持简单、稳定，并确保所有汇编都能在官方轻量模拟器中运行。

## 总结

L3 的核心做法是：先可靠地分开量子与经典代码，再分别复用 L1 检查和本地经典编译，最后通过官方模拟器验证结果。整个过程不依赖样例硬编码，能够处理随机生成的寄存器、表达式和多层条件。
