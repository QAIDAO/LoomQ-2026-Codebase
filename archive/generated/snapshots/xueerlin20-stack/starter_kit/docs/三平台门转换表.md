# 三平台 12 门转换表

## 目的与判定原则

输入门集固定为：`h`、`x`、`s`、`sdg`、`t`、`tdg`、`rz`、`ry`、`cx`、`cu1`、`swap`、`ccx`。

目标代码中的每一条门指令必须同时满足：

1. 符合比赛的 [`target_ir_contract.md`](../starter_kit/target_ir_contract.md)；
2. 能被对应平台的真实 SDK／本地模拟器导入和执行。

下表的后端支持情况来自逐门实测，不是根据平台文档推断。平台文档、比赛契约与实际 SDK 不一致时，以“契约允许且实测可运行”的交集为准；交集不存在的原门按 [`gate_identities.md`](../starter_kit/gate_identities.md) 改写。

符号约定：`q` 为单比特，`a`、`b`、`c` 分别为控制位／目标位；`θ` 为原参数。表中的多条指令按从上到下的顺序输出。

## 总表

| 输入门 | SpinQ（OpenQASM 2） | Braket（OpenQASM 3） | OriginQ（OriginIR） |
|---|---|---|---|
| `h q` | `h q;`（直译） | `h q;`（直译） | `H q`（改名） |
| `x q` | `x q;`（直译） | `x q;`（直译） | `X q`（改名） |
| `s q` | `s q;`（直译） | `s q;`（直译） | `S q`（改名） |
| `sdg q` | `sdg q;`（直译） | `si q;`（Braket 实测门名） | `RZ q,(-pi/2)`（等价改写） |
| `t q` | `t q;`（直译） | `t q;`（直译） | `T q`（改名） |
| `tdg q` | `tdg q;`（直译） | `ti q;`（Braket 实测门名） | `RZ q,(-pi/4)`（等价改写） |
| `rz(θ) q` | `rz(θ) q;`（直译） | `rz(θ) q;`（直译） | `RZ q,(θ)`（参数后置） |
| `ry(θ) q` | `ry(θ) q;`（直译） | `ry(θ) q;`（直译） | `RY q,(θ)`（参数后置） |
| `cx a,b` | `cx a,b;`（直译） | `cnot a,b;`（Braket 实测门名） | `CNOT a,b`（改名） |
| `cu1(θ) a,b` | `cu1(θ) a,b;`（直译） | `cphaseshift(θ) a,b;`（Braket 实测门名） | `CR a,b,(θ)`（契约别名、参数后置） |
| `swap a,b` | `swap a,b;`（直译） | `swap a,b;`（直译） | `SWAP a,b`（改名） |
| `ccx a,b,c` | `ccx a,b,c;`（直译） | `ccnot a,b,c;`（Braket 实测门名） | `TOFFOLI a,b,c`（契约别名） |

实际输出时，表中的 `q`、`a`、`b`、`c` 要替换为目标格式的完整比特引用，例如 `q[0]`。

## 必须特殊处理的门

### Braket：不能照抄 QASM 2 门名

Braket 实测不接受 `sdg`、`tdg`、`cx`、`ccx`，必须分别输出 `si`、`ti`、`cnot`、`ccnot`。`cu1` 输出 Braket 的受控相位门 `cphaseshift`。这些是门名归一化，电路结构不变。

### OriginQ：不要输出 `SDAG`、`TDAG` 或 `U1`

比赛契约把 `SDAG`、`TDAG` 列为允许门名，但 pyqpanda 的 OriginIR 解析器没有实现它们，因此不能直接输出。

`gate_identities.md` 给出：

```text
sdg q  ≡ u1(-pi/2) q
tdg q  ≡ u1(-pi/4) q
```

同一文件还说明，单比特门位置上的 `u1(θ)` 与 `rz(θ)` 只差全局相位，测量分布相同。因此改写为：

```text
# sdg q
RZ q,(-pi/2)

# tdg q
RZ q,(-pi/4)
```

这里特意不输出当前实现采用的 `U1`：`U1` 虽能被 pyqpanda 执行，却不在 OriginQ 官方契约列出的允许门名中；`RZ` 同时满足契约与实测运行要求。

### OriginQ：`cu1` 使用 `CR`

契约明确接受 `CU1/CR`。pyqpanda 实测可解析的写法是参数后置形式：

```text
CR q[a], q[b],(θ)
```

因此无需把 `cu1` 展开成两个 `CNOT` 和三个单比特相位门。若未来某个 OriginQ 执行入口不接受 `CR`，再使用 `gate_identities.md` 第 4 节的标准分解；不要在当前共同支持集仍可用时提前增加门数。

## 代码如何表达这张表

实现位于 `starter_kit/qasm_L1/gates.py`。代码不再为特殊门建立零散的渲染函数，而是用两张结构相同、可直接对照本表检查的映射：

- `BRAKET_GATES`：输入门名映射到 Braket 实测可执行门名；
- `ORIGINQ_GATES`：输入门名映射到契约与 pyqpanda 的共同门名。

每个表项都是一个 `GateRule`：

```python
@dataclass(frozen=True)
class GateRule:
    name: str
    fixed_params: Optional[Tuple[float, ...]] = None
```

`name` 是最终输出的目标门名。通常沿用输入参数；只有等价改写需要设置 `fixed_params`。例如：

```python
BRAKET_GATES = {
    "sdg": GateRule("si"),
    "tdg": GateRule("ti"),
    "cx": GateRule("cnot"),
    "cu1": GateRule("cphaseshift"),
    "ccx": GateRule("ccnot"),
    # 其余 7 门也在实际代码中逐项列出
}

ORIGINQ_GATES = {
    "sdg": GateRule("RZ", fixed_params=(-math.pi / 2,)),
    "tdg": GateRule("RZ", fixed_params=(-math.pi / 4,)),
    "cx": GateRule("CNOT"),
    "cu1": GateRule("CR"),
    "ccx": GateRule("TOFFOLI"),
    # 其余 7 门也在实际代码中逐项列出
}
```

转换器只保留一套统一流程：先按输入门名取得 `GateRule`，再选择原参数或 `fixed_params`，最后按目标格式放置参数。平台级格式规则是：

| 平台 | 参数位置 | 行结束符 |
|---|---|---|
| SpinQ / Braket | 门名之后、比特之前，如 `rz(θ) q[0];` | `;` |
| OriginQ | 比特之后，如 `RZ q[0],(θ)` | 无 |

因此，门的语义差异只出现在映射表里，QASM 与 OriginIR 的语法差异只出现在平台配置里。渲染器不再判断某个映射值是字符串还是函数，也不再为 `sdg`、`tdg`、`cu1` 分别走特殊分支。

三张门表都通过完整性断言与 12 门白名单比较。以后白名单增加门但某个平台忘记添加映射时，模块加载和测试会立即失败，而不会到模拟器执行阶段才发现漏项。
