# LoomQ L2 / L3 最小得分实现设计

## 目标和边界

在保留已通过的 L1 转译器和真机证据的前提下，实现赛题客观评测所需的 L2 与 L3 接口。

- L2：`adapter.agent_chat(prompt) -> str` 必须通过组织方注入的 OpenAI 兼容端点完成至少一次模型调用，并稳定处理电路生成、QASM 修复与后端选择。
- L3：`adapter.compile_hybrid(hybrid_qasm) -> (list[str], str)` 必须编译随机生成的 Hybrid-QASM；经典部分在给定测量位输入下与语义一致。
- 交互部分只提供一个可运行 CLI，不建设网页或数据库；不使用新的第三方依赖。

## 方案选择

采用本地确定性校验 + 最少 LLM 调用的组合：L2 仅将自然语言理解交给组织方模型，关键输出由本地解析与校验把关；L3 采用小型词法/递归下降解析器和直接代码生成。这样覆盖随机评测，而不依赖公开题目的字符串模板。

## L2 架构

新增 L2 模块，`adapter.agent_chat` 只负责委派。

1. 读取现有 `LOOMQ_LLM_*` 环境变量，通过 `llm_client.chat_completion` 发起一次非流式、temperature 为 0 的请求。
2. 系统提示词要求输出简洁文本，电路必须是完整 OpenQASM 2.0，后端必须使用 `backend_capabilities.json` 内的 canonical id。
3. 将用户请求、后端能力和输出格式要求组成消息。后端能力在运行时读取，避免写死具体平台或设备。
4. 从模型回复提取 QASM 或后端 id：QASM 用现有 L1 解析器校验；后端 id 仅接受能力表中的值。
5. 首次回复不合格时，最多一次带具体校验错误的修复请求；最终回复始终包含模型的有效结果或清晰、不含密钥的错误信息。
6. 提供 `python -m starter_kit.l2_cli`：接收一行 prompt，打印 answer，异常给出可操作的配置提示。

不在 L2 中调用真实量子设备；评分所需为组织方 LLM 调用和输出质量。

## L3 架构

新增 Hybrid-QASM 编译模块，分为四层：

1. **分段器**：识别并移除 `classical { ... }` 块，把量子操作规范化为 `list[str]`，保留门和测量的原始执行顺序。由于赛题允许测量后的量子门，校验时构造一个把所有测量暂移到末尾的副本交给现有 OpenQASM 解析器；返回值仍保持原始顺序。
2. **经典词法/语法解析器**：支持整数、`r1..r9`、`c[k]`、赋值、`+`、`-`、`==`、`!=`、嵌套 `if/else` 和顺序语句，生成小 AST。
3. **RISC-V 发射器**：`rN -> xN`，`c[k] -> x(10+k)`；仅发射 `li/add/sub/addi/beq/bne/j` 与标签。使用 x28-x31 作为临时寄存器，避免改写输入测量寄存器。
4. **错误处理**：错误包含行/列和原因；拒绝超出题目定义的变量、操作符、未配对括号或不合法 OpenQASM。

条件以“条件不成立则跳转 else”的形式生成：`==` 使用 `bne`，`!=` 使用 `beq`，then 末尾无条件 `j` 到结束标签。表达式通过立即数优化生成 `li/addi`，其他情形用临时寄存器与 `add/sub`。

## 测试与验收

先写失败测试，再实现。

- L2：模拟 OpenAI 端点/客户端，断言环境读取、至少一次调用、GHZ QASM、修复 QASM、动态 canonical backend id、无密钥泄露、CLI 错误恢复。
- L3：覆盖各运算符、测量位映射、if/else、嵌套分支和多语句；用 `TinyRISCVEmulator` 枚举测量位输入比较最终 x1-x9；验证量子操作序列。
- 回归：运行现有 L1 公开 evaluator 与全量测试；启用 `submission.yaml` 的 l2/l3 后运行 public evaluator。

## 非目标

- 不承诺在没有组织方 LLM 凭据的本机上完成真实 L2 请求。
- 不实现题目范围外的 OpenQASM 3、循环、函数、浮点或完整 RISC-V。
- 不将 API Key、真实请求正文或供应商凭据写入版本库和 evidence。
