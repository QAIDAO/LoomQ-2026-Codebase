# QUANTUM 101 · 从一次可以运行的故事开始（30 分钟版）

> 先看见一个结果，再沿着结果追问：一个量子比特是什么，`H` 做了什么，Bell 电路为什么常出现 `00/11`，以及怎样从更多测量方向获得更完整的证据。

你不需要先学完整门量子力学。LoomQ 会让你先运行实验，再把直觉和形式表达一层层接上：程序层面，它仍是一项熟悉的翻译与验证工作；科学层面，每份结果也必须说明自己证明了什么、没有证明什么。

## 先沿着故事走一遍

1. **先看见一个结果**：运行本地 Bell 示例，得到一份真实 SDK 返回的 counts。
2. **认识一个量子比特**：测量前，它用一组复振幅描述可能性；测量后，你只会读到一个经典结果。
3. **加入 `H` 门**：直觉上，它把从 `|0⟩` 出发的量子比特准备成均匀叠加；重复测量后，0 和 1 会以各约一半的频率出现。需要准确表达时，再使用 `H = 1/√2 [[1, 1], [1, -1]]`。
4. **构造 Bell 电路**：`H q[0]` 后接 `cx q[0], q[1]`，再重复测量，常会看到 `00` 与 `11` 占主导。
5. **停在证据边界前**：只有计算基的 `00/11` 相关性还不能单独证明纠缠，因为经典混合也可能给出同样的统计图样。
6. **继续取证**：换测量基、做纠缠见证或量子态层析，才能回答关于相干性和纠缠的更强问题；真机结论还需要可追溯任务与原始结果。

## 一、五个概念，用程序员的话说

| 术语 | 教科书说法 | 你只需要这样理解 |
|---|---|---|
| 量子比特 (qubit) | 量子叠加态的载体 | n 个 qubit 的系统 = 一个长度 2ⁿ 的复数数组（状态向量）。qubit k 就是数组索引的第 k 个二进制位 |
| 量子门 (gate) | 幺正变换 | 对这个数组做一次矩阵运算。`h`、`x`、`cx` 只是函数名，SDK 帮你算 |
| 电路 (circuit) | 量子算法的图形表示 | **顺序执行的指令列表**——就是一段汇编。你的转译器做的事和汇编方言互转一模一样 |
| 测量 (measure) | 波函数坍缩 | 按 `abs(数组元素)²` 加权，随机采样出一个二进制串 |
| shots | 重复制备与测量 | 同一程序跑 N 次采样，返回直方图。`counts: {"00": 498, "11": 526}` 就是采样 1024 次的结果 |
| 纠缠 (entanglement) | 联合量子态不能写成各子系统状态的乘积或经典混合 | Bell 目标态在计算基中会给出强 `00/11` 相关性；但这张直方图本身不是纠缠证明，还要观察其他测量基中的相干信息 |

这些概念足以开始实现本题。后续章节会把直觉对应到 QASM、位序、保真度和可验证的程序行为。

## 二、10 分钟读懂 OpenQASM 2.0

这是你要翻译的"源语言"。逐行看 `circuits/bell.qasm`：

```text
OPENQASM 2.0;           // 版本声明，固定写法
include "qelib1.inc";   // 标准门库，类似 #include <stdlib.h>
qreg q[2];              // 声明 2 个量子比特（数组长度变为 2²=4）
creg c[2];              // 声明 2 个经典比特，存测量结果
h q[0];                 // 对 q0 施加 Hadamard 门（制造 50/50 叠加）
cx q[0], q[1];          // 受控非门：q0 为 1 时翻转 q1（制造纠缠）
measure q -> c;         // 测量全部 qubit，结果写入 c
```

你需要处理的语法**只有这么多**：版本行、include、两种寄存器声明、门调用（可带参数，如 `rz(0.5) q[1];`）、measure。没有循环、没有条件、没有自定义函数。

**门白名单**：全部评测电路（含隐藏电路与评测日变体）只使用 12 个标准门——
`h, x, s, sdg, t, tdg, rz(θ), ry(θ), cx, cu1(θ), swap, ccx`。
不会出现白名单之外的门。逐个查一遍每家 SDK 对这 12 个门的支持，就是 L1 的完整工作量清单。

## 三、counts 与位序（本题最容易踩的坑）

大赛统一约定（Qiskit 风格）：**counts 的 key 最右侧字符是 `c[0]`**。

```text
key = "10"  含义: c[1]=1, c[0]=0
```

不同平台原生返回的位序可能相反——把它们归一化成统一约定，正是你的中间层的职责之一（也是送分点：这是纯字符串处理）。

## 四、保真度：你的"测试通过率"

题面里那个 Hellinger 公式**不需要你实现**，`evaluator.py` 已经写好了。直觉版：

> 把你的 counts 归一化成概率分布，和标准答案比"相似度"，**≥ 0.97 通过**。

它实际上是二值判定：转译正确时采样涨落只会让它落在 0.99 左右；任何一个门翻错，它会跌到 0.9 以下。不存在"差一点点"的灰色地带，对了就是对了。

## 五、测试电路都是什么（人话版）

| 电路 | 人话 | 理想输出 |
|---|---|---|
| Bell / GHZ-3 / GHZ-5 | 目标态在计算基中的强相关结果；仅凭这组 counts 不能单独认证纠缠 | 50% 全 0，50% 全 1 |
| QFT-4 | 量子版傅里叶变换，考**相位**转译精度 | 恰好 4 个 25% 的峰 |
| Grover-3 | 在 8 个抽屉里"放大"正确答案的概率 | 94.5% 概率开出 `111` |
| Random ×3 | 随机指令流，考门集覆盖完整性 | 各不相同（评测系统算好了） |

你不需要理解这些算法**为什么**有效，只需要保证每条指令被忠实翻译——译者不必赞同原文观点。

## FAQ · 新手恐慌自查

**Q: 我需要线性代数很好吗？**
不需要手算任何矩阵。你的角色是调度矩阵运算的人，不是执行者。

**Q: 隐藏电路会不会出现我没见过的门？**
不会。12 个门的白名单写进题面了，评测日变体同样受白名单约束。

**Q: 某个后端说不支持门 X 怎么办？**
翻开 `gate_identities.md`，把 X 按恒等式改写成基础门——公式可以直接照抄，全部经官方参考模拟器验证。

**Q: 真机听起来很吓人？**
真机是加分阶梯，不是资格线：两个模拟器后端跑通公开电路就有评奖资格。而且各家 SDK 里"提交真机"和"提交模拟器"通常是同一个 API 换个参数。

**Q: 题面里的数学公式看不懂？**
全题面只有一个公式（Hellinger 保真度），它已经在 `evaluator.py` 里实现好了，你永远不需要自己写。

## 页面阅读合同

页面遵循“先看到现象，再命名，再给边界”的顺序。五分钟内，零基础读者应能这样复述：

1. bit 记录 0 或 1；qubit 是量子信息的一个单位，测量后仍读出 0 或 1。
2. 测量会把一次运行变成一个经典读数；重复运行才会显出统计比例。
3. H（Hadamard）作用在从 `|0⟩` 出发的 qubit 上，重复测量会让 0 与 1 各约占一半。
4. CNOT 读取控制位的计算基规则：控制位为 0 时目标位保持，控制位为 1 时目标位翻转；页面先展示这张规则表，再展示 Bell 结果。
5. shots 是重复同一电路并累计 counts 的次数；次数更多，比例通常更稳定。
6. Bell 电路先做 H，再做 CNOT；理想计算基测量主要留下 `00` 与 `11`，各约一半。
7. X/Y/Z 是三种测量基；换方向是在收集同一个量子状态的更多信息。
8. tomography 把多个基的测量数据合在一起，重建密度矩阵这一整态描述。
9. Fidelity `0.952449` 是重建状态接近目标 Bell Φ+ 的点估计，越接近 1 越接近目标。
10. 第一次实验：打开本地服务，点“重做刚才的 Bell 实验”，保留 1024 shots，点“运行这个实验”，再查看 counts、电路、OpenQASM、验证和证据边界。

页面还明确写出：`Czz = 0.99955`、`Cxx = 0.99956`、`Cyy = -0.99865` 属于三个独立归档作业；本页只回放证据，没有提交新的硬件任务。`PPT λmin = -0.4561` 的纠缠判断适用于该 2×2 重建点估计，归档数据没有逐次采样不确定性模型，因此不声明统计置信区间。
