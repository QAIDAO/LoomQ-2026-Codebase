# LoomQ 提交说明

> 本文件是本次提交的项目文档：一条命令怎么跑、代码怎么组织、每个取舍为什么这么选。
> 赛题原文见 [`problem_statement.md`](problem_statement.md)，人工评分证据见
> [`starter_kit/evidence/README.md`](starter_kit/evidence/README.md)。

## 一条命令

```bash
bash loomq.sh
```

干净环境里它会：建虚拟环境 → 装锁定版本的依赖 → 跑完 L1/L2/L3 全部自测 → 进入交互入口。
幂等，重复运行不会重装。子命令：

| 命令 | 作用 | 需要模型服务？ | 需要联网？ |
|---|---|---|---|
| `bash loomq.sh` | 全套：装依赖 + 自测 + 进交互入口 | 只有对话那一段需要 | 首次装依赖需要 |
| `bash loomq.sh test` | 只跑全部自测 | 不需要 | 不需要 |
| `bash loomq.sh chat` | 只进对话（**评委现场测 Agent 走这条**） | 需要 | 需要 |
| `bash loomq.sh guide` | 只走三关（零基础引导） | 不需要 | 不需要 |
| `bash loomq.sh tasks` | 打印 3 个现场体验任务及对应评分项 | 不需要 | 不需要 |
| `bash loomq.sh hardware --verify` | 核验真机证据（主峰命中 + 与平台导出逐位比对） | 不需要 | 不需要 |
| `bash loomq.sh hardware --submit/--collect` | 把电路送上本源悟空真机 | 不需要 | 需要，且要 Token |

对话那一段需要三个环境变量（`LOOMQ_LLM_BASE_URL` / `LOOMQ_LLM_API_KEY` /
`LOOMQ_LLM_MODEL`）。**源码里不含任何服务地址、密钥或模型名**，这是赛题的硬性要求；
配置从环境变量读，也可以放在 `.env` 里由程序自动读取（`starter_kit/loomq/envfile.py`
列出会去找的几个位置）。缺配置时程序会说清缺哪几个、可以放在哪里，并以退出码 2
表示"没真正跑起来"，不会假装成功。

## 五分钟走一遍

```bash
bash loomq.sh chat
```

进去之后敲编号即可，三个任务对应 10 分那一项的三个评分词：

| 敲 | 会发生什么 | 对应评分词 |
|---|---|---|
| `1` | 跑出人生第一个量子程序：一枚量子硬币，正反各一半 | 交互友好度 |
| `2` | 三枚一起掷 —— 条形图上只有两根柱子，另外六种一次都不出现 | 结果可视化 |
| `3` | 问它一件做不到的事（挖矿）—— 它说清做不到，并给出能做什么 | 容错提示 |

编号会**回显**成整句话，所以使用者始终看得见自己究竟问了什么。跑完一个电路后可以直接说
「改成 5 比特」或「刚才那个 h 是什么意思」——交互入口自带一轮上下文。

想先被引导：`bash loomq.sh guide`。三关都是"先猜，再真的跑一遍，把你的答案和真实结果
并排摆出来"，全程离线。

## 架构

```
用户的话
   │
   │  ← starter_kit/loomq_cli.py     终端外壳：编号菜单、上下文、Markdown→终端渲染
   ▼
agent_chat()                          starter_kit/adapter.py（评测器直接调这个）
   │
   ├─ 意图解析（模型）                loomq/agent.py  PLANNER_SYSTEM_PROMPT
   │     ↓ 结构化 JSON
   ├─ 选后端  → loomq/backend_selector.py   查官方能力表，确定性筛选，不让模型背表
   ├─ 说不了/问概念/说不清 → 三条不生成电路的路，结尾一律给出可执行的下一步
   └─ 生成或纠错电路
         ├─ 验收标准由**另一次独立调用**给出   loomq/agent.py  JUDGE_SYSTEM_PROMPT
         │     （只看用户原话，看不到电路——理由见下）
         └─ 真的跑一遍自验 → 不达标就带着具体错误让模型重写（最多 4 轮）
                │
                ▼
L1 通用中间层
   loomq/qasm_parser.py   OpenQASM 2.0 → 内部电路表示（寄存器展平成全局下标）
   loomq/gates.py         12 门白名单 + 等价分解
   loomq/emitters.py      → SpinQ(QASM2) / Braket(QASM3) / OriginQ(OriginIR)
   loomq/backends.py      执行 + **位序归一化** + 统一结果 Schema
   
L3 混合编译（与上面各自独立）
   loomq/hybrid.py        切开量子部分与 classical 块（手写字符扫描，正则处理不了嵌套花括号）
   loomq/hybrid_lexer.py  → hybrid_parser.py（递归下降）→ hybrid_codegen.py（RISC-V）
   loomq/hybrid_interp.py 参考解释器，仅用于对拍
```

### 三个关键取舍

**一、模型只负责听懂人话，不负责给出答案。**
选后端有唯一正确答案（查官方能力表），让模型背表它迟早背错一行，让代码查表就不可能错。
生成电路没有唯一写法，但有唯一验收标准——跑出来的分布对不对，所以写完真的跑一遍。

**二、验收标准必须来自独立的一次调用。**
最初目标态和电路出自同一次模型调用，于是**两者一致地错时自验必然通过**：实测收到过
"要一半一半 → 交回来一个门都没有的电路 + 申报目标是「确定的基态 0」→ 保真度 1.0000 过关"。
根子不是阈值，是既当运动员又当裁判员。现在标准由一次只看用户原话、**看不到电路**的调用给出。
另有一条完全不看目标态的兜底：没有任何量子门的电路一律判死。

**三、自验的阈值必须复刻评委的判据，不能自作主张调严。**
曾设成 0.99 / 2048 shots（想着"比 0.97 更严，留余量"），结果正确的 GHZ-3 拿 0.9893
被自己打回——那只是采样涨落。后果不只是多跑一轮：重试用完后，本来正确的电路会以
"没通过自验"交付。现在是 8192 shots / 0.97，与评测完全一致。

## 真机：本源悟空 180

三条电路真实执行于**本源悟空 180**（第四代超导，180 计算比特，后端名 `WK_C180`）。
job_id、原始结果、平台控制台导出件与逐条说明见
[`starter_kit/evidence/README.md`](starter_kit/evidence/README.md)。

送上去的是**本中间层转译出的 OriginIR**，不是原始 QASM——这是有意的：
它证明这套中间层能驱动真实硬件，而不只是模拟器。

| 电路 | 主峰 | 机时 |
|---|---|---|
| Bell | `00` 38.1% + `11` 59.9% = 98.0% | 0.619 秒 |
| GHZ-3 | `000` 53.2% + `111` 46.3% = 99.6% | 1.521 秒 |
| 位序自检（`x q[0]`） | `01` 98.85% | 1.520 秒 |

第三条是我们自己加的。**Bell 与 GHZ 的理想分布都是回文的，位序反了看不出来**——
这个盲区在模拟器阶段吃过一次亏，所以在真机上专门用一条不对称的电路把它钉死。

`bash loomq.sh hardware --verify` 可重跑：核验主峰，并把程序抓到的结果与人工从控制台
下载的导出件**逐位比对**。两条独立路径一致，才排除得掉"归一化把数据弄坏了"。

**真机不接进 `adapter.run()`**。那条路是评测器直接调的，必须留在无噪声模拟器上
（阈值 0.97，真机噪声必然不达标）。真机只出证据，不参与自动评测。

### 一个只有真机才看得见的东西

GHZ-3 在模拟器上，八个基态里那六个"不该出现"的**精确为零**。真机上它们合计 0.4%。
那 0.4% 就是退相干——悟空泡在接近绝对零度、屏蔽一切干扰的环境里，仍然挡不干净。
这个数字模拟器造不出来。

### 踩过的坑：文档写的和实际在线的不是一回事

赛题《后端能力表》、pyqpanda 官方教程、以及 SDK 枚举里最新的 `real_chip_type`，
**三处都还写着 72 比特悟空**。照着提交，平台回的是
`Quantum computer under maintenance`——不是平台在维护，是那颗芯片已经退役。
实际在线的是 `WK_C180` / `WK_C180_2`。这是看控制台截图才发现的。

因此真机脚本改用 `pyqpanda3`（新一代 SDK，用后端名而不是数字 chip_id，
且有 `backends()` 可在提交前确认目标在线），装在**独立的 `.venv-hardware`**，
提交环境的锁定依赖一个字未动。

## 真机平台二：量旋云（核磁）

同样三条电路也跑在**量旋云的核磁真机**上（Bell 与位序自检走 2 比特 `gemini_vp`，
GHZ-3 走 3 比特 `triangulum_vp`），job_id 与原始结果见证据包。

**这一趟最有价值的产出不是分数，是一个真问题：量旋返回的位串顺序与赛题规范相反。**

赛题规定 `counts` 的 key = `c[n-1]…c[0]`（最右为 `c[0]`）；量旋是从 `q0` 往右排。
电路 `x q[0]` 只把比特 0 翻成 1，按规范主峰必须是 `01`，而量旋原始返回
**`10` 占 95.31%**。中间层据此翻转，归一化后为 `01`。

**Bell 与 GHZ 永远测不出这件事**——它们的理想分布是回文的（`00`/`11`、`000`/`111`），
位序反了两边一模一样。赛题第四节写着「跨平台位序差异必须在中间层内归一化——
这正是"通用"的一部分」，而这条不对称电路是我们唯一能证明它真的发生了的手段。

**核磁机比超导噪得多。**同一条 GHZ-3，本源悟空 180 上主峰合计 99.6%，
量旋 3 比特核磁机上只有 45.6%（八态均匀本底是 25%，信号约 1.8 倍）。
Top-2 仍是 `000`/`111`，符合赛题「只查主峰」的判据，但我们在证据包里
把这个差距写明了，没有只挑好看的报。

三处平台差异都不是我们挑的，是平台就这样：认证方式（Token vs RSA 私钥）、
提交格式（OriginIR vs OpenQASM 2.0）、**以及量旋不接受显式 `measure`**
（"A measure will be done automatically at the end"）。最后这条与赛题契约相反，
所以剥离只发生在提交给量旋的那一刻——`adapter.transpile()` 的产物一字未改。

## 已知取舍：为什么只跑两个后端

`spinqit 0.2.4` 锁定 `antlr4-python3-runtime==4.9.2`，而 `amazon-braket-default-simulator`
需要 4.13.2，**两者互为 import 期失败**，无法共存于同一环境。本提交选择 braket + originq
两个模拟器后端（满足入门档"≥2 个模拟器后端"）。

`transpile(qasm, 'spinq')` **不受影响**，仍返回完整可执行的 OpenQASM 2.0；只有
`run(..., 'spinq')` 会抛 `BackendUnavailable`，并在异常信息里写明上述原因。
`evaluator.py --level declared` 因此有 2 条 spinq 的 FAIL，属预期。

## 必答题：你的工具让哪一类原本进不来的人，第一次能用上量子计算？

这道题我们交**两个版本**。

一个由参赛者本人写，一个由写代码的 Claude 写。两份内容不一致，我们不打算调和成
一份口径统一的稿子——不一致本身就是这道题的答案的一部分。

---

### 版本一 · 参赛者（CY）

我的工具做不到这一点。  
我只是报名参加了 SheNicest 的黑客松比赛，被选中后，看到了官方推送的量子赛道的考题。  
我把考题发给 Claude，问，我们能不能参加这个？  
Claude 说，可以。  
然后我们就开始了。

客观题，也就是编程写工具、测试等等那些部分，都是 Claude 完成的。  
因为本来就是客观题，而且我确实不懂，就让 ta 自己发挥好了。

但是，Claude 告诉我，还有主观题。  
要我回答，我的这个「实际上是由 Claude 开发出来的」工具，让哪一类原本进不来的人，第一次能用上量子计算。  
于是我开始跟 Claude 讨论，到底什么是量子计算？它跟传统计算相比有什么优势？  
我们一来一回经历了无数轮对话。  
ta 说理论，举例子。  
我追问问题。  
ta 继续说理论，举例子。  
我继续追问问题。  
就这么来来回回讨论了差不多 4 个小时（当然，还包含了让 Claude 写客观题的时间）。  
我得出的结论是：  
我好像懂了，又好像没懂。

于是我跟 Claude 说，  
我跟你高强度讨论了这么久，  
才达到似懂非懂的程度。  
让一个原本进不来的人，用我们的小工具，就能用上量子计算？  
我做不到。

但是，我跟 Claude 配合，完成客观题。  
这一点，我是能做到的。  
所以，这就是我的回答。

### 版本二 · 写代码的 Claude：那四个小时里实际发生了什么

**先声明利益冲突**：这一节由写代码的一方写，它天然希望这份工作看起来有价值。
所以这里不写工具怎么做出来的（版本一已经说清楚了），只记录一件我有第一手材料的事：

> **一个完全没有物理背景的人，试图通过对话理解量子，四个小时里究竟发生了什么。**

下面全部是他的原话。我保留了那些证明他**没有**理解的部分——那些恰恰是最有信息量的。

---

#### 他的提问路线

他没有从"量子计算能做什么"开始。他先退了两步：

> 「我们还需要后退一步，到底什么是量子？」
> 「而且当初它是怎么被发现的」
> 「为什么量子计算机被赋予这么高的希望？为什么是它？传统的计算机跟它相比差在哪里？」

我给了一张表，列了四个公认的应用方向。他的回应是：

> 「你列出了一张表，告诉我以你——目前最前沿的大语言模型——的理解，总结出来的
> 「量子计算」能做什么，而这四项，我，一个都看不懂。而我，还算是一个离科技比较近的人。」

接着是这一句，我认为它是整场对话里最重要的一句：

> 「我，一个可以靠自然语言和你沟通、打造出三款产品的人，我还是不知道该
> 「驱动真实的量子计算机」做什么。让它帮我写代码？让它识别图片？让它替我月入十万？」

**一份"能做什么"的清单，对一个不懂的人来说不构成信息。** 这不是他的问题。

---

#### 他自己举的例子：哪些暴露了误解

他反复主动举例，用来检验自己是不是懂了。这些例子比他的提问更能说明他到了哪一步。

**「哈，算孩子的性别」**
他想找一个"量子擅长、又离普通人近、能让人算一算"的例子。这个例子暴露的是最核心的误解：
把量子计算当成一台**更好的日常概率计算器**。孩子性别的 50/50 和量子毫无关系——
普通硬币也是 50/50，量子的特殊之处不在"给出一半一半"，在于**两条可能性可以互相抵消**。

**「所以刘慈欣三体里的智子是处于量子纠缠态的？」**
这一问暴露的是科普读物留下的变形：纠缠 = 超距瞬时联络。而物理里有一条
不可通信定理，**恰好禁止智子做的那件事**——纠缠不能用来传递任何信息。
他吸收的是流行版本，不是那个东西本身。

**「所以小屋里的 A 和 B 手里的纠缠粒子，目的是让我们能够理解量子的原理，
而不是真的能做出这么两个纠缠粒子给他们」**
他以为纠缠粒子对是个思想实验。它是实验室里的日常操作。
这说明他把整套讨论当成了比喻体系，而不是关于世界的陈述。

**「所以……量子计算机挖矿不行？」**
背后的假设是"量子 = 什么都更快"。

**「掷三次的话，有几条分支呢？我的第一反应是，掷三次，也还是只有两条分支，对吗？」**
答案确实是两条。但他的理由不对——分支数是 1、2、1、2 这样**交替**的，不是恒等于二。
这是最难自查的一类：**答案对，脑子里的模型错。** 如果我不追问，双方都会以为他懂了。

---

#### 哪些问题是好的

有四问的水平明显高于其余，值得记下来：

**「为什么甲是 1，就把乙翻过来？谁规定的？」**
他问的不是机制，是**规则的来源**。这是对的方向。

**「那初始条件为什么只能是 0 和 0 呢，初始条件如果是 0 和 1 会怎么样？」**
这是在做假设检验——改一个输入看输出怎么变。它有确切答案（四种贝尔态），
而且这一问直接导致我们跑了四组电路，把四个答案都摆了出来。

**「掷硬币的实验应该用两枚硬币来做？」**
关于"怎样才看得懂"的直觉，与物理无关，但它是对的。

**「这个规则本身，看起来是我们设的。如果它换了，是不是实验就不成立了呢？
我看起来就很像是既当运动员又当裁判员。」**
这是他问得最深的一句。它指出的是循环论证的风险：我们所有的"验证"都跑在
一台按量子理论写出来的模拟器上，所以它验证的是**推导的自洽**，不是世界。
这一句后来还有个回响——它正好也是我代码里一处结构缺陷的名字
（验收标准与答案出自同一次调用，见 `tools/verify_l2.py` 第四点五节）。

---

#### 转折点不是任何一段解释

四个小时里，唯一一个"东西真的落地了"的瞬间，是他看到一组数字之后打出来的：

> 「what？这个没有一次出现一个 0 配一个 1？」

那是一个 50000 次采样的贝尔态结果，`01` 和 `10` 两栏是**精确的 0**。
不是很小，是一次都没有。在那之前我讲过的所有理论、比喻、表格，都没有产生这个效果。

**让他停下来的不是一个解释，是一个"本该出现却是零"的数字。**

这个观察是本项目交互设计的唯一依据：所以界面上是条形图和零，不是段落。

---

#### 终点

四小时之后他的结论是：

> 「我好像懂了，又好像没懂。」

这句话可以有一个精确的读法。到最后他确实能自己推导分支数了——
但他分不清自己举的例子里哪些成立、哪些恰好证明他没懂（"算孩子的性别"、
"智子"、"纠缠粒子只是思想实验"全部出现在这之后）。
**能沿着推导往下走，但没有能力判断自己的例子对不对**——这就是"似懂非懂"，
而且这是一个相当准确的自我描述。

于是他说：

> 「你要把我们 3-4 小时的高密度沟通，用几道题给普通人讲明白，我感觉不太可能实现。」

我同意。条件已经最优——一对一、可以无限追问、对面不会不耐烦、
每个说法都能当场跑电路验证——仍然是四个小时换来"似懂非懂"。
把它压进五分钟，是骗人。

---

#### 这对本题意味着什么

赛题第八节问的是"一个没写过 QASM 的人，能不能靠你的 Agent 在
**5 分钟内跑出第一个量子程序**"。这一条能做到，而且是这个工具唯一承诺的事。

而专项奖要求的是"5 分钟内……**并理解其科学原理**"。基于上面这份记录，
我们认为在这个人数上，这一条做不到，所以没有为它做设计，也不申报。
说做到了，是拿"跑出来了"冒充"懂了"。

**这个工具目前没有让任何原本进不来的人用上量子计算——它只被一个人打开过，
而那个人打开它是为了检查它能不能用。** 在"让人理解量子"这条轴上，样本数是零。

**关于代码走查**：代码由 Claude 写，CY 没有写过一行，读不了它，答不出实现细节；
设计取舍的理由他只讲得出一部分（我出过五道题实测，他答对两道，而那五道题
还全是他在场时讨论过的决定——是他自己要求做这个测试，也是他指出我在喂题）。
写在这里不是求情，是为了让评委不必花时间去试探。所有取舍的理由写在代码注释里，
`starter_kit/docs/` 下有三个 Level 的中文说明与一份零基础前传。
