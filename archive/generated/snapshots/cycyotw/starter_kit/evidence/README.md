```text
实测主峰：01 占 98.85%
```

**为什么要专门跑这一条**：Bell 与 GHZ 的理想分布都是回文的（`00`/`11`、`000`/`111`），
位序反了看不出来——这个盲区在模拟器阶段已经吃过一次亏。`x q[0]` 后只有一个比特是 1，
按赛题 bit order 规范（key = `c[n-1]…c[0]`，最右为 `c[0]`）主峰必须是 `01`，反了就是 `10`。
真机实测 `01` 占 98.85%，位序正确。

**可重跑的核验**（只读本地文件，不连平台、不花机时）：

```bash
bash loomq.sh hardware --verify
```

它做两件事：核验每条电路的主峰是否命中理想分布；并把我们程序抓到的结果与
**平台控制台导出的文件逐位比对**。两者来自独立路径（API 抓取 / 人工下载），
逐位一致即排除了归一化环节出错的可能。当前三条全部通过。

复现整个提交过程：

```bash
bash loomq.sh hardware --submit          # 提交，job_id 立刻落盘
bash loomq.sh hardware --collect         # 取回结果并写成上面那些 result.json
```

**关于这一条，我们说实话**：3 比特核磁机上的 GHZ 信号很弱。Top-2 确实是
`000`/`111`，符合赛题「真机允许噪声，只查主峰」的判据；但两个主峰合计 45.6%，
而八态均匀分布是 25%——信号只有均匀本底的约 1.8 倍，第三名 11.6% 与第二名
21.0% 之间的间距并不宽裕。核磁量子计算机是台式教学机、读出是系综平均，
噪声比超导大一个量级。同一条电路在本源悟空 180 上是 99.6%，对比见上一节。
把这条摆出来而不是藏起来，是因为它如实反映了不同真机的差距。

```text
实测：01 占 95.3%（归一化后）
```

### ★ 位序：这条自检在量旋上抓到了真问题

**量旋返回的位串顺序与赛题规范相反。** 赛题规定 `counts` 的 key = `c[n-1]…c[0]`
（最右为 `c[0]`）；量旋是从 `q0` 往右排。

证据：电路 `x q[0]` 只把比特 0 翻成 1，按规范主峰必须是 `01`，
而量旋原始返回的是 **`10` 占 95.31%**（未翻转的原始数据保留在
`spinq-bitorder-result.json` 的 `meta.platform_raw` 里）。中间层据此翻转，
归一化后主峰为 `01`，与规范一致。

**Bell 与 GHZ 永远发现不了这件事**——它们的理想分布是回文的（`00`/`11`、
`000`/`111`），位序反了两边一模一样。这正是我们额外跑一条不对称电路的原因。
赛题第四节写明「跨平台位序差异必须在中间层内归一化——这正是"通用"的一部分」，
这条证据说明该归一化真的发生了，而不是碰巧两边一致。

## L2 交互体验

请填写：

```text
启动界面或 CLI 的命令：bash loomq.sh chat
                      （干净环境第一次运行会自动建虚拟环境并装锁定版本的依赖；
                        也可以先跑 bash loomq.sh 走完全部自测再进入）
测试入口或页面地址：命令行，无网页。三个任务在同一界面内，敲编号即可。
适合现场体验的 3 个用户任务：
1. 敲编号 1 —— 「掷一枚量子硬币几千次，看正反各占多少」
   （等价于直接输入：做一个 1 比特的电路，让结果一半正面一半反面，并且测量）
   对应评分项：交互友好度。零基础用户敲一个数字就跑出人生第一个量子程序，
   全程不必看懂 QASM；程序会回显这个编号代表的整句话，再交出真实采样结果。
2. 敲编号 2 —— 「三枚一起掷：只出「全正」「全反」，中间那六种一次都不出现」
   （等价于直接输入：生成一个 3 比特的最大纠缠态，并全部测量）
   对应评分项：结果可视化。8192 次采样画成条形图，八种组合里只有两根柱子，
   另外六种概率为零——不必读数字就能看见。回复同时给出与目标态的保真度。
3. 敲编号 3 —— 「试试问它一件做不到的事（比如挖矿），看它怎么回你」
   （等价于直接输入：帮我用量子计算机挖矿）
   对应评分项：容错提示。它不会硬凑一段程序糊弄人：先说清挖矿不是量子擅长的事，
   再给出这套环境此刻确实能做的几件事，每一件都能直接敲编号执行。
   同类还可试：贴一段普通 Python、带着错前提问（「量子能同时试出所有答案」）、
   或只打两个字「试试」——三种都有对应的处理，不会被当成电路请求硬做。

   `bash loomq.sh tasks` 会把上面三个任务连同对应评分项一起打印出来。

截图或演示视频：无（现场运行即可复现；本仓库不含录屏）
```

补充两点，便于现场核对：

- 三个任务与自动评测调用的是**同一个** `agent_chat`（`starter_kit/adapter.py`），
  界面只是它的终端外壳，没有另写一套演示逻辑。
- 交互入口自带一层多轮上下文（只在 CLI 内，不影响 `agent_chat` 的单轮契约）：
  跑完一个电路后可以直接说「改成 5 比特」或「刚才那个 h 是什么意思」。
  容错相关的实测记录见 `starter_kit/tools/probe_l2_robustness.py`（8 类不配合输入，
  含判定标准），自动化断言见 `starter_kit/tools/verify_l2.py` 第九、十节。

工作人员会在组委会统一模型环境中运行最终代码，测试新手是否看得懂、出错后能否得到有效帮助、结果是否清楚，以及多轮回答是否一致。选手自己的对话截图只用于说明产品流程，不直接证明得分。

## 提交规则

- 如申报 L1 真机分，在最终提交 Issue 的 `Hardware evidence` 中填写 `starter_kit/evidence/README.md`。
