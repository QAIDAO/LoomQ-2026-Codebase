# L1 通用中间层 · 人话卡片

> 每张卡片回答同样三个问题——它干什么、为什么这么设计、换个输入会怎样。
>
> 如果读到某处冒出的疑问是「可是为什么非得有这一步」，那要的是更前面一层：
> 先读 [`量子是什么-零基础.md`](量子是什么-零基础.md)。

---

## 它整体在解决什么问题

三家公司做量子计算机，每家有自己一套写指令的方式——**等于三个国家说三种语言**。
为一家写的程序，在另两家跑不了。用户只能挑一家，然后被锁死在那家。

L1 就是那个翻译器。用户用通用写法写一次，它转成三家各自的方言；
三家返回的结果格式也不一样，它再统一成同一种格式。

```text
OpenQASM 2.0 文本
      │
      ├─ 解析 ──> Circuit（我们自己的中立表示）
      │              │
      │              ├─ 输出 ──> OpenQASM 2.0  (spinq)
      │              ├─ 输出 ──> OpenQASM 3    (braket)
      │              └─ 输出 ──> OriginIR      (originq)
      │                              │
      └───────────────────────────── └─ 执行 ──> 统一结果格式
```

**「统一」具体落在哪里：只有一个解析器，只有一份电路表示。**
三个后端各自只负责"把这份表示写成自己的方言"，谁都不许自己再去读一遍原文。
赛题明写"三套硬编码分支不算通用，评委会审查架构"——这就是那条线。

## 卡片 1 · `loomq/qasm_parser.py` —— 读懂用户写的电路

**干什么**：把 OpenQASM 2.0 文本读成 `Circuit`。

**为什么这么设计**

- **比特一律换成全局整数下标。** 源码里写 `qreg a[2]; qreg b[3];`，
  那么 a[0..1] 就是 0、1，b[0..2] 就是 2、3、4。这样后面所有人只跟数字打交道，
  再也不用关心寄存器叫什么名字。
- **参数在这里就算成数字。** 源码里写的是 `pi/2` 这种算式，
  三个后端的写法各不相同。与其让三个后端各自去理解算式，
  不如在解析阶段一次性算成 `1.5707963267948966`。
  （算式解析用的是和 L3 一样的递归下降写法，一条文法规则一个方法。）

**换个输入会怎样**

- `measure q -> c;`（整寄存器）会被展开成逐位的测量，效果一样。
- 缩进、注释、空行随便写。
- 白名单以外的门 → 报错并列出这 12 个门，不会默默算错。
- `measure` 两边长度对不上、比特下标越界 → 报错并指出是哪一句。

## 卡片 2 · `loomq/circuit.py` —— 中立的电路表示

**干什么**：存两件事——用了几个量子比特和几个经典比特，以及一串按顺序排好的操作。

**为什么这么设计**：刻意做到最小。它是三个后端共同的上游，
每往里面加一个字段，三个后端就都要跟着改。

里面有一个方法值得单独说：**`measure_map()`，经典比特 → 量子比特的映射。**
后端返回的结果通常按"量子比特"排，而赛题要求的结果按"经典比特"排。
而且测量语句允许错位——`measure q[0] -> c[2];` 是合法的。
所以这张映射表必须留着，不能想当然地按顺序对号入座。

## 卡片 3 · `loomq/gates.py` —— 12 个门，以及"某家不认时改写成什么"

**干什么**：存下白名单 12 个门的参数个数与比特个数，以及等价改写式。

**为什么这么设计**：赛题把工作量边界划得很死——所有评测电路，
公开的、隐藏的、评测当天新生成的，**只会用到这 12 个门**。
所以这个文件就是 L1 的全部门知识，不多也不少。

改写式抄自官方 `gate_identities.md`，**但我们又自己在真模拟器上复核了一遍**。
复核的方法是关键：**不能用普通电路照，要用干涉电路照**。
因为分解写错时，末态的"大小"往往还是对的，**只有相位错**——
普通电路看不出来，只有让它跟自己干涉，错误才会显形。
（复核结果见 `tools/verify_l1.py`，四条分解的保真度 0.991–0.999，
差值就是两万次采样的统计涨落。）

## 卡片 4 · `loomq/emitters.py` —— 写成三家各自的方言

**干什么**：`Circuit` → 目标格式文本。这就是 `transpile()`。

| target | 格式 | 长相 |
|---|---|---|
| `spinq` | OpenQASM 2.0 | `h q[0];` |
| `braket` | OpenQASM 3 | `h q[0];`，但 cx 要写成 `cnot` |
| `originq` | OriginIR | `H q[0]`，门名大写、不带分号、参数写在比特后面 |

**为什么这么设计**

每个后端认得的门**不一样**，认不得的必须先改写。而这张"谁认得谁"的表，
是**逐个门在真模拟器上试出来的，不是查文档抄的**——因为文档和实现对不上的地方有好几处：

- **braket 不认 `sdg` / `tdg` / `ccx` / `cx`**（它自己管这些叫 `si` / `ti` / `ccnot` / `cnot`）
- **originq 的 `SDAG` / `TDAG` 写在官方契约的允许门名里，但 pyqpanda 根本没实现**

所以做法是：**只输出"目标格式的规范写法"和"后端真能跑"两者都满足的门**，
其余一律按等价式改写。这样产物既符合契约，我们自己又能跑得动。

改写用的 `lower()` 是递归的，而且一定会停：所有分解式的产物都落在
`{h, x, rz, t, cx}` 这五个门里，而这五个门三家都认得。

**换个输入会怎样**：`ccx` 一个门在 braket 上会展开成 15 条指令。
电路变长不影响正确性——无噪声模拟器不在乎深度，评分也不看深度。

## 卡片 5 · `loomq/backends.py` —— 真的跑起来，并把结果格式统一

**干什么**：这就是 `run()`。送进模拟器、收回结果、统一成赛题规定的格式。

**为什么这么设计**

**送进模拟器的文本，就是 `transpile()` 返回的那份文本。**
（唯一例外是 braket 的 `include` 行，原因见下。）
这样一来，`transpile()` 一旦写错，`run()` 一定跑不对——两者不会互相掩护。

### ★★ 全项目最要紧的一件事：位序

赛题规定结果的 key 是 `c[n-1]…c[1]c[0]`，**最右边那个字符是 c[0]**。

而各家的原生约定并不一致。我们实测过——同一个电路 `x q[0]`（只翻转第 0 个比特）：

| 后端 | 两比特 | 三比特 | |
|---|---|---|---|
| originq | `01` | `001` | ✅ 合规范 |
| braket | `10` | `100` | ❌ **相反** |

**而两个公开电路 Bell（`00`/`11`）和 GHZ-3（`000`/`111`）都是回文串**——
比特顺序整个反过来，输出一模一样。所以**位序错了，公开自测照样满分**，
只会在隐藏的非对称电路（QFT-4 / Grover-3 / Random）上全灭。

因此这里没有采用"看情况翻转一下"的写法（那种写法遇到错位测量就会错），
而是**从每一次采样的原始比特重新拼出 key**：
按电路里的测量语句，把每个量子比特的结果放进它该去的经典比特位置。
这样无论后端怎么排、无论测量怎么错位，结果都对。

### 关于 braket 的 `include` 行

官方契约的 braket 范例里带着 `include "stdgates.inc";`，
但 braket 的本地模拟器会把它当成**磁盘上的文件**去找，然后报 `FileNotFoundError`。
所以 `transpile()` 保留这一行（符合契约），`run()` 执行前把它删掉。
这是全项目唯一一处"转译产物"与"实际喂给 SDK 的文本"的差别。

### 关于 spinq

`run(qasm, 'spinq', shots)` 会抛出一个说明清楚原因的异常：
spinqit 0.2.4 锁定 `antlr4-python3-runtime==4.9.2`，braket 需要 4.13.2，
两者互为 import 期失败，**在同一个 Python 环境里无法共存**。
本提交选择 braket + originq 两个后端，满足赛题「≥2 个模拟器后端」的评奖资格线。

**`transpile(qasm, 'spinq')` 不受影响**——它是纯文本转换，不需要 spinqit 这个库。

## 卡片 6 · `tools/reference_simulator.py` —— 自己精确算一遍

**干什么**：不采样，直接按门的数学定义算出末态，给出**精确概率**。

**为什么需要这个看起来"重复"的东西**

验收 L1 时有两个看起来很强、其实有同一个盲区的办法：

- **跨后端对拍**：同一电路在两家 SDK 上分布一致
- **自逆电路**：一段电路接上它自己的逆，必须回到初态

**如果解析器把某个门读错了**（比如把 `cx` 的控制位和目标位搞反），
这两个办法**都查不出来**——两个后端会一致地按错电路去跑，
而错电路接上它自己的逆，照样精确回到初态。

所以必须有一个东西回答另一个问题：**我们建出来的电路，
真的就是 QASM 文本写的那个电路吗？** 这就是它。

它自己也要被验证：`verify_l1.py` 的 E 节用 9 道**人手推出答案**的电路钉住它
（`h;h` 必然回到 0、`ccx` 只在两个控制位都是 1 时才翻、`swap` 换位……）。

## 卡片 7 · `tools/verify_l1.py` —— 验收测试

**干什么**：五道关卡，每一道针对一类公开自测查不出来的错。

| 关卡 | 查什么 |
|---|---|
| **A 转译回环** | spinq 的产物在本机跑不了，改用"解析回来必须逐条一致"来验；再把它当输入喂给能跑的后端，分布必须与原电路一致 |
| **B 位序** | 非对称电路（`x q[0]`）+ 错位测量（`q[0] -> c[2]`），**结果是确定值，逼出比特顺序问题** |
| **C 自逆电路** | 随机造一段电路 U，接上 U†，**答案必然是初态**。12 个门的逆全都还在白名单里，所以一次覆盖全部门与全部分解 |
| **D 对精确参考** | 随机电路 vs 参考模拟器算出的精确分布，阈值和官方一样是 0.97 |
| **E 手写答案 + Schema** | 9 道人手推答案的电路 + 官方 Schema 校验器 |

**为什么 D 不是"两个后端互比"**：一开始确实是那么写的，然后立刻发现两个问题——
① 解析器读错门时两边会**一致地错**，互比查不出来；
② 两份采样的噪声会叠加，0.97 这个阈值不再是官方那个含义
（16 个结果、4096 次采样时，两份采样之间的固有保真度就只有 0.97 左右，
完美实现也会"失败"）。所以改成跟自算的精确分布比。

**怎么跑**

```bash
python3 starter_kit/tools/verify_l1.py            # 默认 40 道随机电路，约 4 秒
python3 starter_kit/tools/verify_l1.py --cases 200
python3 starter_kit/tools/verify_l1.py --seed 7   # 复现某一次
```

当前状态：A–E 全部通过。随机电路对精确分布的最低保真度约 0.98，
余量来自 8192 次采样的统计涨落——确定性电路上的保真度是精确的 `1.00000`。

## 环境与依赖

`requirements.txt` 里有两处刻意的固定，头部注释写了原因，简述：

1. **`scipy==1.14.1`** —— Python 3.10 能装的最高版 1.15.3，其二进制在 macOS 27 上
   被系统拒绝加载；三个后端都要过 scipy，会一起失败。
2. **`antlr4-python3-runtime==4.13.2`** —— braket 与 spinqit 对它的要求互斥，
   见卡片 5「关于 spinq」。因此本提交不安装 spinqit，依赖树也随之从 81 个包降到 59 个
   （spinqit 会连带拖进 torch、matplotlib、scikit-learn 等一大批用不上的东西）。
