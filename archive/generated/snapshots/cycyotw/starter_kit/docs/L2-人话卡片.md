# L2 智能体 · 人话卡片

> 每张卡片回答同样三个问题——它干什么、为什么这么设计、换个输入会怎样。
> 姊妹篇：[`量子是什么-零基础.md`](量子是什么-零基础.md)、[`L1-人话卡片.md`](L1-人话卡片.md)。

---

## 它整体在解决什么问题

L1 解决的是"三家平台说三种话"。但用户还得会写量子电路才能用上 L1——
门槛只是从三道降到了一道，没有消失。

L2 要拆的是最后这一道：**用户说人话，程序把电路写出来、跑出来、讲明白。**

评测会往 `agent_chat(prompt)` 里丢三类问题：

| 类型 | 例子 | 怎么算对 |
|---|---|---|
| 意图生成 | "生成一个 3 比特的最大纠缠态并全测量" | 产物电路跑出来的分布保真度 ≥ 0.97 |
| 代码纠错 | "我想要贝尔态，这段代码报错了，帮我修" | 修好的电路必须实现用户声明的目标态 |
| 智能选后端 | "我要跑 15 比特电路且零排队，选哪个？" | 回复必须含正确的规范后端标识 |

---

## 贯穿全篇的一个主张

> **模型只负责听懂人话，不负责给出答案。**

```text
用户的话 ──[模型]──> 结构化的意图 ──[确定性代码]──> 答案
```

为什么要这么切：

- **选后端有唯一正确答案**（查官方能力表）。让模型背表，它迟早背错一行；
  让代码查表，就不可能错。官方文档自己也这么建议。
- **生成电路没有唯一写法，但有唯一验收标准**——跑出来的分布对不对。
  所以模型写完之后，我们**真的把它跑一遍**，不对就带着具体错误让它重写。

第二条尤其重要，因为它把"模型靠不靠谱"这件事从赌博变成了工程：
**我们不需要模型每次都对，只需要能判断它这次对没对。**

## 卡片 1 · `loomq/backend_selector.py` —— 选后端（完全确定性）

**干什么**：输入结构化约束（要几个比特、能不能排队、愿不愿意花钱、要不要真机），
输出满足条件的后端列表。

**为什么这么设计**：这是三类任务里唯一**答案唯一确定**的。
评测方按官方《后端能力表》推导正确答案集，所以我们也照着那张表查——
数据源和判定方式跟评委完全一致，不存在"理解偏差"。

**约束无解时怎么办**：赛题明说"如实说明超出所有可用后端能力，比给错答案得分更高"。
所以无解时会明说无解，**同时给出最接近的替代**——而且照样带上规范标识，
因为回复里没有任何规范标识就一定不得分。

**换个输入会怎样**：官方文档给了三个示例，它们就是现成的标准答案，
我们的判定与三个全部一致（包括那个无解的）：

| 条件 | 判定 |
|---|---|
| 15 比特 + 零排队 | 三个本地模拟器 |
| 真机 + 5 比特 + 不花钱 | `spinq_cloud_qpu`、`originq_wukong` |
| 50 比特 + 模拟器 + 零排队 | 无解，并给出最接近的 `originq_local_simulator` |

## 卡片 2 · `loomq/target_states.py` —— 自验用的标准答案

**干什么**：把常见目标态写成理想分布。

| 名字 | 意思 | 3 比特时 |
|---|---|---|
| `ghz` | 所有比特要么全 0 要么全 1 | `000` 一半、`111` 一半 |
| `bell` | 两比特的 GHZ | `00` 一半、`11` 一半 |
| `w` | 恰好一个比特是 1，不确定是哪个 | `001`/`010`/`100` 各三分之一 |
| `uniform` | 所有结果等概率 | 8 个结果各八分之一 |
| `basis` | 确定的一个结果 | 比如 `101` 概率 1 |

**为什么这么设计**：要自验就得知道"对"是什么。
**认不出来的目标态返回 None**——这时自验只做结构检查（能不能解析、能不能跑、
有没有测量），不做分布比对。**宁可少判，不要判错**：
用一个猜错的标准答案去否决一个正确的电路，比不判更糟。

## 卡片 3 · `loomq/agent.py` —— 主流程

**干什么**：`agent_chat(prompt)`。一次模型调用解析意图，然后交给确定性代码。

**流程**

1. **调模型一次**，要它把用户的话解析成 JSON（任务类型、目标态、约束、以及电路）。
2. 选后端 → 交给卡片 1，结束。
3. 生成/纠错 → **进自验循环**：
   - 用我们自己的解析器读一遍（语法、白名单、有没有测量）
   - 用我们自己的 L1 **真的跑 8192 次**
   - 和目标态的理想分布比保真度
   - 不过就把**具体的错误**（包括实测分布长什么样）丢回给模型重写，最多两轮

**为什么必须"真的跑"**：有一类错误只有跑了才看得出来。
比如把 GHZ 电路里的 `cx` 忘掉——语法完全正确，白名单也没违反，
但跑出来是均匀分布而不是纠缠态。静态检查永远抓不到它。

**★ 一个踩过的坑，值得单独说**

自验的阈值最初写的是 **0.99**，理由听起来很合理："比评测的 0.97 更严，留点余量"。

结果测试里**正确的 GHZ-3 电路拿到 0.9893，被自己打回去了。**

原因是采样本身有涨落：2 个结果、2048 次采样时，**完美电路**的保真度期望值
也只有 0.992 左右，压根碰不到 0.99 这条线。

后果比"多跑一轮"严重得多：重试次数用完之后，一个**本来就正确**的电路
会以"没有通过自验"的名义交出去——白丢分，而且丢得莫名其妙。

结论：**自验的职责是复刻评委的判据，不是自创一个更难的。**
现在是 8192 次采样、阈值 0.97，与评测完全一致。
这样做不会漏判——真正写错的电路（GHZ 写成均匀叠加）保真度只有 **0.29**，
和 0.97 之间隔着一条鸿沟。

（`tools/verify_l2.py` 第七节专门盯这个坑：正确电路连跑 30 次，
一次都不许被误判。这类 bug 是间歇性的，所以必须反复跑。）

**换个输入会怎样**

- 模型吐了一堆非 JSON 的废话 → 有多层兜底的 JSON 提取，实在挖不出来就如实说明，不崩。
- 模型两轮都改不对 → **不把没验过的东西当成品交出去**，明说没通过，
  附上最后一版并标注"它没通过自验"。
- 模型服务连不上、环境变量没配 → 返回可读的说明，并列出缺哪三个变量。
- **任何情况下 `agent_chat` 都不向调用方抛异常。**

**关于配置**：服务地址、密钥、模型名一律从 `LOOMQ_LLM_BASE_URL` /
`LOOMQ_LLM_API_KEY` / `LOOMQ_LLM_MODEL` 三个环境变量读取，**不硬编码**。
这是赛题的硬性要求，也顺带意味着换成任何 OpenAI 协议的服务都不用改一行代码。

## 卡片 4 · `tools/fake_llm_server.py` —— 假的模型服务

**干什么**：一个说 OpenAI 协议的本地小服务，**按剧本回答**。

**为什么需要它**

L2 的代码要处理很多"模型没配合"的情况：答案是错的、格式是垃圾、
服务连不上、连续两轮都改不对……**这些情况用真模型没法稳定复现**。
温度调到 0 只是让它每次答得一样，不是让它按你要的方式答错。

有了这个桩，每一种失败路径都变成一条可重复、可回归的测试。

顺带还有一个好处，在这个项目里正好用上了：**整套 L2 逻辑可以在
完全没有 API Key、甚至完全断网的情况下开发和验证。**

## 卡片 5 · `tools/verify_l2.py` —— 验收测试

八节，测的不是"模型聪明不聪明"（那不归我们管），而是
**我们的代码在模型各种表现下是否都拿得住**：

| 节 | 内容 |
|---|---|
| 一 | 选后端：官方三个示例，答案唯一确定 |
| 二 | 一次写对：官方提取函数能取出 QASM，且带真实采样证据 |
| 三 | 重试：语法错 / 态错 / 用了禁用门 / 忘了测量，四种都要能抓到并重写 |
| 四 | 两轮都改不对：老实说没通过，不交没验过的东西 |
| 五 | 模型吐垃圾 / 返回 500 / 连不上 / 没配环境变量——都不许崩 |
| 六 | 契约合规：源码里不得出现硬编码的服务地址、密钥、模型名 |
| 七 | **回归：自验绝不能把正确的电路判成错的**（见上面那个坑） |
| 八 | 官方公开 L2 用例，接上假模型后必须 PASS |

```bash
python3 starter_kit/tools/verify_l2.py     # 不需要 API Key，不需要联网
```

## 卡片 6 · `tools/probe_l2_live.py` —— 接真模型实测得分

**干什么**：拿真模型跑一批 prompt 变体，**按评委的判法自己打一次分**。

**和 `verify_l2.py` 的区别**：那个测"代码在模型各种表现下拿不拿得住"（用桩模型）；
这个测"接上真模型之后，实际能得多少分"。

**为什么用变体而不是照抄官方示例**：赛题写明正式评测用的是**未公开的同类变体**
（改写措辞、更换比特数与目标态）。照抄示例测出来的通过率没有意义。

**为什么每题的标准答案写死在文件里**：如果标准答案从 Agent 自己的判断里取，
那 Agent 把目标态认错时判分也会跟着错，**测出来的通过率是假的**。

### 实测结果（15 道变体，与评委同一个模型）

**通过 14 / 15 = 93%，按客观分 20 折算约 18.7 分。**最慢一题 31 秒（限时 120 秒）。

唯一失败的是 **3 比特 W 态**。而它失败的方式是对的：自验连续多轮发现分布不符，
**最后拒绝交付**，如实说明"没能给出通过自验的电路"——宁可交白卷，不交错的。

### ★ 关于这个失败，我们做过的判断

先排除自己的问题：**手写一个只用白名单门的 W 态电路，我们的管线跑出来保真度 0.9978**——
所以管线没问题，是模型造不出来。

然后试着补平台知识：W 态需要「受控旋转门」，而白名单里没有这个门，必须拆成 `ry + cx`。
补上这条通用分解之后，模型的产物从"基态全乱"变成"基态全对、只是权重不对"——
**说明它学会了结构，卡在角度的三角计算上。**

再往下就只剩一条路：直接把每个比特数对应的角度值写进提示。

**我们没有走那条路，因为那就是打表。** 赛题反作弊条款写明"发现关键词匹配式伪 Agent、
打表式伪编译器 → 该 Level 判 0"。给模型"这类态怎么构造"的方法是平台文档，
给"某个态的现成电路或现成角度"是答案泄露，两者的分界线就在这里。

那条没换来分数的提示也一并撤掉了——它不管用，还在每次调用里烧 token。

## 没有 API Key 时的正常现象

`evaluator.py --level declared` 里 **l2 那一条会 FAIL**，理由是
"response contains no OpenQASM 2.0 program"。

**那是缺配置，不是代码不行。** 没有模型服务，Agent 自然写不出电路——
而且赛题明确规定组委会赛前不提供 API（`l2_policy.json` 里
`organizer_api_available_before_scoring: false`），正式评测时他们会注入自己的服务。

想在本地看它通过，跑 `verify_l2.py` 第八节即可：那一节把官方原样的判定逻辑
接到假模型上跑，结果是 PASS。
