## 一、先说清楚普通的「比特」

一切数字设备底下都是**开关**。开着记作 1，关着记作 0。一个开关只能是其中一个。

你的照片、这段文字、一整个操作系统，全都是一长串开关的状态。这就是「比特」。
计算机做的所有事情，本质上就是**按规则把这些开关翻来翻去**。

---

## 二、量子比特**不是**「同时是 0 和 1」

这是流传最广、也最误导人的一句话。

真相是：**你去看它的时候，永远只会得到 0 或者 1 中的一个。**
一个量子比特读出来，也只有一个比特的信息，不多不少。

那问题就来了——如果它只是"随机给你一个 0 或 1"，那它就是个骰子，一点用都没有。

**真正的区别在别的地方。**

---

## 三、关键：概率只会累加，「振幅」会互相**抵消**

普通的随机是这样的：如果有两条不同的路都能到达"答案是 5"，
那"答案是 5"的可能性就是两条路**相加**，只会变得更大。
**概率没有负数，永远只增不减。**

量子不一样。量子比特身上带的不是概率，是一个**可以为负**的量（它的学名叫**振幅**）。

于是会发生一件在经典世界里不可能的事：两条路都通向"答案是 5"，
但一条带 +0.5，另一条带 −0.5，它们**互相抵消**，"答案是 5"的可能性变成 **0**。

这就是降噪耳机的原理——两列波，一列的波峰对上另一列的波谷，叠起来是安静。

> 严格说，振幅是复数，能取的不只是正负；但"可以为负、因而能抵消"就是全部要点。

**这就是量子计算唯一的、真正的资源。**

---

## 四、所以量子算法到底是什么

一句话：

> **想办法让所有通向错误答案的路互相抵消，让通向正确答案的路互相加强。**
> 然后测量一次，大概率直接读到正确答案。

设计一个量子算法，就是**设计一场干涉**。就这样，没有别的。

---

## 五、一个能亲手验证「它不是骰子」的实验

`H` 这个门（我们代码里到处都是它）的作用，是把一个确定的 0 变成"0 和 1 各一半"。

如果它只是个随机化器，那么：

- 做一次 `H` → 一半一半
- **再**做一次 `H` → 应该还是一半一半（骰子摇两次还是随机）

**但实际结果是：连做两次 `H`，测出来 100% 是 0。**

因为第二次 `H` 的时候，通向 1 的两条路一正一负，**抵消掉了**。

**骰子摇两次不会必然回到原点，量子比特会。** 这就是"它不是随机"的直接证据，
而且用本仓库的模拟器就能跑出来。

## 六、纠缠：`bell.qasm` 到底在做什么

本仓库 `starter_kit/circuits/bell.qasm` 的全部有效内容只有三行：

```text
h q[0];            // 让第 0 个量子比特进入"一半一半"
cx q[0], q[1];     // 如果第 0 个是 1，就把第 1 个翻过来
measure q -> c;    // 两个都测
```

结果是：**要么 00，要么 11，各占一半，永远不会出现 01 或 10。**

请注意这有多奇怪：

- 单看第 0 个比特，它是随机的（一半 0 一半 1）
- 单看第 1 个比特，它也是随机的
- **但它们俩永远一致**

这就叫**纠缠**：两个比特**没有各自的答案，只有共同的答案**。

**它不能用来超光速传信息。** 你在这边测到 0，那边确实立刻是 0——
但你**没法控制自己测到什么**，所以你送不出任何信息。
只有两边把各自的结果拿到一起对照，那个关联才显现出来。

`ghz3.qasm` 是同一件事扩到三个比特，结果只有 `000` 和 `111`。
`evaluator.py` 里那行 `{"000": 0.5, "111": 0.5}` 说的就是它。

## 七、为什么代码里到处是 `shots = 8192`

因为**测量一次只给你一个结果**。

要看到"分布"，唯一的办法是**把同一段电路重复跑几千次，然后数数**。
`shots = 8192` 就是"跑 8192 次"，`counts` 就是那张"正"字表。

这也解释了本项目里标记为 ★★ 的**位序陷阱**为什么危险：

Bell 的结果是 `00` / `11`，GHZ-3 是 `000` / `111`——**全是回文**，正着念反着念一样。
所以如果比特顺序写反了，这两个公开电路的数数结果**一模一样**，
你会在公开自测里看到满分，然后在隐藏的非对称电路上全军覆没。

## 八、那量子计算机到底强在哪

最实在的答案，就藏在官方那张《后端能力表》里。

要在普通电脑上**精确模拟** n 个量子比特，需要记录 **2ⁿ** 个数：

| 量子比特数 | 需要记录多少个数 | 什么概念 |
|---:|---:|---|
| 10 | 1,024 | 随便算 |
| 30 | 十亿 | 一台好机器的极限 |
| 300 | 约 10⁹⁰ | **比整个可观测宇宙的原子还多** |

**每多一个量子比特，普通电脑的代价就翻一倍。**

这就是为什么能力表里三个模拟器的上限分别是 24 / 25 / 30——不是厂商偷懒，是物理上限。

而量子计算机不需要"记录"这些数，**它本身就处在那个状态里**。这就是整件事的起点。

## 九、但也要说实话

- 今天的真机**又小又吵**，噪声还在毁掉大部分计算。
- 到目前为止，**还没有任何一个实用问题，被量子计算机真正做得比经典计算机更好。**
- 已知有用的算法就那么几类：大数分解、无结构搜索的平方根加速、
  以及模拟分子和材料——**最后这个可能最实在，因为分子本来就是量子的。**
- 本次比赛跑的三个后端**全都是模拟器**，也就是用普通电脑算量子的行为。
  真机是另外 +10 分的选做项。

夸大和唱衰都没意思。它是一件**还没兑现、但底层原理确凿**的事。
