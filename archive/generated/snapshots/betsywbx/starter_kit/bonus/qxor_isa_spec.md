# `qxor` 自定义指令编码规格

## 1. 设计动机

题面给定的基础指令子集(`li, add, sub, addi, beq, bne, j`)只提供算术运算(加减法)和相等性比较，
**没有任何按位运算能力**。这是量子-经典混合程序里一个真实存在的表达力缺口：

量子纠错(QEC)协议中最常见的经典后处理操作之一是**计算多个稳定子测量位的奇偶校验(parity)**，
用来决定该对物理比特施加哪种 Pauli 修正——这是表面码(surface code)、Steane码等主流QEC方案
里的标准操作。给定测量位 `c[i]`、`c[j]`，判断它们是否"不一致"(即 XOR 结果是否为1)，
用现有指令集**无法直接表达**：加法算不出异或(`a+b`在a=b=1时得2，不是XOR该有的0)，
也没有其它按位指令可以组合模拟。

`qxor` 直接填补这个缺口，语义上贴合真实 QEC 场景，不是为了凑数而设计的空指令。

## 2. 汇编语法

```
qxor rd, rs1, rs2      ; rd = rs1 XOR rs2 (按位异或)
```

用法与 `add`/`sub` 完全一致(三寄存器 R-type)，学习成本为零。

## 3. 二进制编码 (32位 R-type)

沿用标准 RISC-V R-type 指令格式，复用 RISC-V 官方规范里为用户自定义扩展预留的
**custom-0** 操作码空间(`opcode = 0001011`，即 RISC-V spec 中明确保留、
不会与任何标准指令冲突的区域)：

```
 31        25 24     20 19     15 14  12 11      7 6      0
┌────────────┬─────────┬─────────┬──────┬─────────┬────────┐
│  funct7    │   rs2   │   rs1   │funct3│    rd   │ opcode │
│  0000000   │ (5 bit) │ (5 bit) │ 000  │ (5 bit) │0001011 │
└────────────┴─────────┴─────────┴──────┴─────────┴────────┘
     7            5         5        3        5         7
```

| 字段 | 值 | 说明 |
|---|---|---|
| `opcode` | `0001011` (0x0B) | RISC-V 规范保留的 custom-0 扩展空间 |
| `funct3` | `000` | 本指令在 custom-0 空间内的功能码(为未来扩展第二条custom指令预留 001-111) |
| `funct7` | `0000000` | 固定值，区分 R-type 内的具体运算(对齐标准 `add`/`sub` 用 funct7 区分的做法) |
| `rd`/`rs1`/`rs2` | 5 bit | 与标准 R-type 指令语义完全一致的寄存器编号字段 |

选择 custom-0 而不是随便编一个 opcode，是为了让这份编码在"如果真的要接入一个遵循
RISC-V 规范的工具链"时不会跟任何标准指令或其他扩展冲突——这是真实 RISC-V 自定义
扩展提案的标准做法。

## 4. 语义

```
rd ← rs1 ⊕ rs2   (按位异或，逐位无进位)
```

与 `add`/`sub` 相同，若 `rd = x0`，写入被丢弃(x0恒为0，符合RISC-V规范惯例)。

## 5. 示例：QEC 奇偶校验修正判断

```
; 已知 c[0], c[1] 是两个稳定子测量结果(通过classical块的c[k]映射进x10,x11)
qxor x1, x10, x11      ; x1 = 校验位是否翻转(奇偶不一致)
beq x1, x0, NO_ERROR   ; 校验位为0(偶校验) -> 无需修正
li x2, 1                ; 校验位为1 -> 标记需要修正
j END
NO_ERROR:
li x2, 0
END:
```

这段程序用现有6条基础指令**无法等价实现**(没有任何组合能从加减法/等值比较推出XOR语义)，
是 `qxor` 存在必要性的直接证明。
