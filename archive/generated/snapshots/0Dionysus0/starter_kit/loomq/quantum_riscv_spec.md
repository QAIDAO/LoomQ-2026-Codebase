# 自定义量子 RISC-V 扩展指令规格 v1.0

> Bonus 项（+8）：设计 custom opcode 编码量子操作。本规格文档 + `starter_kit/loomq/riscv_quantum_emulator.py`（fork 自官方 `riscv_emulator.py` 的扩展实现）+ 该文件底部的端到端自测，三者共同构成这一项的完整交付。

## 一、动机

L3 基线模型里，`compile_hybrid()` 输出"量子操作序列"和"RISC-V 汇编"是两个**互不相通**的产物：经典汇编只能读评测系统在执行前一次性注入的测量值，程序运行过程中无法"测量 → 立刻按结果分支 → 再做下一个量子操作"。这个扩展把量子操作也变成寄存器机能识别的指令，塞进同一条指令流，让量子和经典可以在一次 `execute()` 调用里交替执行、真正的运行时耦合。

## 二、新增指令一览

沿用官方 `riscv_emulator.py` 的文本汇编风格（助记符 + 逗号/空格分隔的参数），qubit 下标和寄存器编号都用立即数直接给，不做寄存器间接寻址，跟已有的 `li rd, imm` 风格保持一致，解析器不需要额外的寻址模式。

| 助记符 | 语法 | 语义 |
|---|---|---|
| `qinit` | `qinit N` | 初始化一个 N 比特量子寄存器：态矢量清零到 \|0...0>，替换掉上一次 `qinit` 建立的态（如果有） |
| `qh` | `qh Q` | 对 qubit `Q` 施加 Hadamard 门 |
| `qx` | `qx Q` | 对 qubit `Q` 施加 Pauli-X 门 |
| `qcx` | `qcx Qc, Qt` | CNOT：控制位 `Qc`，目标位 `Qt` |
| `qrz` | `qrz Q, A` | 对 qubit `Q` 施加 `RZ(A·π/4)`，`A` 是 0–7 的整数"角度编码" |
| `qmeasure` | `qmeasure Q, xR` | 测量 qubit `Q`：按当前态矢量的玻恩概率采样一次、**坍缩**态矢量，把结果（0 或 1）写入通用寄存器 `xR` |

### 为什么 `qrz` 用整数角度编码而不是浮点立即数

官方汇编器（`riscv_emulator.py` 的 `load_program`）本来就只解析整数立即数（`li rd, imm` 里的 `imm` 直接 `int(args[1])`），没有浮点字面量的语法。为了不引入新的数值语法、保持跟基础指令集一致的解析方式，`qrz` 的第二个操作数固定是 0–7 的整数，代表 `π/4` 的整数倍——这个编码延续了 L1 `gate_identities.md` 分解表里本来就在用的角度集合（`s`=π/2=编码2、`t`=π/4=编码1、`sdg`=-π/2=编码6、`tdg`=-π/4=编码7，超出 0–7 就取模 8）。

## 三、执行语义细节

- **`qinit` 必须在使用任何 `q*` 指令前执行一次**；未初始化就用会抛错，不做隐式初始化（避免悄悄用错比特数）。
- **`qmeasure` 是真坍缩**，不是只读概率：测量同一个 qubit 两次，第二次会读到跟第一次一致的确定值（除非中间又对它施加了门）——这是模拟真实量子测量不可逆的关键，也是端到端测试要验证的核心行为。
- 量子指令不影响 `pc`、不占用跳转标签逻辑，`beq`/`bne`/`j` 这些经典控制流指令可以直接读 `qmeasure` 写入的通用寄存器，形成真正的混合控制流。
- 门操作的酉矩阵、态矢量施加逻辑**直接复用** `starter_kit/loomq/simulate.py` 和 `gates.py` 里 L1 已经写好并测试过的 `_apply_single`/`_apply_cx`/`single_qubit_matrix`，不重新实现一遍线性代数。

## 四、形式化指令编码（32 位字长示意）

参考实现只解析文本助记符（跟基础 RISC-V 子集本身的处理方式一致，官方 `riscv_emulator.py` 也没有做真正的二进制译码）。但完整的"指令编码规格"应当包含机器码级别的字段划分，写在这里：

RISC-V 规范里 `0001011`（custom-0）是明确保留给厂商/实验性扩展的操作码，这里借用它作为量子扩展指令的基础 opcode，`funct3` 字段区分具体是哪条指令，字段布局仿照标准 R-type：

| 字段 | 位宽 | 含义 |
|---|---|---|
| opcode | `[6:0]` | 固定 `0001011`（custom-0） |
| rd / 目标寄存器 | `[11:7]` | `qmeasure` 写入的 `xR`；其余指令为 0 |
| funct3 | `[14:12]` | `000` qinit · `001` qh · `010` qx · `011` qcx · `100` qrz · `101` qmeasure |
| rs1 | `[19:15]` | 主 qubit 下标，或 `qcx` 的控制位 |
| rs2 | `[24:20]` | `qcx` 的目标位，或 `qrz` 的角度编码 0–7 |
| funct7 | `[31:25]` | 保留 0 |

参考实现按文本助记符解析，与官方 `riscv_emulator.py` 一致，不要求评测器执行上述二进制编码。

## 五、端到端自测

在仓库根目录执行（必须用 `-m`，以便 `loomq` 包内的相对导入生效）：

```bash
python -m loomq.riscv_quantum_emulator
```

工作目录为 `starter_kit/`。自测程序在 `riscv_quantum_emulator.py` 的 `if __name__ == "__main__"` 中：2000 次运行 `H → 测 q0 → 按结果决定是否 X q1 → 测 q1`，断言每次 `x1 == x2`，且 `x1=1` 的比例约 0.5。打印 `量子 RISC-V 扩展指令端到端自测通过！` 且退出码为 0 即通过。
